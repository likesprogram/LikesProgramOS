# 体积与内存报告

本文是 M7 收尾任务 **T7.4（D10 口径）** 的实测记录（基线数字），并在第八节记录 M8（`Modules.list` 归还内核侧）后的复测：按 P5 实施计划第 1 节 **D10** 的六项（计划文件随 P5 收尾移出工作树，内容见 Git 历史 `d5b3222` 之前的提交）分别记录内核核心 `.os`、引导闭包、运行期模块、整集、压缩前后与调试符号的体积，并给出启动峰值内存与运行期常驻的**可观测口径**。所有数字来自 2026-10-22 的现有构建产物与 M6 启动证据（基线 `697d917`，统计时 M7 工作区），**只读统计、不重跑构建与 QEMU**；命令见各节，未验证与不适用项在第七节显式列出。

**口径说明：**体积是字节数（`stat` / `find -printf`），压缩比用 `gzip -9` 作**参考**（项目没有压缩启动产物的方案，gzip 数字不代表实际压缩策略）；内存是从串口事实与 ELF/镜像数据**相加**出来的下限估算，不是运行时采样值。计划 D10 只要求分列口径，没有给硬指标；对比见第五节。

## 三、启动峰值内存（下界估算口径）

### 3.1 可观测事实（来自 M6 启动证据）

| 事实 | 证据（串口行） | 数值 |
| --- | --- | --- |
| 预装闭包字节 | `boot closure preloaded: count=13 bytes=222680 bad=0` | `222,680` B |
| 交接包模块字节 | `Handoff=Manifest=…/0x471 List=…/0x1C0 Records=0xD Bytes=0x365D8` | `0x365D8 = 222,680` B |
| 清单副本 / 列表副本 | 同上：`0x471 = 1,137` / `0x1C0 = 448` | 1,137 / 448 B |
| 预装记录 | 记录数 `13`；数组 `8 + 32×16 = 520` B 上限（实际使用 `8 + 13×16 = 216` B） | 520 B（分配上限） |
| 内核镜像装载 | `Load=0x01000000 Bytes=0x00012418 Span=0x000A4008` | 文件 74,776 / 静态跨度 671,752 B |
| 页帧事实 | `ManagedMiB=0x00001000 FreeMiB=0x000001EF`（HDD 档）；NVMe 档 `0x1EA` | 管理上限 4 GiB；初始化后空闲 495 MiB（NVMe 档 490 MiB） |
| 机器内存 | `QEMU_MEM` 默认 `512`（`Tools/Test/CheckAll.sh`），内存图 `Mmap=9` 条、`UsableMiB=0x1FF` | 约 512 MiB |
| 交接副本 | `Copies=Manifest=… List=… Records=… Modules=0xD` | 三类缓冲 + 13 个模块字节的副本 |

说明：`FreeMiB` 行在页帧分配器初始化之后、交接区间标占之前打印；它不含内核自身跨度与引导器常驻区，但**含**尚未被标占的 Baleen 预装缓冲所在页。

### 3.2 组成与合计

| 组成 | 字节 | 依据 |
| --- | --- | --- |
| 内核映像静态跨度（含 BSS、页表、栈） | `671,752` | 镜像数据 `MemoryBytes`；BSS 明细见 4.2 |
| 预装闭包页（分页标占） | `278,528` | 222,680 按模块逐段向上取整到 4 KiB：模块页 `266,240` + 清单/列表/记录各 1 页 `12,288` |
| 内核自有交接副本页 | `278,528` | 同上：复制接管为每段分配内核自有 4 KiB 帧 |
| 闭包模块装载映像 | `356,352` | 13 个 `.osm` 的 `ImageBytes` 合计（已 4 KiB 整数倍） |
| **启动峰值下界（页取整口径）** | **`1,585,160`**（约 1.51 MiB） | 以上四项之和；四者在闭包装载完成时同时存在 |
| 备查：按字节口径（不计页取整） | `1,473,464`（约 1.41 MiB） | 预装/副本都用 222,680 文件字节计算 |

**为什么叫"下界"**：这四项是从串口与镜像数据可观测到的、同时驻留的字节数之和。实际峰值还要加上以下**未计入**项（无法从现有证据取数，不伪造测量值）：

- 页帧分配器元数据、空闲链表与分配碎片（部分在 BSS 内已计，动态部分未计）；
- MMIO 高地址窗口的 4 KiB 页表页（M6 起按映射条数动态分配，单页 4 KiB、窗口上限 64 条 = 最多 262,144 B，本报告未计入）；
- 固件/引导器残留在内存图里的占用（已由内核在初始化时避开，不属于内核峰值）；
- 内核栈深度实际峰值（栈静态区 32 KiB 已按整段计入，实际使用未采样）；
- 中断/异常现场的嵌套栈与 IST（静态 IST 栈已在 BSS 内计入）。

### 3.3 与页帧基线的对照

以 HDD 档 `FreeMiB=495`（初始化后、标占前）为基线，本报告能算出的启动占用为：

```text
预装页标占 278,528 + 交接副本 278,528 + 模块映像 356,352 = 913,408 B（约 0.87 MiB）
估算剩余空闲 ≈ 495 MiB - 0.87 MiB ≈ 494.1 MiB
```

这部分"占用"里有两份是**同一批模块字节**（Baleen 预装页 + 内核自有副本），是计划 6.9 选择的"复制而非接管"策略的已知开销：交接副本在本次启动内不释放（`ReserveHandoff` 标占后没有对应的释放路径），因此它也同时进入第四节的运行期常驻。

## 五、对比规划量级

- 计划第 1 节 D10（第 61 行）只要求**分别记录**内核 `.os`、引导闭包合计、运行期模块合计、整集合计与压缩前后大小、调试符号；**没有给体积硬指标或回归阈值**。
- [内核架构与自举闭包](../Specs/内核架构与自举闭包.md)第四节明确"集级体积与启动峰值内存的规划量级在 P5 实测后给出——它是规划参考，不是硬上限，也不作为构建失败条件"。因此本报告记录实测值，**不宣布达标/超标**；可作为后续发行对比的基线。
- 可对照的**硬上限**（规格已定，不是规划量级）：
  - 单个 `.osm` ≤ 64 MiB（容器规格 2 节）：最大模块 25,504 B，约 0.04%；
  - `Modules.list` ≤ 16 KiB（模块修订与更新第四节）：448 B，约 2.7%；
  - 清单 ≤ 64 KiB（清单规格 2.3）：1,137 B，约 1.7%；
  - 系统卷 16 MiB（引导布局）：卷内集产物 299,041 B，约 1.8%。
- 启动峰值下界约 1.51 MiB（相对 QEMU 512 MiB 可用内存约 0.3%），页帧基线 495 MiB 空闲；运行期常驻下界约 1.51～1.52 MiB。量级上不构成约束，主要成本仍是**复制接管**策略带来的双份模块字节（约 0.27 MiB）。

## 七、未验证项与边界

1. **不是运行时内存采样**：峰值与常驻按可观测字节相加得出，没有在 QEMU/真机里采样实际用量；页面元数据、碎片、MMIO 页表页与栈深度峰值未计入（见 3.2/4.1 的说明）。
2. **QEMU 口径**：页帧基线与占用对照来自 QEMU 默认 `QEMU_MEM=512`；真机与其它内存档的 `FreeMiB` 会不同，但本报告的体积与内核/模块静态数字不变。
3. **压缩数字是 gzip 参考**：项目没有启用产物压缩，gzip 结果不进入构建链、不改变交付体积；系统卷/介质镜像的低比值主要来自零填充。
4. **介质镜像体积含几何尺寸**：ISO/HDD 的固定大小由启动器布局决定，不代表内核集或系统卷的实际内容大小；变体镜像（4Kn/degrade/revocation）同尺寸，只差少量测试数据。
5. **运行期模块体积只覆盖 G6d 夹具**：`Fault`/`Optional` 是验证夹具，正式发行集不含；正式运行期模块（`Process`/`Ipc` 等）尚未实现，未统计。
6. **调试符号零字节只针对当前交付物**：未来若按容器规格交付独立 `.sym`，应在此节追加其体积，不能沿用"0"。
7. **基线**：第一～六节数字来自 M6 提交 `697d917` 的产物（2026-10-22 14:21 构建），第七节是 M7 口径说明；M8 复测见第八节，复现命令不变。
