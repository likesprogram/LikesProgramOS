# 镜像制作器与安装器实现手册

本手册面向需要为 LikesProgramOS 产出可引导介质的实现者。**制作器**在构建期把已经编译好的各阶段产物组装成一份镜像文件；**安装器**在目标机器上把同一套内容写入用户选定的设备。两者写出的字节必须能被 Baleen 引导链按[一级引导契约](../Specs/Baleen/一级引导契约.md)读取，因此本手册只规定**写什么、写到哪里**，不规定用什么语言、跑在哪个环境。

项目自带的 `Tools/Build/MakeImage` 是**通用镜像制作器**：产出的 `LikesProgram.iso` 可刻录到 U 盘、移动硬盘、CD，也可由虚拟机直接选择 ISO 文件启动；`Tools/Build/TestInstaller` 是**测试安装器**：作为正式安装器（ISO 内运行，尚未实现）的替代产品，把系统装配成可写入内置硬盘、移动硬盘或 U 盘的整盘镜像。两者的用法与能力边界见第九节；需要别的介质形态或安装行为的实现者，可按本手册自行实现，或参考这两个工具修改。

## 一、产物从哪来

引导链要的输入是几类文件，全部由各自的构建环节产出：

| 文件 | 产出方 | 说明 |
| --- | --- | --- |
| `BaleenIPL.bin` | `Packages/Baleen/Ipl/` | 512 字节的磁盘一级引导，同时是 MBR 的引导代码 |
| `BaleenIPLCd.bin` | 同上 | 2048 字节的光盘一级引导，用于 El Torito |
| `BaleenStub.bin` | `Packages/Baleen/Stub/` | 实模式服务层，由 IPL 按扇区读入并自检 |
| `BaleenCore.bin` | `Packages/Baleen/Core/` | 核心阶段，由 Stub 装入 1 MiB |
| 描述符段 | `Packages/Baleen/Common/Out/Descs/` | 描述符区的头部与各段，**拆开输出**，见第三节 |

**描述符区必须由段产物拼成，不要自己拼字节**：段的布局与固定取值是契约的一部分，实现方只负责回填其中的位置字段。

## 二、介质布局

| 位置 | 内容 |
| --- | --- |
| 偏移 0 | MBR：`BaleenIPL.bin` 的引导代码 + 分区表（分区表由部署侧生成，见第八节） |
| 描述符扇区 | 描述符区（头部 + 段序列），见第三节 |
| 描述符扇区之后、按 4096 对齐 | 载荷：Stub、Core 与其它原始条目 |
| 1 MiB 与 8 MiB | 0 号分区：ESP（FAT16，含 `\EFI\BOOT\BOOTX64.EFI`），同一份写两处（见第七节） |
| 两份 ESP 之后 | 1 号分区：Ext4 系统卷 |
| 末尾 | 按目标设备的整扇区收尾 |

**描述符区的位置不写死在装载方**：IPL 的二进制里留了一个 4 字节的槽，装载方从槽里读出描述符区的**512 字节基准地址**（值 = 字节偏移 / 512），再按运行期探测到的本地扇区单位右移换算成本地扇区号。槽有编译期默认值，装载器可以覆盖它。

| 形态 | 槽的文件偏移 | 默认值 |
| --- | --- | --- |
| `BaleenIPL.bin`（磁盘） | 440（代码之后、446 字节分区表之前） | `272`，对应字节偏移 `0x22000` |
| `BaleenIPLCd.bin`（光盘） | 494（代码之后、510 字节代码区之内） | 同上，两种形态同值 |

**什么时候要改槽**：把描述符区放在默认位置以外的字节偏移时——例如该位置被后续的介质布局占用。**改槽就是把"新字节偏移 / 512"写进槽**；不改槽就等于用默认值，此时描述符区必须落在 `0x22000`。因为槽里是设备无关的基准值，**同一个值在 512e、4Kn 与 2048 字节单位的光盘上都指向同一处物理位置**。

**两处必须一致**：槽里的值决定装载方去哪里找描述符区，描述符区头部的 `areaLba` 用于自我核对——两者都是 512 字节基准、直接比较，不等则装载方以 `D` 停机。改位置时两处一起改。

## 三、描述符区格式

描述符区**独占一个扇区**，由头部与段序列组成。头部不枚举段：读取方从头部之后开始，按每段的段长前进、按段标记认段，**段的顺序不作要求**；新增段只要在段序列里多写一段。

**头部（16 字节，小端）**

| 偏移 | 宽度 | 字段 | 写入值 |
| --- | --- | --- | --- |
| `0x00` | 4 | magic | `0x43534442`（`BDSC`） |
| `0x04` | 2 | version | `1` |
| `0x06` | 2 | headerBytes | `16` |
| `0x08` | 4 | areaLba | 本区起始扇区 |
| `0x0C` | 4 | areaEndLba | 本区结束扇区，含 |

**段头（8 字节，各段共用）**

| 偏移 | 宽度 | 字段 | 写入值 |
| --- | --- | --- | --- |
| `0x00` | 4 | magic | 段的格式标记 |
| `0x04` | 2 | version | `1` |
| `0x06` | 2 | length | 段长，含段头 |

**现有段**

| 段 | 标记 | 段头之后的内容 |
| --- | --- | --- |
| Stub | `0x52445342`（`BSDR`） | `stubLba`（4 字节）、`stubEndLba`（4 字节），均为 512 字节基准 |
| Core | `0x52444342`（`BCDR`） | `coreLba`（4 字节）、`coreEndLba`（4 字节），均为 512 字节基准 |

段产物在 `Packages/Baleen/Common/Out/Descs/`（`Head.bin` 是头部，其余 `*.bin` 按文件名排序即段序列），**位置字段在其中留 0**，由实现方回填。

## 四、需要写回的信息

这是本手册的核心。**每一项都按 512 字节基准写**（值 = 字节偏移 / 512，与目标设备的逻辑扇区单位无关），结束位置含在范围内：`结束 = 起始 + 上取整(字节数 / 512) - 1`。

| 写回项 | 写到哪 | 规则 |
| --- | --- | --- |
| 描述符区起始位置 | **IPL 里的槽**（偏移 440 / 494）**和**头部 `areaLba` | 两处必须一致、同为基准值；默认 `272`，位置变了要一起改 |
| 描述符区结束位置 | 头部 `areaEndLba` | 描述符区按 512 字节上取整后的最后一个位置；不得早于起始 |
| Stub 起始位置 | Stub 段 `stubLba` | 载荷实际写入位置换算成基准值；装载方换算后必须大于描述符区扇区号 |
| Stub 结束位置 | Stub 段 `stubEndLba` | 不得早于起始；装载方换算后的扇区数不超过 65（512 B）/ 16（2048 B）/ 8（4096 B） |
| Core 起始位置 | Core 段 `coreLba` | 同上；装载方换算后必须大于描述符区扇区号 |
| Core 结束位置 | Core 段 `coreEndLba` | 同上；扇区数不超过 `0x400000` |

**为什么结束位置也要写**：装载方用它判定"读盘请求是否落在声明的区间内"。IPL 读完 Stub 段就按这一对值决定读多少扇区，Stub 对 Core 段同样处理；只写起始位置、或把结束位置写错，都会在启动时表现为读盘失败或读到错误内容。

**载荷起点必须按 4096 对齐**：基准值换算到 4096 单位时要右移 3 位，起点不是 4096 的整数倍就会错位；4096 对齐同时保证 512 与 2048 单位下也整扇区可读。

**其余字段原样保留**：标记、版本、头长与段长由段产物给出，不要改写。

## 五、建议流程

1. **确定目标设备的逻辑扇区大小**（512 / 2048 / 4096）与总容量；
2. **读入段产物**：`Out/Descs/Head.bin` 与其余 `*.bin`，按段标记识别哪些段需要回填；
3. **规划布局**：描述符区占一个扇区（默认在字节偏移 `0x22000`，也可以放到别处并在第 5 步改槽）；载荷从描述符区之后、按 4096 对齐开始，逐个分配连续区间；
4. **计算位置**：按第四节的规则算出描述符区与各载荷的 512 字节基准位置；
5. **回填**：把第四节的各项写进 IPL 的槽、头部与对应段；
6. **写描述符区**：整个区（头部 + 段序列）写到描述符区所在的字节位置；
7. **写载荷**：各载荷写到第 3 步分配的字节位置；
8. **写分区表**：MBR 或 GPT，按目标设备的单位生成（见第八节）；
9. **写 ESP 与系统卷**：ESP 是 FAT16 镜像（同一份写到 1 MiB 与 8 MiB 两处）、系统卷是 Ext4 镜像，各自写到分区起点；
10. **校验**：读回描述符区核对标记与位置字段，确认载荷与描述符声明一致。

**描述符区必须落在一个扇区之内**：装载方在最小的 512 字节单位下也只读一个扇区就完成段遍历，所以描述符区不得超过 512 字节。段序列过长时应精简段，而不是让描述符区跨扇区。

## 六、装载方如何校验

写回的每一项都会被读的一侧核对，写错时的表现如下，便于自检与排错：

| 写错的地方 | 表现 |
| --- | --- |
| 头部标记不符 | IPL 以 `D` 停机 |
| `areaLba` 与约定值不符 | 同上 |
| Stub 段找不到、段长异常 | 同上 |
| Stub 起始扇区为零、落回描述符扇区、结束倒置 | 同上 |
| Stub 扇区数超出窗口 | IPL 以 `S` 停机 |
| Stub 读盘失败 | IPL 以 `L` 停机 |
| Core 段起始扇区为零、落回描述符扇区、结束倒置 | Stub 打印 `FATAL` 原因后停机 |
| Core 读盘失败 | 同上 |
| 载荷内容与描述符声明不符 | Stub 的摘要校验失败，打印 `FATAL` 后停机 |

错误码与诊断行的正式定义见[一级引导契约](../Specs/Baleen/一级引导契约.md)第六节。

## 七、扇区单位与跨介质

- **位置字段与设备单位解耦**：描述符区的位置字段一律按 512 字节基准写，同一套布局在 512 / 2048 / 4096 三种单位下的**字节位置一致**，装载方各自换算成本地扇区号——**同一份镜像可直接写入这三种单位的介质**；
- **混合镜像（写入 U 盘或移动硬盘的 ISO）**：同一份字节同时带 MBR 与 El Torito 两条引导路径，两条路径看到的单位不同（U 盘是 512 / 4096，光盘是 2048），但读的是同一处描述符区与同一份载荷，换算由各自的装载方完成；
- **光盘形态**：单位固定 2048，基准值 272 / 280 / 312 换算后是 68 / 70 / 78；
- **4Kn**：单位 4096；还要确认固件能识别该设备——部分固件的 USB 存储层只接受 512 字节块设备（如 SeaBIOS），此时设备根本不可见，与镜像内容无关；
- **UEFI 路径用双 ESP 通吃两种设备单位**：分区项不带单位，同一个 LBA 整数在 512e 与 4Kn 上指向相差 8 倍的位置。做法是把 0xEF 项的起点固定写 LBA 2048——512e 固件读到 1 MiB、4Kn 固件读到 8 MiB——并在两处各放一份同样的 FAT 卷，两种设备都能找到 ESP。ESP 必须小于 7 MiB（1 MiB 处那份不得盖住 8 MiB），这也是 ESP 用 FAT16 而不是 FAT32 的原因（FAT32 的最小卷是 32 MiB）；
- **系统卷只放一份**：Ext4 分区项（`0x83`）在一种单位下会指向错误位置，但内核对系统卷用布局描述（`BaleenLayout.bin`）定位，不依赖分区表；外部工具在另一种单位下看到的分区范围会偏，这是安装介质的已知取舍。

## 八、分区表与部署侧

- **引导区不依赖分区表**：BIOS 路径按介质起始的固定偏移读描述符与载荷，分区表只服务固件找 ESP；
- **MBR 与 GPT 共用同一套引导区**：两者都落在 GPT 保留区（LBA 1..33）之后，切换分区表形态不需要重新编译任何二进制；
- **0x83 系统卷项与 GPT 项的单位按目标设备确定**：同一个整数在 512e 与 4Kn 上指向相差 8 倍的位置，必须按目标设备生成；0xEF 项例外，起点固定 LBA 2048，配合双 ESP（第七节）让同一份产物在两种单位下都能被固件找到；
- **分区要求**：0 号分区 = ESP（类型 `0xEF`、FAT16、起点固定 LBA 2048、两处各一份）、1 号分区 = Ext4 系统卷（类型 `0x83`）；分区起点按 4096 对齐以便两种单位都能描述。取舍见[启动介质与文件系统](../Specs/Common/启动介质与文件系统.md) 4.1 与 4.2。

## 九、与 Tools 中实现的关系

`Tools/Build` 下的两个工具是本手册的现成实现，定位不同：

| 工具 | 定位 | 工作内容 |
| --- | --- | --- |
| [MakeImage](../../Tools/Build/MakeImage/README.md) | 通用镜像制作器 | 把各阶段产物组装成一份混合镜像（`Out/LikesProgram.iso`）：刻录到 U 盘、移动硬盘、CD，或由虚拟机直接选择 ISO 文件启动，用的都是这一份字节 |
| [TestInstaller](../../Tools/Build/TestInstaller/README.md) | 测试安装器 | 模拟正式安装器，把同一套内容装配成可写入内置硬盘、移动硬盘或 U 盘的整盘镜像（`Out/LikesProgram.hdd`），用于在真实设备上验证安装结果 |

**能力边界**：两者都按本手册的约定工作，但都不提供"交互式选盘、改写已有分区表、现场读取目标设备逻辑扇区"这类正式安装器行为，也不负责把镜像写进目标设备——写盘由 `dd` 一类工具完成。

**需要别的功能时**：按本手册自行实现，或参考这两个工具与它们共用的 `Tools/Build/Common` 修改——位置字段的参考实现在 `Tools/Build/Common/Src/Baleen.cpp` 的 `BuildDescriptorArea`（读段、按段标记把起止位置按 512 字节基准回填、写回整区）。

**段产物是格式的唯一来源**：无论自制还是改写，都不要自己拼描述符区的字节；从 `Packages/Baleen/Common/Out/Descs/` 取段产物、只回填位置字段，格式变更时实现方不必跟改。

## 十、介质与单位的验证矩阵

下表是在本机 QEMU 上实测的结果，覆盖两种装配方式的全部分支。**"到 Core"**指 BIOS 路径经 IPL → Stub → Core 打印环境事实；**"占位 EFI 执行"**指 UEFI 路径按分区表找到 ESP、执行 `\EFI\BOOT\BOOTX64.EFI`（Baleen UEFI 链尚未实现，当前是占位件，能走到它说明固件侧的发现与加载已通）。

| 装配方式 | 目标介质 | 逻辑扇区单位 | BIOS 路径 | UEFI 路径 |
| --- | --- | --- | --- | --- |
| 刻录 ISO（第三方刻录器写入 `LikesProgram.iso`） | CD / DVD / 虚拟机挂载 | 2048（固定） | 到 Core | 占位 EFI 执行 |
| 刻录 ISO | U 盘 / 移动硬盘 | 512e | 到 Core | 占位 EFI 执行（1 MiB 处的 ESP） |
| 刻录 ISO | U 盘 / 移动硬盘 | 4Kn | 固件不枚举设备（见下） | 占位 EFI 执行（8 MiB 处的 ESP，**同一份镜像**） |
| 安装器装入（TestInstaller 产物直写） | U 盘 / 移动硬盘 | 512e | 到 Core | 占位 EFI 执行 |
| 安装器装入 | U 盘 / 移动硬盘 | 4Kn | 固件不枚举设备（见下） | 占位 EFI 执行（**同一份产物**） |
| 安装器装入 | 内置硬盘（SATA / IDE） | 512e | 到 Core | 占位 EFI 执行 |
| 安装器装入 | 内置硬盘（NVMe） | 4Kn | 到 Core | 占位 EFI 执行 |

**"固件不枚举设备"是固件侧的限制，与镜像内容无关**：SeaBIOS 的 USB 存储栈只接受 512 字节块设备，4Kn USB 存储挂上去连引导项都不会出现（表现为模拟器无任何引导输出）。这类组合的镜像侧逻辑由回归覆盖——IPL 在 4096 单位下的取址由 `CheckIpl` 的 AH=48 夹具验证，Stub 侧由 `CheckStub` 的 NVMe 4Kn 用例验证。

**三条边界结论**（含改造前后的对照）：

| 验证项 | 配置 | 结果 |
| --- | --- | --- |
| 位置字段与设备单位解耦 | 按 4096 单位生成的产物挂到 512e 设备，BIOS 路径 | 到 Core——分区表单位不影响 BIOS 引导 |
| 双 ESP 通吃两种单位 | 同一份镜像分别挂到 512e 与 4Kn 设备，UEFI 路径 | 两者都执行占位 EFI：固件各读到 1 MiB 与 8 MiB 处那份 ESP |
| 双 ESP 之前（对照） | 旧布局的镜像挂到 4Kn 设备，UEFI 路径 | 固件报 `Not Found`——分区项在 4Kn 下指向 8 倍位置、那里没有 ESP；这正是改成"固定 LBA 2048 + 两处各一份"的原因 |

用 QEMU 复现 4Kn 组合：`make run iso qemu usb uefi RUN_USB_BLOCK_BYTES=4096`（刻录路径）或 `make run hdd qemu usb uefi RUN_USB_BLOCK_BYTES=4096`（安装路径）；`RUN_USB_BLOCK_BYTES` 让虚拟机把 USB 设备挂成 4Kn，产物用默认参数生成即可。
