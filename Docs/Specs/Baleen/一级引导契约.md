# Baleen 一级引导契约

本文规定 BIOS 路径的 IPL、镜像组装器与 Stub 之间的边界。描述符区、介质约束和交权状态是当前的一级引导 ABI；Stub 的自身完整性头与摘要自检不属于本契约，见 [Stub 约定与结构](../../../Packages/Baleen/Stub/README.md)：IPL 不解析它，也不因它改变入口。

## 一、分层职责与完成边界

| 阶段 | 必须承担 | 不属于本阶段 |
| --- | --- | --- |
| IPL | 读取并按当前字段校验描述符区与 Stub 段；把 Stub 文件读到固定地址；按约定交权；任何失败输出诊断并停机 | Stub 镜像头、摘要、签名、BuildId、BSS 校验；A20；内存图；Core 装载；文件系统与选版 |
| Stub | 自身完整性头与摘要自检；自身初始化与内存占用检查；A20；内存图；BIOS 磁盘会话；按后续契约读取 Core 段与镜像头、校验其摘要，再装载并交权 | `BaleenLayout.bin` 的系统卷语义、Ext4、内核集选版与签名策略 |
| Core / UEFI | 解释 `BaleenLayout.bin`、定位系统卷、读取 Ext4、核验内核集摘要与签名、选版与持久化状态、准备内核交接 | 把这些能力倒灌进 IPL，或要求 IPL 因后续组件缺失而扩展 ABI |
| 构建与组装工具 | 生成描述符；验证文件长度、介质布局与读入范围；打包 Stub 与 Core 的完整性头并校验其字段、长度、摘要与内存跨度；对占位载荷显式放行 | 以当前占位件代替真实 Core 实现，或把未经检查的布局称为可发布镜像 |

**IPL 的完成边界是按本契约读入载荷并交权，或在约定错误上停止。** Core 的阶段边界在上层布局、卷访问与内核装载之前，不属于 IPL 的职责；这个边界不构成 IPL 缺陷。IPL 本身是否合格仍由入口、描述符、读盘、交权和失败路径的实际证据判定。

UEFI 直接执行固件应用，绕过 BIOS IPL 和实模式 Stub。

## 二、介质产物与内存窗口

### 2.1 固件入口

| 项 | HDD / USB-HDD | CD / El Torito 无仿真 |
| --- | --- | --- |
| 产物 | `BaleenIPL.bin` | `BaleenIPLCd.bin` |
| 文件大小 | 恰好 512 字节 | 恰好 2048 字节 |
| IPL 代码与数据预算 | 前 446 字节以内；446..509 为分区表 | 代码、数据及偏移 8..63 的 Boot Info Table 保留区全部位于前 510 字节 |
| 引导签名 | 文件偏移 510..511 为 `55 AA`（小端 `0xAA55`） | 文件偏移 510..511 为 `55 AA`；512..2047 不放 IPL 运行必需内容 |
| 固件装入地址 | 物理 `0x7C00` | 物理 `0x7C00`；目录约定 LoadSize 为 4，单位为 512 字节 |
| 读盘本地扇区大小 | 512 或 4096 字节，由 AH=48 查询；查询失败按传统 512 路径，成功但返回短表或其他大小则拒绝 | 2048 字节；不可与目录 LoadSize 的单位混淆 |

两种 IPL 都留在 `0x7C00`，不搬移。CD 的偏移 8..63 按 El Torito 的 Boot Info Table 位置保留，入口跳过该区，IPL 不解析其内容；**本项目不使用该表**：IPL 不读它，混合镜像写入 U 盘后其中的 ISO LBA 也不再有效，因此该区保持全 0，由 `CheckIpl` 核对。代码预算包含这 56 字节空洞。将全部运行必需内容约束在首 510 字节，是本项目的布局要求，不是对所有固件加载行为的保证。

### 2.2 运行期物理地址

| 物理范围或位置 | 用途与有效期 |
| --- | --- |
| `[0x7C00, 0x7E00)` | IPL 执行区；Stub 不得覆盖 |
| `0x7C00` 以下 | 初始 16 位栈向下增长；这不表示所有更低地址均可任意占用 |
| `[0x7E00, 0x10000)` | Stub 装入及静态内存窗口，右端不含 `0x10000` |
| 描述符缓冲 `0x7E00` | 描述符所在的逻辑扇区读到这里；描述符落在缓冲起始，三种单位下扇区内偏移都是 0 |
| HDD `[0x7E00, 0x7E1A)` | AH=48 最小参数表；读取描述符前复用，大小字段位于表内 `0x18` |

描述符缓冲区与 Stub 装入窗口重叠，装入 Stub 时会被覆盖。IPL **不承诺向 Stub 传递持久有效的描述符指针或副本**，也不承诺交权时 `SI` 等寄存器仍能用于读取它。固件即使预先装入整个 CD IPL，其 `0x7E00` 以上部分也会被后续读盘覆盖。

### 2.3 文件字节数与内存字节数

设本地扇区大小为 `SectorBytes`、描述符中的 Stub 文件字节数为 `ImageBytes`，IPL 实际读取 `ceil(ImageBytes / SectorBytes)` 个完整扇区。

| 路径 | 最大文件字节数 | 最大读入扇区数 | 满额读入后的物理末端（不含） |
| --- | --- | --- | --- |
| HDD / USB-HDD，逻辑 512 B | `0x8200`（33280） | 65 × 512 | `0x10000` |
| HDD / USB-HDD，逻辑 4096 B | `0x8000`（32768） | 8 × 4096 | `0xFE00` |
| CD | `0x8000`（32768） | 16 × 2048 | `0xFE00` |

这些上限是**文件镜像**上限。最后一个扇区的填充也会写入内存，必须在介质上可读；填充不计入描述符的文件字节数。共用 512 B 磁盘、4Kn 与 CD 的 Stub 文件必须满足 `0x8000` 上限。

描述符区与 Stub 段没有 BSS 或总内存尺寸字段，IPL 无从检查它们。Stub 头的 `MemoryBytes` 覆盖文件和未落盘的静态内存（包括 BSS）；`0x7E00 + MemoryBytes <= 0x10000` 在构建期与运行期各检查一次，规则见 [Stub 约定与结构](../../../Packages/Baleen/Stub/README.md)。内存预留同时覆盖完整扇区读入范围，不能只检查文件或把扇区填充与 BSS 重复相加。BSS 的清零也由 Stub 负责。CD 文件达到 `0x8000` 时，窗口仍可能容纳尾部 `0x200` 的 BSS，但这不是 IPL 验证过的事实。

## 三、描述符区与 Stub 段

### 3.1 介质位置

描述符**独占引导介质上的一个扇区**，其位置由 IPL 里的**槽**给出：`BaleenIPL.bin` 在文件偏移 `440`（代码之后、446 字节分区表之前）留 4 字节，`BaleenIPLCd.bin` 在偏移 `494` 留 4 字节；槽里是**512 字节基准地址**（值 = 字节偏移 / 512），默认 `272`，对应字节偏移 `0x22000`。装载方按运行期探测到的本地扇区单位右移换算成本地扇区号，所以**同一份镜像在光盘、512e 与 4Kn 上指向同一处物理位置**。**装载器可以覆盖槽里的值**，把描述符区放到别处（覆盖值同样是 512 字节基准）；装载方读槽，不假定固定扇区。它既不是物理内存地址，也不是分区内偏移或 CD 引导镜像内部偏移。

默认扇区位于 GPT 保留区（LBA 1..33）之后，落在任何分区与引导载荷之前；同一份镜像在三种单位下的描述符位置一致，不随介质单位变化。

CD 固件装入的 IPL 文件与这里读取的介质 LBA 0 是两个不同对象。磁盘 / ISO 组装器必须把描述符写到介质的约定扇区。

描述符区的段序列里另有一枚 Stub 阶段的 `CoreDescriptor` 段：它由组装器写入、由 Stub 读取，**不属于本契约**，IPL 不解析它，字段与校验规则见 [Stub 约定与结构](../../../Packages/Baleen/Stub/README.md) 第二节；Core 镜像内部的完整性头同样由 Stub 解释，本契约不涉及。两者同处一个扇区是有意的：Stub 读一次就能同时拿到定位自己的描述符与定位 Core 的描述符。因此描述符扇区内除头部与段序列外不放运行必需内容，组装器按此保留。

### 3.2 字节表

所有整数均为无填充的小端值；字段偏移相对于描述符区起点。

描述符区独占一个扇区，头部给出本区起止扇区；其后是段序列，每段以统一的段头开头。

| 偏移 | 字节数 | 字段 | 当前要求 |
| --- | --- | --- | --- |
| `0x00` | 4 | Magic | `0x43534442`，介质字节为 `BDSC` |
| `0x04` | 2 | Version | 当前值 `1` |
| `0x06` | 2 | HeaderBytes | `16` |
| `0x08` | 4 | AreaLba | 本区起始位置，512 字节基准；必须与 IPL 槽里的值一致（同为基准值，直接比较） |
| `0x0C` | 4 | AreaEndLba | 本区结束位置，512 字节基准，含；不得早于起始 |
| `0x10` 起 | — | 段序列 | 段头 8 字节：标记 4 + 版本 2 + 段长 2（含段头），随后是段内容 |

段按段长遍历、按标记认段，**顺序不作要求**；Stub 段的标记为 `0x52445342`（`BSDR`），其后是载荷的起始与结束位置（各 4 字节，512 字节基准，结束含在范围内）。头部不枚举段，新增段只需在段序列里多写一段。

**位置字段以 512 字节为基准，与目标设备的逻辑扇区单位无关。** 头部与段里的值都是"字节偏移 / 512"，由组装器或安装器写入一次；装载方按运行期探测到的本地单位把它右移换算成本地扇区号（512 字节单位不移、2048 右移 2、4096 右移 3）再读盘。因此同一份字节刻录到光盘、写入 U 盘或移动硬盘（512e / 4Kn）都指向同一处物理位置。描述符区的位置取自 IPL 里的槽（见 3.1），头部的 `areaLba` 必须与槽里的值一致（两者同为基准值，直接比较），不符即拒绝。载荷起点必须按 4096 对齐，保证换算到 512 / 2048 / 4096 三种单位都不错位。

还必须满足以下边界。

1. Stub 段的起始位置换算成本地扇区号后必须大于描述符区扇区号，不得落回描述符扇区之前。
2. 段里的起止位置不得倒置，换算后的扇区数（结束 − 起始 + 1）不得超过 Stub 窗口。
3. 换算后的起始扇区号加扇区数不得产生 32 位进位；恰好到该值也拒绝。
4. 头部与段头里的保留、版本与段长字段按各自规则校验；段长小于段头长度、或段头越过本扇区缓冲即拒绝。

**IPL 只把 Stub 当成有界字节载荷。** 它不解析 Stub 头，不检查 Stub 入口字段、BSS、摘要或签名。Stub 的自身完整性头独立于本描述符，它的字段改动不改变固定的 Stub 交权地址；与实现不匹配的格式标记或头长由 Stub 自己拒绝。开发阶段若修改头格式，须同时更新生成方、读取方和文档。

**不校验 Stub 的完整性头与摘要，直接约束是产物空间预算。** 摘要算法、64 条轮常量，连同整幅文件的遍历与失败诊断，放不进 446 字节（HDD）或 510 字节（CD）的首段预算——当前目标侧 SHA-256 实现单独编译后就约 1.4 KiB，数倍于 HDD 形态的全部代码与数据预算；把校验挪到装入之后也不省这份算法与常量。完整性验证因此下移给有余量的下一阶段：Stub 有自己的镜像上限（HDD 为逻辑 512 时 `0x8200`、4Kn / CD 为 `0x8000`）与独立静态内存，在被装入后、继续初始化之前核对头字段、长度与链接布局的一致性，再比对整幅镜像的 SHA-256 摘要（见 [Stub 约定与结构](../../../Packages/Baleen/Stub/README.md) 第三、四节）。时点也限定了它的性质：自检发生在 IPL 已跳入并开始执行之后，检测的是非预期字节变化；执行前认证及其信任锚仍未定义，不能由这条自检冒充。

组装侧的要求：Stub 与 Core 的文件偏移起点至少 `0x23000` 且按 4096 对齐，使 512 / 2048 / 4096 三种逻辑扇区下都能整扇区读取；描述符区的位置字段按 512 字节基准写入（设备无关，写一次即可），读入范围按最严的 512 字节单位检查上取整（HDD 上限 `0x8200`，4Kn 与 CD 上限 `0x8000`），偏移加长度不得进位。MBR 分区表的 LBA 单位仍按目标设备确定，与载荷放置相互独立——BIOS 路径不解析分区表，见[启动介质与文件系统](../Common/启动介质与文件系统.md) 4.1。媒体长度检查与 BSS、Stub 镜像头的检查是相互独立的约束：后者由 `Tools/Bin/PackImage` 打包时的字段检查、以及 Stub 运行期的头字段与摘要自检承担。

## 四、交给 Stub 的机器状态

仅在描述符通过校验且 Stub 全部读入后，执行远跳转交权。

| 状态 | 保证值 |
| --- | --- |
| 执行环境 | 16 位实模式 |
| `CS:IP` | `0000:7E00` |
| `DS` | `07C0`，仍为 IPL 段，不是 Stub 自身的数据段 |
| `ES` | `0000` |
| `SS:SP` | `0000:7C00` |
| `DL` | 实际读取 Stub 的 BIOS 驱动器号；HDD 沿用固件值，CD 可能使用探测候选号 |
| `DH` | `2` = HDD / USB-HDD；`4` = CD |
| `CX` | 本次装载使用的逻辑扇区字节数：HDD 512 / 4096，CD 2048；Stub 保存并沿用，描述符位置字段的换算也按它计算 |
| `ESI` | 描述符所在扇区的 LBA（本地单位）；Stub 按它定位同扇区的 `CoreDescriptor`，段内位置字段按 `CX` 给出的单位换算 |
| `IF` | `1` |
| `DF` | `0` |

**除此之外的寄存器和标志均不承诺，A20 状态也不承诺。** Stub 必须先保存驱动器、介质身份和 `CX` 扇区单位，再自行建立数据段、内存所有权及后续运行环境。`CX` 是入口契约的一部分，IPL 与 Stub 必须配套构建，不能混用旧 IPL；描述符的字节格式与版本保持不变。

## 五、读盘、重试与兼容边界

### 5.1 EDD 请求与失败恢复

IPL 主路径使用 INT 13h / AH=42h，使用按 DWORD 对齐的 16 字节 DAP，块数单位为当前介质的本地扇区。描述符只读 1 个扇区；Stub 最多请求 512 B HDD 65 块、4Kn HDD 8 块或 CD 16 块，不需要通用的大文件分批装载器。HDD 读取之前用 AH=48 查询 26 字节参数表，返回表长至少 `0x1A` 且 `0x18` 处扇区大小为 512 / 4096 才接受；CF 失败时仅保留传统 512 兼容路径，不靠描述符魔数猜测单位。4Kn 要求固件提供有效的 EDD 参数与扩展读取。

每个 `Read_Range` 请求最多进行 **3 轮尝试（含首次）**，失败轮之间用 AH=00h 复位，最多进行 2 次这样的轮间复位。只走 EDD（`AH=42h`），不保留 CHS 回退。此上限是项目策略，不是固件保证。

主批量请求耗尽尝试后，必须从**原始 LBA 和原始目标地址**开始，将整个范围逐扇区重读；每个单扇区请求同样受上述上限约束。不能按失败调用回写的 DAP 块数、AH 或 AL 推定前缀已成功，更不能跳过部分读取后的未知内容。任一必要扇区最终读失败即停止，不进入 Stub。

RBIL 的 AH=42h 条目明确区分 CF 成功 / 失败和 AH 返回状态，并记载 DAP 块数可能回写。因此 BIOS 调用后必须保留或恢复原始请求数据，不能按回写的字段推定前缀已成功。该条目将 `007Fh`（127 块）上限具体记在 Phoenix EDD 下；本项目采用不超过 127 块的保守请求约束。依据见第八节。

### 5.2 只走 EDD 的边界

硬盘与光盘都只使用 EDD（`AH=42h`），没有 CHS 回退：引导载荷自 `0x23000` 起，远超 C0H0 能覆盖的前 63 个扇区，回退路径不可能命中，因此不保留。软盘、USB-FDD 和 USB-ZIP 不在支持范围；HDD 入口对 `DL<0x80` 输出 `D`。**固件必须提供 EDD 与 `AH=48` 参数查询**：不提供 EDD 的极老机器不在支持范围内。

### 5.3 CD 的驱动器候选

CD 只使用 EDD，没有 CHS 回退。原始 `DL >= 0x80` 时优先尝试它，再按失败路径尝试 `0xE0` / `0xE1`；原始 `DL < 0x80` 时从 `0xE0` 开始。这是有限的候选策略，不是枚举所有光驱或保证所有 BIOS 的编号习惯相同。

候选读取先识别描述符魔数，再由公共路径校验其余字段；命中候选不表示结构校验已经通过，也不承诺遇到后续结构错误时继续遍历其他驱动器。探测不能取得可读且合法的描述符时以 `D` 结束；已取得的描述符若长度非法，按 `S` 处理。

## 六、失败诊断

| 字符 | 含义 |
| --- | --- |
| `R` | HDD 描述符所在扇区读取失败 |
| `D` | HDD 驱动器号不支持，或 AH=48 成功但返回短表 / 不支持的扇区大小；描述符魔数、版本、头长或保留字段非法；偏移高位、对齐、起点或文件末端加法非法；CD 候选探测未取得可读合法描述符 |
| `S` | Stub 长度高 32 位非零、长度为零，或超过对应介质的文件上限 |
| `L` | 描述符通过后，Stub 所需扇区读取最终失败 |

错误通过 BIOS 电传输出；启用 `ENABLE_E9` 时也写入 `0xE9` 调试口。随后关中断并进入停机循环。若固件显示服务本身不可用，不额外保证可见字符，但**所有失败路径都不得跳入 Stub**。同一描述符存在多种错误时以首先检查出的错误为准，不承诺同时报告多个原因。

这些是 IPL 的错误码。Stub 的头、摘要、内存、A20 或 Core 错误使用自己的诊断约定（当前为带 `FATAL` 标签的诊断行），不能伪装成 IPL 已检查的内容。

## 七、源码对应与验证边界

两种源入口分别包含 `Hdd.inc` / `Cd.inc`，由各自入口组合共享片段，职责如下。

| 文件（相对 `Packages/Baleen/Ipl`） | 职责 |
| --- | --- |
| `Src/Mbr.asm` / `Src/Cdrom.asm` | 各自介质参数、产物外壳、尺寸与签名；分别包含 `Hdd.inc` / `Cd.inc` |
| `Include/Hdd.inc` / `Include/Cd.inc` | 各介质的描述符入口及 CD 候选探测；分别包含 `Init.inc`、`Body.inc`、`Error.inc`、`Read.inc` |
| `Include/Init.inc` | 包含 `Const.inc`，归一化实模式段、栈和标志，保存固件驱动器号 |
| `Include/Body.inc` | 描述符共同校验、Stub 长度与范围检查、装入和交权 |
| `Include/Error.inc` | 单字符诊断与停机 |
| `Include/Read.inc` | EDD、复位与有界重试、请求状态保护 |
| `Include/Const.inc` | 当前 IPL 地址、描述符字段、媒体编号及长度上限 |

正常构建只能依赖正式的 C++、ASM、Makefile 与 sh 源码及工具；`Test` 不上传，不能成为 Makefile 的构建依赖或交付必要文件。静态尺寸等约束可由 NASM 汇编期断言和正式 C++ 工具承担。IPL 回归工具采用 `Tools/Build/CheckIpl` → `Tools/Bin/CheckIpl` 的独立工具形态，由工具构建环节产出、按需手工执行；其实际实现和检查结果以工具及测试记录为准，不把运行回归挂成默认构建依赖，也不要求本地测试目录或额外脚本语言。

Core 的布局、卷访问与内核装载不属于 IPL 的职责，UEFI 路径也绕过 IPL，两者是各自独立的阶段。
