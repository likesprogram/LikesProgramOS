# Baleen 一级引导契约

本文规定 BIOS 路径的 IPL、镜像组装器与 Stub 之间的边界。`BootDescriptor`、介质约束和交权状态是当前开发中的一级引导 ABI；未来 Stub 的完整性头见 [Stub 约定与结构草案](../../../Packages/Baleen/Stub/README.md)，尚未启用。

**BootDescriptor 尚未发布。** 字段中的 `Version=1` 只是当前开发格式标记，不是已发布的“第一版”，不承担旧格式迁移或兼容保证；首发后再建立正式版本管理规则。本文记录当前字段和行为，本次文档工作不改变源码中的格式。

本文统一一级引导的运行期口径。旧说明中把 `0x300` 称为物理内存地址、把 BSS 上限算作 IPL 可检查项，或把选版分配给 Stub 的表述，以本文为准。这里定义契约，不声称所有组装工具、后续阶段或硬件验证已经完成。

## 一、分层职责与完成边界

| 阶段 | 必须承担 | 不属于本阶段 |
| --- | --- | --- |
| IPL | 读取并按当前字段校验 `BootDescriptor`；把 Stub 文件读到固定地址；按约定交权；任何失败输出诊断并停机 | Stub 镜像头、摘要、签名、BuildId、BSS 校验；A20；内存图；Core 装载；文件系统与选版 |
| Stub（待实现） | 自身初始化与内存占用检查；A20；内存图；BIOS 磁盘会话；按后续契约装载 Core 并交权 | `BaleenLayout.bin` 的系统卷语义、Ext4、内核集选版与签名策略 |
| Core / UEFI（待实现） | 解释 `BaleenLayout.bin`、定位系统卷、读取 Ext4、核验内核集摘要与签名、选版与持久化状态、准备内核交接 | 把这些能力倒灌进 IPL，或要求 IPL 因后续组件缺失而扩展 ABI |
| 构建与组装工具 | 生成描述符；验证文件长度、介质布局与读入范围；未来验证 Stub 的内存占用、完整性头和 Baleen 构建身份 | 以当前占位件代替真实 Stub/Core 实现，或把未经检查的布局称为可发布镜像 |

**IPL 的完成边界是按本契约读入载荷并交权，或在约定错误上停止。** Stub/Core 未实现、占位件主动停机以及尚不能进入内核，属于后续阶段未完成，不能据此判定 IPL 存在缺陷。IPL 本身是否合格仍需由入口、描述符、读盘、交权和失败路径的实际证据判定。

UEFI 直接执行固件应用，绕过 BIOS IPL 和实模式 Stub。

## 二、介质产物与内存窗口

### 2.1 固件入口

| 项 | HDD / USB-HDD | CD / El Torito 无仿真 |
| --- | --- | --- |
| 产物 | `BaleenIPL.bin` | `BaleenIPLCd.bin` |
| 文件大小 | 恰好 512 字节 | 恰好 2048 字节 |
| IPL 代码与数据预算 | 前 446 字节以内；446..509 为分区表 | 代码、数据及偏移 8..63 的 Boot Info Table 保留区全部位于前 510 字节 |
| 引导签名 | 文件偏移 510..511 为 `55 AA`（小端 `0xAA55`） | 文件偏移 510..511 为 `55 AA`；512..2047 不放 IPL 运行必需内容 |
| 固件装入地址 | 物理 `0x7C00` | 物理 `0x7C00`；目录约定 LoadSize 为 4，单位为 512 字节 |
| 读盘本地扇区大小 | 512 字节 | 2048 字节；不可与目录 LoadSize 的单位混淆 |

两种 IPL 都留在 `0x7C00`，不搬移。CD 的偏移 8..63 留给镜像工具写入 Boot Info Table，入口跳过该区，IPL 不解析其内容；代码预算包含这 56 字节空洞。将全部运行必需内容约束在首 510 字节，是本项目的布局要求，不是对所有固件加载行为的保证。

### 2.2 运行期物理地址

| 物理范围或位置 | 用途与有效期 |
| --- | --- |
| `[0x7C00, 0x7E00)` | IPL 执行区；Stub 不得覆盖 |
| `0x7C00` 以下 | 初始 16 位栈向下增长；这不表示所有更低地址均可任意占用 |
| `[0x7E00, 0x10000)` | Stub 装入及静态内存窗口，右端不含 `0x10000` |
| HDD `0x7F00` | 描述符扇区读到 `0x7E00` 后，`BootDescriptor` 的临时地址 |
| CD `0x8100` | 描述符扇区读到 `0x7E00` 后，`BootDescriptor` 的临时地址 |

描述符缓冲区与 Stub 装入窗口重叠，装入 Stub 时会被覆盖。IPL **不承诺向 Stub 传递持久有效的描述符指针或副本**，也不承诺交权时 `SI` 等寄存器仍能用于读取它。固件即使预先装入整个 CD IPL，其 `0x7E00` 以上部分也会被后续读盘覆盖。

### 2.3 文件字节数与内存字节数

设本地扇区大小为 `SectorBytes`、描述符中的 Stub 文件字节数为 `ImageBytes`，IPL 实际读取 `ceil(ImageBytes / SectorBytes)` 个完整扇区。

| 路径 | 最大文件字节数 | 最大读入扇区数 | 满额读入后的物理末端（不含） |
| --- | --- | --- | --- |
| HDD / USB-HDD | `0x8200`（33280） | 65 × 512 | `0x10000` |
| CD | `0x8000`（32768） | 16 × 2048 | `0xFE00` |

这两个上限是**文件镜像**上限。最后一个扇区的填充也会写入内存，必须在介质上可读；填充不计入描述符的文件字节数。共用 HDD/CD 的 Stub 文件必须满足更严格的 CD 上限。

`BootDescriptor` 没有 BSS 或总内存尺寸字段，IPL 无从检查它们。未来 Stub 的 `MemoryBytes` 必须覆盖文件和未落盘的静态内存（包括 BSS）；打包器与 Stub 分别负责构建期和运行期检查 `0x7E00 + MemoryBytes <= 0x10000`。内存预留同时覆盖完整扇区读入范围，不能只检查文件或把扇区填充与 BSS 重复相加。BSS 的清零也由 Stub 负责。CD 文件达到 `0x8000` 时，窗口仍可能容纳尾部 `0x200` 的 BSS，但这不是 IPL 验证过的事实。

## 三、BootDescriptor

### 3.1 介质位置

描述符位于**整个引导介质的绝对字节偏移 `0x300`**，既不是物理内存 `0x300`，也不是分区内偏移或 CD 引导镜像内部偏移。

- HDD：512 字节 LBA 1 内的偏移 `0x100`。
- CD：2048 字节 LBA 0 内的偏移 `0x300`。

CD 固件装入的 IPL 文件与这里读取的介质 LBA 0 是两个不同对象。磁盘 / ISO 组装器必须把描述符写到介质的约定位置。

同一扇区的绝对偏移 `0x340` 留给 Stub 阶段的 `CoreDescriptor`：它由组装器写入、由 Stub 读取，**不属于本契约**，IPL 不解析它，字段与校验规则见 [Stub 约定与结构草案](../../../Packages/Baleen/Stub/README.md) 第二节。两者落在同一扇区是有意的：Stub 读一次就能同时拿到定位自己的描述符与定位 Core 的描述符。因此 `[0x300, 0x400)` 之间除这两个描述符外不放运行必需内容，组装器按此保留。

### 3.2 字节表

所有整数均为无填充的小端值，总长固定为 32 字节；字段偏移相对于描述符起点。

| 偏移 | 字节数 | 字段 | 当前要求 |
| --- | --- | --- | --- |
| `0x00` | 4 | Magic | `0x52445342`，介质字节为 `BSDR` |
| `0x04` | 2 | Version | 当前值 `1`，未发布的开发格式标记 |
| `0x06` | 2 | HeaderBytes | `32` |
| `0x08` | 8 | StubFileOffset | 介质绝对字节偏移；高 32 位为 0；低 32 位非零且按本地扇区对齐 |
| `0x10` | 8 | StubImageBytes | 文件字节数；高 32 位为 0；低 32 位非零且不超过对应介质的最大文件字节数 |
| `0x18` | 8 | Reserved | 8 字节全部为 0 |

还必须满足以下边界。

1. Stub 起点在描述符所在扇区之后：HDD `StubFileOffset >= 0x400`；CD `StubFileOffset >= 0x800`。不得落在描述符扇区内，也不得指回其之前的区域。
2. `StubFileOffset + StubImageBytes` 的低 32 位加法不得进位，数学和必须小于 `0x100000000`；恰好到该值也拒绝。偏移和长度均先按上表验证，再进行运算。
3. 向本地扇区上取整后的读取范围必须位于 Stub 窗口内；第二节的媒体长度上限保证此项。介质是否真的提供这些字节，由读盘结果及组装器的文件范围检查共同约束。
4. 保留字段当前全部为零。BuildId、摘要和后续装载信息应由所属阶段的结构承担；本次不把它们放入描述符，依据是 IPL 的职责、有限代码空间与内存约束，不是要兼容某个已发布版本。Core 的定位信息已经按这条原则落到同扇区的 `CoreDescriptor`，见 3.1。

**IPL 只把 Stub 当成有界字节载荷。** 它不解析 Stub 头，不检查 Stub 入口字段、BSS、摘要或签名。未来结构草案独立于本描述符，本次不更改其当前字段，也不改变固定的 Stub 交权地址。与当前实现不匹配的格式标记或头长直接拒绝；开发阶段若修改格式，须同时更新生成方、读取方和文档。

当前公共 C++ 组装代码已经按媒体扇区大小检查上取整范围，分别接受 HDD `0x8200` 与 CD `0x8000` 的文件上限，并检查偏移和文件末端。工具对两种介质统一采用起点至少 `0x800`、2048 字节对齐的放置策略，比 HDD IPL 的最低要求更严格。BSS 与未来 Stub 镜像头仍需后续工具及 Stub 实现，媒体长度检查通过不表示这些检查已经完成。

## 四、交给 Stub 的机器状态

仅在描述符通过校验且 Stub 全部读入后，执行远跳转交权。

| 状态 | 保证值 |
| --- | --- |
| 执行环境 | 16 位实模式 |
| `CS:IP` | `0000:7E00` |
| `DS` | `07C0`，仍为 IPL 段，不是 Stub 自身的数据段 |
| `ES` | `0000` |
| `SS:SP` | `0000:7C00` |
| `DL` | 实际读取 Stub 的 BIOS 驱动器号；HDD 沿用固件值，CD 可能使用探测候选号 |
| `DH` | `2` = HDD / USB-HDD；`4` = CD |
| `IF` | `1` |
| `DF` | `0` |

**除此之外的寄存器和标志均不承诺，A20 状态也不承诺。** Stub 必须先保存仍需要的驱动器与介质身份，再自行建立数据段、内存所有权及后续运行环境；不能把进入时的其他寄存器或被覆盖的描述符缓冲当成隐式参数。

## 五、读盘、重试与兼容边界

### 5.1 EDD 请求与失败恢复

IPL 主路径使用 INT 13h / AH=42h，使用 16 字节 DAP，块数单位为当前介质的本地扇区。描述符只读 1 个扇区；Stub 最多请求 HDD 65 块或 CD 16 块，不需要通用的大文件分批装载器。

每个 `Read_Range` 请求最多进行 **3 轮尝试（含首次）**，失败轮之间用 AH=00h 复位，最多进行 2 次这样的轮间复位。HDD 满足下一节条件时，一轮中可在 EDD 失败后尝试 CHS。此上限是项目策略，不是固件保证。

主批量请求耗尽尝试后，必须从**原始 LBA 和原始目标地址**开始，将整个范围逐扇区重读；每个单扇区请求同样受上述上限约束。不能按失败调用回写的 DAP 块数、AH 或 AL 推定前缀已成功，更不能跳过部分读取后的未知内容。任一必要扇区最终读失败即停止，不进入 Stub。

RBIL 的 AH=42h 条目明确区分 CF 成功 / 失败和 AH 返回状态，并记载 DAP 块数可能回写。因此 BIOS 调用后必须保留或恢复原始请求数据，尤其不能把已被返回状态覆盖的 AH 当作原 LBA 的一部分继续用于 CHS。该条目将 `007Fh`（127 块）上限具体记在 Phoenix EDD 下；本项目采用不超过 127 块的保守请求约束，不把它解释为所有 BIOS 均支持任意 127 块传输的保证。依据见第八节。

### 5.2 HDD 的有限 CHS 回退

只在单扇区请求且 `LBA < 63` 时保留 AH=02h 回退，编码固定为 `C=0`、`H=0`、`S=LBA+1`。这是 C0H0 范围内的兼容路径，不进行任意磁盘几何换算。

只有固件提供相应 CHS 服务、实际几何接受请求的扇区号，且描述符与全部 Stub 读取都落在这个范围内，才可能完成整段回退启动。例如某固件每磁道少于 63 扇区，则 `LBA < 63` 本身仍不足以证明请求有效。完整的 65 扇区 Stub 上限也不代表无 EDD 时可读满该长度。

不得将此路径写成“所有无 EDD 的机器都能启动”，也不得用模拟器某一组几何的结果替代旧 BIOS 及实际介质的验证。

### 5.3 CD 的驱动器候选

CD 只使用 EDD，没有 CHS 回退。原始 `DL >= 0x80` 时优先尝试它，再按失败路径尝试 `0xE0` / `0xE1`；原始 `DL < 0x80` 时从 `0xE0` 开始。这是有限的候选策略，不是枚举所有光驱或保证所有 BIOS 的编号习惯相同。

候选读取先识别描述符魔数，再由公共路径校验其余字段；命中候选不表示结构校验已经通过，也不承诺遇到后续结构错误时继续遍历其他驱动器。探测不能取得可读且合法的描述符时以 `D` 结束；已取得的描述符若长度非法，按 `S` 处理。

## 六、失败诊断

| 字符 | 含义 |
| --- | --- |
| `R` | HDD 描述符所在扇区读取失败 |
| `D` | 描述符魔数、版本、头长或保留字段非法；偏移高位、对齐、起点或文件末端加法非法；CD 候选探测未取得可读合法描述符 |
| `S` | Stub 长度高 32 位非零、长度为零，或超过对应介质的文件上限 |
| `L` | 描述符通过后，Stub 所需扇区读取最终失败 |

错误通过 BIOS 电传输出；启用 `ENABLE_E9` 时也写入 `0xE9` 调试口。随后关中断并进入停机循环。若固件显示服务本身不可用，不额外保证可见字符，但**所有失败路径都不得跳入 Stub**。同一描述符存在多种错误时以首先检查出的错误为准，不承诺同时报告多个原因。

这些是 IPL 的错误码。Stub 未来的头、摘要、内存、A20 或 Core 错误应使用自己的诊断约定，不能伪装成 IPL 已检查的内容。

## 七、源码对应与验证边界

两种源入口分别包含 `Hdd.inc` / `Cd.inc`，由各自入口组合共享片段，职责如下。

| 文件（相对 `Packages/Baleen/Ipl`） | 职责 |
| --- | --- |
| `Src/Mbr.asm` / `Src/Cdrom.asm` | 各自介质参数、产物外壳、尺寸与签名；分别包含 `Hdd.inc` / `Cd.inc` |
| `Include/Hdd.inc` / `Include/Cd.inc` | 各介质的描述符入口及 CD 候选探测；分别包含 `Init.inc`、`Body.inc`、`Error.inc`、`Read.inc` |
| `Include/Init.inc` | 包含 `Const.inc`，归一化实模式段、栈和标志，保存固件驱动器号 |
| `Include/Body.inc` | 描述符共同校验、Stub 长度与范围检查、装入和交权 |
| `Include/Error.inc` | 单字符诊断与停机 |
| `Include/Read.inc` | EDD、有限 HDD CHS 回退、复位与有界重试、请求状态保护 |
| `Include/Const.inc` | 当前 IPL 地址、描述符字段、媒体编号及长度上限 |

正常构建只能依赖正式的 C++、ASM、Makefile 与 sh 源码及工具；`Test` 不上传，不能成为 Makefile 的构建依赖或交付必要文件。静态尺寸等约束可由 NASM 汇编期断言和正式 C++ 工具承担。IPL 回归工具采用 `Tools/Build/CheckIpl` → `Tools/Bin/CheckIpl` 的独立工具形态，由工具构建环节产出、按需手工执行；其实际实现和检查结果以工具及测试记录为准，不把运行回归挂成默认构建依赖，也不要求本地测试目录或额外脚本语言。

验证报告必须区分以下层次，具体测试方法与结果由对应测试记录给出，本文不宣布已通过。

- 静态产物检查与 ABI 检查只能证明其检查的尺寸、字段、路径和交权条件；到达测试载荷或占位 Stub 的标记只能证明执行到了该载荷。
- Stub/Core 尚未实现不构成 IPL 缺陷，也不能因 IPL 交权成功就宣称完整引导链、内核选版或签名验证完成。
- QEMU、Bochs 及固件模拟环境的实测不能替代真机、物理 USB、物理光驱或旧 BIOS 验证。工业可用性声明需要记录实际机器、固件、设备与故障恢复证据，不从接口文献或少量成功案例推出普遍兼容。
- UEFI 路径绕过 IPL；其通过不能计为 BIOS IPL 测试通过。依赖、固件文件缺失或未执行的测试应记为缺失 / 跳过，不能当成通过。

## 八、外部依据

- [RBIL：INT 13h / AH=42h — EXTENDED READ](https://www.ctyme.com/intr/rb-0708.htm)：DAP、CF/AH 返回语义、块数回写，以及 Phoenix EDD 的 127 块记载。
- [RBIL：INT 13h / AH=02h — READ SECTOR(S)](https://www.ctyme.com/intr/rb-0607.htm)：CHS 输入、CF/AH 返回，以及部分 BIOS 的寄存器、几何与跨磁道行为差异；其中复位与至少三次重试的建议针对软盘场景，本文的有界重试是项目选择。

RBIL 是接口及历史兼容行为资料，不是本项目或各 BIOS 厂商出具的硬件验证报告。
