# 内核镜像数据

**内核镜像数据是内核镜像文件起点的一份固定结构。** 它随镜像一起被写入系统卷、被 BaleenCore 读入，用来核对两件事：这份内核镜像声明了什么事实（长度、内存跨度、入口、装载地址、它要求的 `BootInfo` 版本），以及它载入的字节是否完整。它不参与执行，不被固件识别，也不是可执行的镜像头——内核镜像不带任何固件能直接识别的标准头，进入内核的入口由 [Baleen 引导器](README.md) 的交接契约准备。

字节表的单点定义在 `Packages/Common/Include/KernelImage.hpp`；宿主侧的派生与写入在 `Tools/Bin/MakeManifest`，结构、摘要与身份的校验在 `Tools/Build/Common` 的 `KernelImage`（由 `Tools/Bin/PackImage` 调用）；内核侧的字段布局在 `Packages/LikesProgramOS/Core` 的汇编与链接脚本里与同一份定义对齐。

## 一、位置与形态

| 项 | 约定 |
| --- | --- |
| 位置 | 内核镜像文件字节偏移 `0`，占 `0x80` 字节 |
| 单位无关 | 偏移相对文件起点，与介质逻辑扇区大小、卷内布局无关 |
| 入口 | 数据之后的第一个字节，文件偏移由 `EntryOffset` 给出（当前 `0x80`）；数据本身不被执行 |
| 内容源 | 格式标记、固定取值、入口与装载地址由内核构建的汇编常量给出；长度字段由链接器按镜像与未初始化区边界填入；`ModuleMajor` 由汇编常量给出；`BuildId`（`.os` 发布线身份）与 `Digest` 由 `MakeManifest` 在集组装期写入，`PackImage` 只校验 |
| 只读 | 数据落在镜像的落盘区，载入后不得改写：摘要覆盖它，任何改动都要重跑打包器 |

**这份数据描述的是一个文件，不是一个卷。** 内核在卷内的路径、系统卷的位置与卷标识属于[布局描述](布局描述.md)；把两者混在一处会让同一份内核镜像无法被不同介质布局复用。

## 二、字节表

所有整数小端序，不允许编译器填充；偏移相对文件起点。保留字段必须写 0，读取方遇到非 0 保留字段按格式不符拒绝，不猜测语义。

| 偏移 | 字节数 | 字段 | 当前语义 | 填出方 |
| --- | --- | --- | --- | --- |
| `0x00` | 8 | `Magic` | 字节 `4C 50 4F 53 4B 52 4E 00`，即 `LPOSKRN` 加终止零 | 汇编常量 |
| `0x08` | 2 | `Version` | 当前值 `1` | 汇编常量 |
| `0x0A` | 2 | `DataBytes` | `0x80`，本结构长度 | 汇编常量 |
| `0x0C` | 4 | `Flags` | `0`，当前不定义可选标志 | 汇编常量 |
| `0x10` | 4 | `ImageBytes` | 内核镜像文件的实际字节数，含本数据；不含扇区填充与未落盘部分 | 链接器按 `__image_end` |
| `0x14` | 4 | `MemoryBytes` | 从装载地址起的静态内存跨度，包含文件与未落盘部分（BSS、栈、页表与分配器存储） | 链接器按 `__bss_end` |
| `0x18` | 4 | `EntryOffset` | 入口的文件偏移；须落在 `[0x80, ImageBytes)`，实际由链接布局保证 | 汇编常量 |
| `0x1C` | 4 | `LoadAddress` | 内核镜像装载的物理地址，按 2MiB 对齐且不低于 1MiB（当前 `0x1000000`） | 汇编常量 |
| `0x20` | 2 | `DigestAlgorithm` | `1` = SHA-256；其他值拒绝，无“禁用摘要”值 | 汇编常量 |
| `0x22` | 2 | `BuildIdBytes` | `32` | 汇编常量 |
| `0x24` | 4 | `BootInfoVersion` | 内核要求的 `BootInfo` 版本，当前 `1` | 汇编常量 |
| `0x28` | 32 | `BuildId` | `.os` 发布线身份（`KernelSets/<BuildId>/` 的集目录名）：由 `.os` 内容摘要与集内路径派生，模块补丁不改变它；全零保留为“未分配”，原型以外的正式产物不得为全零 | `MakeManifest` 按发布线身份填入 |
| `0x48` | 32 | `Digest` | 按第三节计算的 SHA-256 原始 32 字节摘要，不是十六进制文本 | `MakeManifest` 在 `BuildId` 填入后计算并写入；`PackImage` 校验 |
| `0x68` | 2 | `ModuleMajor` | 本内核所属的发布线，非零；每个 `.osm` 的 `ModuleVersionMajor` 必须与它硬相等，跨主版本一律拒绝装载 | 汇编常量（`KERNEL_MODULE_MAJOR`） |
| `0x6A` | 22 | `Reserved` | 全 0 | 汇编常量 |

约束至少包括 `ImageBytes > 0x80`、`MemoryBytes >= ImageBytes`、`EntryOffset` 落在数据之后与文件之内、`LoadAddress` 按 2MiB 对齐且映像与静态内存按装载对齐上取整后不越出 32 位物理地址范围。所有加法与上取整都先检查溢出。

## 三、摘要覆盖与自引用处理

设文件的原始字节串为 `F`、实际长度为 `ImageBytes`。摘要字段位于文件 `[0x48, 0x68)`，计算时只将这 32 字节视为零：

```text
Digest = SHA-256(F[0x00:0x48] || 32 个零字节 || F[0x68:ImageBytes])
```

切片右端均不含。格式标记、版本、长度、入口、装载地址、`BuildId`、全部保留字节、代码与落盘数据都在覆盖范围内，只有摘要本身按规则归零，避免自引用。

**`BuildId` 不是由本文件内容派生的整集摘要。** 它是 `.os` 发布线身份：由 `.os` 的内容摘要与集内路径一起算出，模块补丁不改变它，见[内核集清单与签名](../内核集清单与签名.md) 2.2。`MakeManifest` 先算出发布线身份并写入 `BuildId` 字段，再按上式（此时 `BuildId` 已填入）计算并写入 `Digest`；`PackImage` 只校验结构、`ModuleMajor` 与 `Digest`（旧 `PackImage` 内核身份填充路径已退役，历史记录见[退役项清单](../../Test/退役项清单.md)）。

为了在填充前后得到同一个可核对的内容标识，本文件定义**内容摘要** `C_os`：把 `BuildId` 与 `Digest` 两段都按 32 个零字节代入后，对 `[0, ImageBytes)` 计算 SHA-256：

```text
C_os = SHA-256(F[0x00:0x28] || 32 个零字节 || 32 个零字节 || F[0x68:ImageBytes))
```

`C_os` 只描述这份 `.os` 的字节内容（`ModuleMajor` 也在覆盖范围内），不写入文件；`MakeManifest` 用它参与发布线身份派生，`--verify` 也用它重算身份。**单个 `.os` 无法自证发布线身份**：`BuildId` 是否成立要与集路径一起核对（[内核集清单与签名](../内核集清单与签名.md) 第三节）；`PackImage` 只核对结构、`ModuleMajor` 与 `Digest`，`--expect-build-id` 可额外比对期望身份，但不重算身份。

覆盖范围不包含介质上的布局描述、最后一个本地扇区的文件外填充、未落盘的静态内存，也不包含内核集里的其他载荷与清单。

## 四、校验顺序

BaleenCore 按[布局描述](布局描述.md)给的 `KernelPath` 定位内核镜像后，依次检查，任一不通过即报告原因并停机，不猜测：

1. **定位**：按路径打开并取事实——必须是常规文件、字节数非零且落在 32 位范围内；路径不存在时按“内核尚未放入系统卷”处理，不视为结构错误。
2. **结构与事实**：读首块核对格式标记、版本、数据长度、标志、摘要算法、`BuildId` 长度与保留字段；`ImageBytes` 必须与实际文件长度一致，`MemoryBytes` 必须覆盖文件，`EntryOffset` 必须落在数据之后与文件之内，`LoadAddress` 必须对齐且映像跨度不越出 32 位物理范围。
3. **BootInfo 版本**：`BootInfoVersion` 必须是本侧能构造的版本，否则拒绝，不带着无法满足的要求交接。
4. **装载区**：`max(MemoryBytes, ImageBytes)` 整段必须落在交权块内存图的**可用区间**内，相邻的可用条目按同一段连续内存合并覆盖；不假定装载地址以上一定可写。
5. **摘要**：从文件起点流式重读整幅文件计算 SHA-256，`Digest` 字段按 32 个零代入，与数据里的摘要逐字节比较。

内核入口以同一份数据反向核对链接布局：`ImageBytes`、`MemoryBytes` 必须与 `__image_end`、`__bss_end` 一致，`LoadAddress` 必须等于镜像实际运行地址，`EntryOffset` 必须等于入口符号相对镜像起点的偏移。**摘要不重复取**：引导器已在交接前比对过整幅镜像，内核只核对结构与配对关系。

**`BuildId` 的一致性不在本节由镜像自身证明**：选版阶段把镜像里的 32 字节 `BuildId` 与清单 `BuildId`、所选集标识逐字节比较（[内核集清单与签名](../内核集清单与签名.md) 第三节第 8、10 条）；`ModuleMajor` 还要与 `Modules.list` 的 `major` 及每个 `.osm` 的主版本比较，跨主版本一律拒绝（[模块修订与更新](../模块修订与更新.md)）。P5 起内核入口还会用随 `BootInfo` 交来的清单副本与列表再核对一次。本节只定义字段与摘要规则，不把“文件自称是谁”当成身份。

## 五、装载与交接的当前边界

| 环节 | 当前状态 |
| --- | --- |
| 读取与校验 | 已实现：BaleenCore 按路径定位、读首块核对数据、流式比对整幅摘要并核对装载区 |
| 装载到内存 | 已实现：BaleenCore 把镜像整幅读进 `LoadAddress`，并按 `MemoryBytes` 清零未落盘尾部 |
| 机器状态 | 已实现：BaleenCore 按恒等映射建页表（4 级表、2MiB 大页覆盖低 4GiB）、构造 `BootInfo` 并把内存图复制到自己的静态存储，切长模式跳到入口 |
| 内核侧入口 | 已接通：交接路径跳入本入口，内核核对镜像数据与 `BootInfo`、让固件启动服务失效、建描述符表与中断表、引导页表与直映射、页帧分配器，见 [内核侧 Core 说明](../../../Packages/LikesProgramOS/Core/README.md)；设备模型、模块装载、调度与 Init 属于后续阶段 |
| 选版与签名 | 已实现：BaleenCore 读引导状态记录选版，验证所选集的清单结构与 Ed25519 签名、`BuildId` 一致、防回滚比较与逐产物摘要，并按需写回 `Trying` / `Failed` 与已见版本；状态机见[内核集更新与回滚](../内核集更新与回滚.md)，记录与信任锚见[引导状态记录](引导状态记录.md)与[内核集清单与签名](../内核集清单与签名.md) |

`LoadAddress` 当前是内核构建的常量 `0x1000000`；交接阶段建的页表是过渡映射，内核随后换上自己的引导页表并加 `0xFFFF800000000000` 的直映射窗口。更高半区的虚拟地址布局仍未定义，届时本表的字段语义（物理装载地址与虚拟入口的关系）在同一份规格里更新。
