# 失败诊断编号

内核侧的失败编号（`E-KRN`）登记在[内核诊断编号](../内核诊断编号.md)，本文只覆盖引导链阶段的编号。

本文登记引导链各阶段的稳定失败编号：`E-IPL`、`E-STUB`、`E-CORE` 与 `E-UEFI`。编号是工单、日志聚合与自动化回归引用的标识；**同一编号的含义一经发布不再改动，文本可以润色**。编号随诊断行一起输出：Stub 与 BaleenCore 的 `FATAL` / `WARN` 行格式为 `[ FATAL ] E-CORE-07 <文本>`，编号与文本之间一个空格；UEFI 侧的固件应用用同一个格式。

编号在各阶段内唯一，序号不要求连续。文本与编号的配对定义在源码里的 `Baleen::Diagnostic` 常量：各包自己的常量在 `Packages/Baleen/Common/Include/Diagnostics.hpp`，与 BaleenCore 共用的选版、清单验签与内核装载实现（`SelectSet.cpp`、`ManifestVerify.cpp`、`LoadKernel.cpp`）里的常量定义在各自源文件；本表是它们的登记副本，**新增编号必须同时改源码与本文**。回归工具按编号或文本子串断言，改动文本时须同步检查 `CheckStub` / `CheckIpl` 的期望值。

## 一、E-IPL：一级引导

IPL 是 16 位纯汇编，446 / 510 字节的首段预算放不下编号文本：失败码是**大于零的整数**，屏幕上与 `0xE9` 调试口里各输出它的一位十六进制字符（码 `1`..`7` 输出 `1`..`7`）。一位十六进制是本阶段预算下的宽度上限；码值取到 `0xF` 为止，新增码超过它时必须连同输出程序一起改。码值与登记编号同号，含义见[一级引导契约](一级引导契约.md)第六节。

| 编号 | 输出 | 含义 |
| --- | --- | --- |
| `E-IPL-01` | `1` | 描述符所在扇区读取失败（HDD） |
| `E-IPL-02` | `2` | 驱动器或介质不受支持：驱动器号不是硬盘、AH=48 返回短表、报告的扇区大小不是 512 / 4096 |
| `E-IPL-03` | `3` | 描述符头部或段序列非法：本区起始位置与槽不符、段头越过本扇区缓冲、段长小于段头、Stub 段长容不下起止位置、魔数不符 |
| `E-IPL-04` | `4` | Stub 段起止位置非法：起点不晚于描述符扇区、结束位置加一产生 32 位进位、起止倒置或扇区数为零 |
| `E-IPL-05` | `5` | 光盘候选驱动器探测未取得可读且魔数正确的描述符 |
| `E-IPL-06` | `6` | Stub 扇区数超过装载窗口上限 |
| `E-IPL-07` | `7` | 描述符通过后 Stub 读盘最终失败 |

## 四、E-UEFI：UEFI 侧

UEFI 侧的固件应用与 BaleenCore 是同一批检查的两种载体，因此沿用**同号异前缀**：同一含义的检查在两侧用同一个序号，只换阶段前缀（布局描述、系统卷与选版那几批就是共用实现，两侧各编一份）。**UEFI 侧不链接 `ImageHeader`，编号 40..51 不由 UEFI 产生**——镜像头字段校验只发生在 Stub 与 BaleenCore 自身（`E-STUB-40..51` / `E-CORE-40..51`）。两侧的**文本通常共用一份**：共用实现里的同一处常量同时服务两个阶段，前缀由编译选项 `BALEEN_STAGE_PREFIX` 给出（`Packages/Baleen/Common/Include/Diagnostics.hpp`），因此改文本只需要改一处、改前缀不会漏；**阶段名写进句子的编号**（如 `E-CORE-58` / `E-UEFI-58`）在各自阶段单独成句。

**`E-UEFI-40`..`E-UEFI-51` 不再出现。** UEFI 侧不链接 `ImageHeader`，镜像头字段校验只由 Stub 与 BaleenCore 产生（`E-STUB-40..51` / `E-CORE-40..51`）；把 `ImageHeader` 链进 UEFI 只会让已不产生的编号留在二进制里。

**`E-UEFI-52` 不由 UEFI 侧产生。** UEFI 阶段无法在装载之前判定内核的固定装载跨度是否整段可用：退出启动服务之前拿到的是“当前归属”视图，启动服务内存与引导器内存还归固件，按它判定会误拒合法跨度；跨度归属要等 `ExitBootServices` 之后按最终内存图快照才作数。因此装载前只核对与引导器映像的重叠（`E-UEFI-91`），退出后核整段归系统并拷入（`E-UEFI-88`）；`E-CORE-52` 的判据在 UEFI 侧落到 `E-UEFI-88`，`E-UEFI-53` / `E-UEFI-54` 照常产生。`E-UEFI-52` 保留不产生，理由与 `40..51` 相同。

**UEFI 侧独有的编号**：BaleenCore 没有对应检查（例如整盘视图要沿设备路径上溯、退出启动服务要用固件的内存图键），不参与同号异前缀。

## 六、维护规则

1. **首次发布之前不背兼容包袱**：编号直接改写、删除或重排，本文不留已废弃行。**首次发布之后编号只增不改**：含义变化时分配新编号，旧编号不再复用；删除的编号标记为已废弃，不回收。
2. 每条 `Baleen::Diagnostic` 常量都必须在本文登记；新增时同时改源码与本文。
3. 诊断行同时输出编号与文本；自动化按编号聚合，人按文本定位，两者都不作为唯一依据。
4. 存储层错误名（`Storage::ErrorMessage`）作为补充现场附在编号行末尾的括号里，不属于编号体系。
