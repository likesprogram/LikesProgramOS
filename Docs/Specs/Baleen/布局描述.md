# BaleenLayout — 布局描述

**布局描述是引导介质上的一份固定结构**，由镜像组装器写入约定位置，由 BaleenCore 与 UEFI 侧读取，不执行。它回答四个问题：卷标识是什么、系统卷在介质上的哪一段、内核镜像在卷内的哪条路径、引导状态区域在哪里。

本文定义 `BaleenLayout.bin` 的字节表、写入位置与校验规则。卷内布局的语义见 [Baleen 引导器](README.md)第五节；介质与分区关系见[启动介质与文件系统](../Common/启动介质与文件系统.md) 4.2；引导状态的记录语义见[内核集更新与回滚](../内核集更新与回滚.md)。

## 一、写入位置与形态

| 项 | 约定 |
| --- | --- |
| 位置 | 介质字节偏移 `0x20000`（512 字节基准 `256`） |
| 形态 | 占一个 4096 字节块：有效内容在前，其余保留写 0 |
| 单位无关 | `0x20000` 是 4096 的整数倍，512 / 2048 / 4096 三种逻辑扇区下都能整扇区读取，读取方按 `0x20000 / 本地扇区大小` 得到本地 LBA |
| 与分区无关 | 位于引导区，任何分区不得覆盖它；分区表形态（MBR / GPT）不改变本位置 |
| 内容源 | 骨架（内核路径）可来自模板；位置类字段由组装器回填，见第五节 |

引导区的完整布局：

| 字节偏移 | 内容 | 说明 |
| --- | --- | --- |
| `0x20000` | 布局描述（本文） | 占一个 4096 字节块 |
| `0x21000` | 引导状态区域 | 占一个 4096 字节块，供引导选择器持久化状态；只读介质上不使用，见第四节 |
| `0x22000` | 描述符区 | 头部与段序列，见[一级引导契约](一级引导契约.md)；占一个本地扇区 |
| `0x23000` 起 | 引导载荷 | Stub 与 BaleenCore，4096 对齐连续存放 |

## 二、字节表

所有整数小端序，不允许编译器填充；偏移相对布局描述起点。保留字段必须写 0，读取方遇到非 0 保留字段按格式不符拒绝，不猜测语义。

| 偏移 | 字节数 | 字段 | 当前语义 | 填出方 |
| --- | --- | --- | --- | --- |
| `0x000` | 4 | `Magic` | 字节 `42 4C 41 59`，即 `BLAY` | 模板或生成器 |
| `0x004` | 2 | `Version` | 当前值 `1` | 模板或生成器 |
| `0x006` | 2 | `HeaderBytes` | `0x40`，头部固定长度 | 模板或生成器 |
| `0x008` | 4 | `LayoutBytes` | 本结构有效字节数，当前 `0x144` | 模板或生成器 |
| `0x00C` | 4 | `Flags` | 位 0 已定义（`kFlagDegradeWithoutRecord`，见下）；其余位必须为 0，出现未定义位即拒绝 | 模板或生成器 |

**标志位当前只定义位 0：`kFlagDegradeWithoutRecord`（记录损坏时退到缺省集）。** 不置位（默认）时，引导状态记录有写入痕迹但全部槽位都不可验证就停机等人工处理（`E-CORE-69` / `E-UEFI-69`），不猜测目标集；置位时改为按本描述指定的缺省集启动，并报 `E-CORE-56` / `E-UEFI-56`。那条路要付出两样东西：设备已见最高安全版本与记录里的吊销并集都随记录一起丢了，防回滚只剩内嵌下限与系统卷里的签名吊销记录——**可用性换一档防回滚强度，因此由介质侧显式声明，出厂默认不换**。未定义的位一律为 0，出现未定义的位即拒绝（`E-CORE-22` / `E-UEFI-22`）。组装侧由 `TestInstaller` / `MakeImage` 的 `--degrade-without-record` 置位。
| `0x010` | 16 | `VolumeUuid` | 系统卷的卷标识：Ext4 superblock 的 `s_uuid`，按原字节比较 | 组装器回填 |
| `0x020` | 8 | `VolumeOffset` | 系统卷在介质上的起始字节偏移 | 组装器回填 |
| `0x028` | 8 | `VolumeBytes` | 系统卷长度，字节；非 0 | 组装器回填 |
| `0x030` | 8 | `StateOffset` | 引导状态区域起始字节偏移；`0` 表示无状态区域 | 组装器回填 |
| `0x038` | 4 | `StateBytes` | 引导状态区域长度，字节；`StateOffset` 为 0 时忽略 | 组装器回填 |
| `0x03C` | 2 | `KernelPathBytes` | 内核路径的字节数，取值 `1..255` | 模板或生成器 |
| `0x03E` | 2 | `Reserved` | 全 0 | — |
| `0x040` | 256 | `KernelPath` | 内核镜像在系统卷内的绝对路径，非 ASCII 字节按原字节使用，不以 0 结尾；长度由 `KernelPathBytes` 给出 | 模板或生成器 |
| `0x140` | 4 | `Checksum` | 覆盖 `[0x000, 0x140)` 的 32 位累加和：逐字节按无符号相加，取低 32 位 | 组装器回填 |
| `0x144` | `4096-0x144` | `Reserved` | 全 0 | — |

**系统卷位置是介质上的字节偏移，不是分区号。** 磁盘形态下它是系统卷分区内的卷起点，ISO 形态下它是 ISO9660 卷内那个镜像文件的连续区段起点；两种形态对读取方是同一条路径——在介质设备上开一个偏移视图，直接挂 Ext4。镜像组装器保证这个区段连续（单区段实现），读取方按卷标识核对身份，见第六节。

**内核路径是卷内的一条绝对路径**，语法按[文件系统抽象与 VFS](../Common/文件系统抽象与VFS.md) 3.5 的统一路径：以 `/` 起头，分量非空、不含 `.` 与 `..`。读取方在布局校验阶段就核对这条语法，不符合即以 `E-CORE-93` / `E-UEFI-93` 拒绝；路径不得依赖符号链接（组装器保证，见 [Baleen 引导器](README.md)第五节）。**选版启用后，它必须指向缺省集目录里、清单登记的 `.os` 条目**，形态为 `<集根>/KernelSets/<64 位小写十六进制 BuildId>/<相对产物路径>`；旧扁平落点与其它形态在选版阶段被拒绝（`E-CORE-84` / `E-UEFI-84`），相对产物路径与清单登记的 `.os` 条目不相等同样拒绝（`E-CORE-85` / `E-UEFI-85`）。

## 三、校验与读取顺序

读取方（BaleenCore / UEFI）按以下顺序处理，任一不通过都报告原因并停止，不猜测：

1. 读 `0x20000` 所在的一个本地扇区（4096 字节块已完整覆盖），核对 `Magic`、`Version`、`HeaderBytes`、`LayoutBytes`、`Flags` 与头部保留字段；`Flags` 只允许已定义的位 0，出现未定义位以 `E-CORE-22` / `E-UEFI-22` 拒绝，头部保留字段非 0 以 `E-CORE-23` / `E-UEFI-23` 拒绝；
2. 计算 `[0x000, 0x140)` 的累加和与 `Checksum` 比对，并核对尾部保留区 `[0x144, 0x1000)` 全 0（否则说明写入方越界或介质上有非预期内容，以 `E-CORE-23` / `E-UEFI-23` 拒绝）；`Checksum` 只用于检测写损与非预期字节变化，不构成认证，也不能代替内核集签名；
3. 校验 `KernelPathBytes` 与路径语法：长度取值 `1..255`（否则 `E-CORE-25` / `E-UEFI-25`），必须以 `/` 起头（否则 `E-CORE-26` / `E-UEFI-26`），并按统一路径语法校验分量非空、不含 `.` 与 `..`（否则 `E-CORE-93` / `E-UEFI-93`）；
4. 用 `VolumeOffset` / `VolumeBytes` 在介质设备上开偏移视图，挂 Ext4，把 superblock 的 `s_uuid` 与 `VolumeUuid` 按原字节比较；不一致说明介质与布局描述不是同一次组装，停止；
5. 把 `KernelPath` 交给内核集校验与选版流程（见 [Baleen 引导器](README.md)第五节、[内核集更新与回滚](../内核集更新与回滚.md)）：选择器按 `<集根>/KernelSets/<BuildId>/<相对产物路径>` 形态拆出缺省集并验证其清单，装载路径取自验证通过的清单 `.os` 条目；路径不是这一形态（含旧扁平落点）以 `E-CORE-84` / `E-UEFI-84` 拒绝，相对产物路径与清单条目不相等以 `E-CORE-85` / `E-UEFI-85` 拒绝；
6. 读到步骤 5 之前不写任何引导状态；状态区域的可用性判断见第四节。

读取方不得从分区表推导系统卷位置，也不得在布局描述校验失败后回退到固定偏移猜测。

## 四、引导状态区域

`StateOffset` / `StateBytes` 声明一段裸块区域，供引导选择器按[内核集更新与回滚](../内核集更新与回滚.md)的语义持久化 Pending / Trying / Confirmed / Failed 状态。默认位置 `0x21000`、长度 4096 字节。

- **记录格式在[引导状态记录](引导状态记录.md)里定义**：冗余槽位布局、代次、校验、写入顺序与掉电语义属于那份规格；本文只固定区域的位置与长度，使同一份镜像在写入前就确定好的字节位置。
- **状态区域起点按 4096 字节对齐**：`StateOffset` 须是 4096 的整数倍（默认 `0x21000` 满足），`StateBytes` 至少 4096 字节；这样在 512 / 1024 / 2048 / 4096 字节逻辑块下，区域起点与 4096 字节长度都满足块设备的对齐契约、能够整块读写，4Kn 上区域恰好一个逻辑块。
- **只读介质上不启用**：光盘等不可写介质上，引导选择器不写状态、按直接启动指定镜像处理；试启动要求介质可写且写入可持久化（见[内核集更新与回滚](../内核集更新与回滚.md)）。
- **写入范围限于本区域**：引导期对介质的写操作只允许落在状态区域内，系统卷只读（见 [Baleen 引导器](README.md)第五节）。

## 五、生成与回填

布局描述有两个来源，职责分列：

| 来源 | 提供 | 说明 |
| --- | --- | --- |
| 模板 | 头部固定字段、`KernelPath` | 内核路径取决于系统卷内容布局，随内核构建确定；模板由系统本体构建产出，或由组装器按参数取默认值 |
| 组装器 | `VolumeUuid`、`VolumeOffset`、`VolumeBytes`、`StateOffset`、`StateBytes`、`Checksum` | 这些只有组装器知道：卷在介质上的落点、卷镜像的标识、状态区域的实际位置 |

组装器流程：

1. 读系统卷镜像的 superblock（字节偏移 `1024`），核对魔数 `0xEF53`，取 `s_uuid`；
2. 按布局得到系统卷在介质上的偏移与长度；
3. 填位置类字段与 `Checksum`，生成完整 4096 字节块；生成前按与读取方同一套判据自检：`Flags` 只允许已定义位、尾部 `[0x144, 0x1000)` 全 0、`KernelPath` 符合统一路径语法；模板或参数带未定义位、非 0 尾部或非法路径时拒绝产出（编号与读取方共用 `E-CORE-22` / `E-CORE-23` / `E-CORE-25` / `E-CORE-26` / `E-CORE-93`）；
4. 写到 `0x20000`，并把 `[0x20000, 0x22000)`（布局描述与状态区域）登记为已占用，避免与其它载荷重叠；
5. 在构建输出与清单里记录布局描述的实际内容（卷标识、卷偏移与长度、状态区域、内核路径），供核对。

**模板尾部必须显式清零**：`[0x144, 0x1000)` 是保留区，模板或组装参数留下的任何非 0 字节都会让读取方按 `E-CORE-23` / `E-UEFI-23` 拒绝。**未定义 `Flags` 位与非法 `KernelPath` 同样在生成期就拒绝**（`E-CORE-22` / `E-CORE-93` 对应同义判据），不把“等设备上读取时才发现”当成正常路径。

**默认内核路径**：必须形如 `<集根>/KernelSets/<BuildId>/<清单 .os 条目相对路径>`（例如 `/LikesProgram/System/KernelSets/<BuildId>/LikesProgram.os`，产物在子目录时末段随清单条目），集名由 `BuildId` 决定、无法预先写死，因此当前构建由系统卷包把实际集路径写进 `Out/KernelPath`、顶层组装器传给 MakeImage / TestInstaller。旧的扁平模板默认值（`/LikesProgram/System/LikesProgram.os`）不再可用：它推不出集目录形态，选择器直接拒绝（`E-CORE-84` / `E-UEFI-84`）。布局的 `Checksum` 只检测写损、不是认证；路径形态校验与清单验签都在选版阶段完成，改布局描述不能跳过清单验签（见[内核集清单与签名](../内核集清单与签名.md)第三节、5.2 与[系统卷布局](../Common/系统卷布局.md) 3.2）。

## 六、与其它规格的关系

- [Baleen 引导器](README.md)：第八节的产物表把本结构列为 `BaleenLayout.bin`，由 Core / UEFI 读取；第五节定义卷定位与内核路径的语义，本文给出这些事实的字节形态。
- [一级引导契约](一级引导契约.md)：描述符区与本文是两套结构，位置相邻但格式无关；IPL 与 Stub 不读布局描述。
- [启动介质与文件系统](../Common/启动介质与文件系统.md)：系统卷在磁盘与 ISO 上的两种形态，本文的 `VolumeOffset` / `VolumeBytes` 对两者统一。
- [内核集更新与回滚](../内核集更新与回滚.md)：引导状态区域承载它的状态记录；记录格式见[引导状态记录](引导状态记录.md)。
- [引导状态记录](引导状态记录.md)：状态区域的槽位布局、记录字节表与读写顺序；本文只固定区域的位置与长度。
- [内核集清单与签名](../内核集清单与签名.md)：内核集清单与签名的字节形态；本结构的 `KernelPath` 指向缺省集目录里清单登记的 `.os` 条目，选择器据此定位缺省集并核对装载路径。
- [内核镜像数据](内核镜像数据.md)：`KernelPath` 指向的文件起点那份数据的字节表与校验；本结构定位卷与路径，那份数据描述文件自身。
- [文件系统抽象与 VFS](../Common/文件系统抽象与VFS.md)：`KernelPath` 的路径语法与统一路径一致；偏移视图（`SubDevice`）是读取系统卷的机制。
