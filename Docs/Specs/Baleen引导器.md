# Baleen 引导器

**Baleen 是 LikesProgramOS 的自家引导器子项目**，源码位于 `Packages/Baleen`，与系统本体 `LikesProgramOS` 平级。

它的职责只有一件事：**从不同硬件上找到指定 Ext4 文件系统的指定路径，把系统内核装载起来并完成交接。**

## 一、名字与命名口径

**Baleen 取自鲸须**：须鲸用鲸须从大量海水与浮游生物中筛出需要的食物，正如引导器要从多种固件、控制器、总线和介质中筛出唯一的目标卷，并从中取走指定的内核镜像。

**为什么不用 BootLoader 当名字**：那是这个组件的功能描述，不是名字。功能描述会在讨论、产物命名和诊断信息里反复出现——“BootLoader 加载失败”说不清是引导器的哪一段失败。项目内统一用 Baleen 指代这套引导链，产物名加 `Baleen` 前缀。

| 用在哪 | 怎么写 |
| --- | --- |
| 子项目、文档、讨论 | Baleen |
| 产物名 | `BaleenIPL.bin`、`BaleenStub.bin`、`BaleenCore.bin`、`BaleenLayout.bin`（见第八节） |
| 固件要求的固定名 | `BOOTX64.EFI` 等按协议保留，不套用本项目命名（见[后缀设计](后缀设计.md)第六节） |

与其他生态重名时按[后缀设计](后缀设计.md)第八节的口径处理：同名不构成关系，也不承诺互通。

## 二、职责边界

| Baleen 做 | Baleen 不做 |
| --- | --- |
| 在固件环境下枚举控制器、总线和设备，确定可引导介质 | 不加载 `.osm`、`.drv`、`.exe`；这些是内核装载器的职责 |
| 识别介质形态与分区布局，定位候选系统卷 | 不做通用文件系统操作：Ext4 读取仅为定位内核镜像服务，见第五节 |
| 校验卷身份（标识、布局描述、版本） | 不解析构建清单之外的容器内部结构 |
| 在系统卷的指定路径读取内核镜像与所需清单 | 不为第三方引导协议做适配，见[内核启动与固件边界](内核启动与固件边界.md) |
| 按引导模式准备机器状态、装载镜像、交付 `BootInfo` | 不建立运行时设备模型；设备模型属于内核 |
| 引导选择器职责：选版、持久记录试启动状态、失败回退 | 不做运行期更新编排；那是 Updater 的职责 |

**引导器与内核各自持有文件系统代码，这不是“两套实现”。** [内核架构与自举闭包](内核架构与自举闭包.md)禁止的是同一内核模块或驱动维护“引导简版 / 运行期完整版”，因为它们在同一个地址空间、同一套资源记录里工作。Baleen 独立运行在固件环境，与内核不共享地址空间，它的 Ext4 读取是为装载镜像服务的最小只读实现，内核的 Ext4 是含日志回放与写入的完整实现。两者不需要共享代码，但**可识别的卷格式范围必须一致**：镜像组装器为一套布局生成两边的访问路径，引导器读不了的卷，内核也不该被要求读出内容。

## 三、引导模式

引导模式分三层理解：**固件环境**决定 Baleen 以什么形态运行，**交权入口**决定内核以什么机器状态接手，**验证链**决定镜像要不要签名。本项目按支持梯队排序。本节引用的技术事实来源见[参考资料](../参考资料.md)的「固件与引导」「安全引导」两节。

### 3.1 固件环境

| 梯队 | 环境 | 说明 |
| --- | --- | --- |
| 必须支持 | **Legacy BIOS / CSM** | 16 位实模式起步，用 BIOS 磁盘与显示服务完成介质访问；光盘走 El Torito 引导目录 |
| 必须支持 | **UEFI x64** | 以 PE/COFF 固件应用形态运行，使用 Boot Services 的块设备与文件系统协议；包含无 CSM 的纯 UEFI 机器（通称 UEFI Class 3） |
| 计划支持 | **coreboot** | 开源固件平台，以 SELF 机制装载 payload：SeaBIOS payload 提供 BIOS 环境，edk2 payload 提供 UEFI 环境，Baleen 以对应形态接入 |
| 计划支持 | **coreboot 发行版** | 在 coreboot 之上打包好 UEFI、SeaBIOS 或 LinuxBoot 环境的发行版（如 Dasharo）；Baleen 按其中实际提供的环境接入 |
| 计划支持 | **虚拟化直启（PVH）** | 由 Xen 引入，被 QEMU、Cloud Hypervisor、Firecracker 等采用的入口约定：内核以 ELF note 声明 32 位保护模式入口，不使用固件服务。见 3.2 |
| 记录在案 | **LinuxBoot** | 用 Linux 内核与 u-root initramfs 取代固件中大部分驱动与阶段，再由 kexec 载入目标内核；Baleen 的接入方式是作为其载入对象 |
| 记录在案 | **Slim Bootloader** | Intel 维护的开源固件，覆盖其多个客户端与嵌入式平台；是否作为接入目标待评估 |
| 记录在案 | **U-Boot** | 主要面向嵌入式平台，coreboot 也可把它当作 payload；本项目不将它列为 PC 首要目标 |
| 记录在案 | **网络引导（PXE / HTTP Boot）** | UEFI 规范包含网络引导路径，可经网络取得引导镜像；本项目列入后续扩展，不在首批交付 |

**这张表不承诺“固件名字相同就一定能启动”。** 同一固件在不同机器上开放的协议与服务可能不同，Baleen 按实际可用的接口探测，探测不到就报告，不猜测。

### 3.2 交权入口

| 入口 | 进入内核时的状态 | 谁的机器状态准备 |
| --- | --- | --- |
| BIOS 路径 | 从实模式起步，由 Baleen 建立 A20、内存图、页表与长模式 | Baleen 自建 |
| UEFI 路径 | Baleen 作为固件应用运行，在交权前退出 Boot Services；内核在 `KernelMain` 第一步核对并确认固件启动服务已失效 | Baleen 准备，内核确认 |
| PVH 直启 | 内核以 ELF note（`XEN_ELFNOTE_PHYS32_ENTRY`）声明 32 位保护模式入口，进入时分页关闭，无固件服务可依赖 | Baleen 或虚拟机监视器按约定准备 |

**无论走哪条入口，内核看到的都是同一份 `BootInfo`。** 交权状态必须显式传递：UEFI 的 Boot Services 仍有效时，Baleen 在准备完成并取得有效内存图后调用 `ExitBootServices`；若已退出，不得重复调用，由 `BootInfo` 标记状态。BIOS 交权后不再调用 BIOS 服务。完整边界见[内核启动与固件边界](内核启动与固件边界.md)。

### 3.3 验证链

| 机制 | 作用层级 | Baleen 的应对 |
| --- | --- | --- |
| **UEFI Secure Boot** | 固件验证引导程序镜像 | 提供可签名的 PE/COFF 形态；未签名或签名不受信任时固件不会执行它，这与本项目无关 |
| **Measured Boot（TPM）** | 固件与引导器把度量值记录进 PCR | 镜像与布局描述保持可度量、可复现：同一构建产出同样的字节 |
| **Intel Boot Guard / AMD 平台安全处理器** | 验证固件自身 | 在 Baleen 之下，不属于本项目可控范围 |
| **本项目签名与信任锚** | 验证内核集与构建清单 | 由引导选择器在装载前检查，见[内核集更新与回滚](内核集更新与回滚.md) |

Secure Boot 与项目自身的签名是两条独立的链：前者让固件愿意执行 Baleen，后者让 Baleen 愿意装载内核集。两者不能互相替代。

## 四、硬件与介质支持范围

| 介质 | 引导期访问方式 | Baleen 看到的卷 |
| --- | --- | --- |
| 内部硬盘（SATA / NVMe / 老 IDE） | 优先走固件的磁盘服务或块协议；固件覆盖不到该控制器时走 Baleen 的最小控制器路径 | 分区上的 Ext4 卷 |
| U 盘、移动硬盘、外置 SSD | **只用固件提供的 USB 引导能力** | 分区上的 Ext4 卷，或混合镜像上的 ISO9660 卷 |
| ISO 镜像（写入 U 盘 / 移动硬盘、虚拟机挂载、物理光驱） | 固件的光盘访问路径，或按 U 盘方式引导 | ISO9660 卷，系统卷为其内部文件 |

**引导期的介质访问优先走固件能力。** BIOS 把可引导设备作为驱动器号暴露，UEFI 通过块设备协议暴露；能走固件就走固件，这是 Baleen 保持小体积的前提。

**Baleen 自建访问路径只有一个适用场合**：固件的磁盘服务覆盖不到目标控制器（例如 UEFI 下固件没有为该 NVMe 或 AHCI 控制器提供块协议）。此时 Baleen 按自己的最小控制器访问路径读取目标卷，这条路径只服务引导，不建立内核那样的设备模型。

**USB 不在此列。** 固件不提供 USB 引导支持的机器上，从 USB 介质启动不在支持范围；Baleen 不自带 USB 栈。内核的 USB 栈是运行期实现，此刻还没有运行，也不能被引导器依赖。

**ISO 是分发形态，不是物理设备。** 写入 U 盘或移动硬盘的镜像要在同一份字节上同时满足光盘与磁盘两种引导记录要求；虚拟机选择 ISO 文件时按虚拟光驱引导。三种方式在内核侧是同一条路径，见[启动介质与文件系统](启动介质与文件系统.md)第二节。

## 五、卷定位与内核路径

**目标是一个卷加一条路径，不是一个固定块偏移。** Baleen 按以下顺序工作：

1. **拿到候选设备**：由固件枚举或自行探测得到可引导设备列表。
2. **读布局描述**：在约定位置找到 `BaleenLayout.bin`，取得卷标识、系统卷位置、内核路径、引导状态区域及格式版本。布局描述不固定占用整盘 LBA1，不覆盖分区表或固件要求的区域。
3. **校验卷身份**：读 Ext4 superblock，核对卷标识与布局描述一致；不一致就换下一个候选设备，不猜测。
4. **按路径读内核**：逐级解析目录项与 inode，按 extent 读取内核镜像文件；路径与文件名由布局描述给定。
5. **校验后装载**：核对摘要与签名，按引导模式把镜像放到约定位置并准备机器状态。

**Ext4 读取是最小只读实现**，边界明确：

| 项 | 约定 |
| --- | --- |
| 能力 | 识别 superblock 与特性标志、读块组描述符与 inode、走 extent 树、解析目录项、读常规文件 |
| 不支持 | 不支持的特性标志（未知 `INCOMPAT` 位）、加密、内联数据等；遇到就明确拒绝并报告 |
| 符号链接 | 布局描述给出的路径不得依赖符号链接；镜像组装器保证这一点 |
| 写入 | **绝不写系统卷**。Baleen 对系统卷只有读操作，写操作仅针对引导状态区的裸块记录 |
| 布局约束 | 镜像组装器保证系统卷布局落在支持范围内；不支持的布局在构建或装载时明确拒绝，不做兼容性猜测 |

**卷定位失败的处理**：线索不足时继续在受支持设备中查找并验证，无法唯一定位就报告失败，不能猜测磁盘。这条约束同样适用于内核：内核拿到 `BootInfo` 里的设备线索后自己再校验一次卷标识和布局信息。

## 六、装载与交接

Baleen 交付给内核的内容：

| 项 | 内容 |
| --- | --- |
| 机器状态 | 引导模式要求的寄存器、栈、页表与长模式状态；进入内核后不得依赖任何固件服务 |
| 内核镜像形态 | Baleen 契约定义的镜像头与入口点；装载前校验摘要与签名。内核镜像不带固件可直接识别的标准头，固件接触的是 Baleen 自己 |
| `BootInfo` | 尺寸与版本、内存图、启动设备线索、系统卷标识、CPU/固件信息、可用输出通道、资源所有权，以及可选的内核集与试启动身份 |
| 所有权信息 | 哪些内存与固件资源已由 Baleen 占用、哪些交给内核接管，避免内核把引导器的残留当成可用资源 |
| 失败报告通路 | 交权前后各自的错误输出方式，保证“引导器失败”和“内核失败”可区分 |

`BootInfo` 的字段定义、版本规则与生成工具由 HostSDK 提供；内核侧只核对尺寸与版本，见[内核启动与固件边界](内核启动与固件边界.md)。**第三方引导方式要用自己的实现构造同一份 `BootInfo`**，本项目不为它们提供适配层。

## 七、引导选择器与状态持久化

自动回滚模式下，Baleen 承担引导选择器职责。完整的 Pending / Trying / Confirmed / Failed 语义见[内核集更新与回滚](内核集更新与回滚.md)，引导期的动作是：

1. 读引导状态记录，结合冗余副本选出最新完整有效的一份。
2. 无待试候选时选择已知良好集；有 `Pending` 候选时校验其完整性与签名，把选中的候选身份写入并持久化 `Trying`，再装载。
3. 记录已为 `Trying` 时，判定上次未确认，记录失败并改选原良好集。
4. 全部记录都无法验证时不猜测目标集，进入受控恢复或停止。

**运行期确认写入与引导期选择必须使用同一状态存储后端和记录格式。** 只有该后端能在内核交权前可靠写入并持久化时，才启用试启动；否则只能直接启动指定的已确认镜像，不能宣称支持自动回滚。

## 八、产物与验证

| 组件 | 输出名称 | 被谁载入 | 用途 |
| --- | --- | --- | --- |
| 一级引导 | `BaleenIPL.bin` | BIOS / El Torito 引导目录 | 校验布局描述，装入实模式服务层，传出驱动器号与介质类型 |
| 实模式服务层 | `BaleenStub.bin` | 一级引导 | A20、内存图、固件磁盘会话；装载核心阶段 |
| 核心阶段（BIOS 侧） | `BaleenCore.bin` | 实模式服务层 | 引导选择器：验证布局与选择记录，持久记录试启动，按 Ext4 路径读入所选 `.os`，交付 `BootInfo` |
| 固件应用（UEFI 侧） | `BOOTX64.EFI` | UEFI 引导管理器，`\EFI\BOOT\` | UEFI 侧引导选择器与装载器：经固件接口完成选版与状态持久化，传递内存图、输出信息及 Boot Services 状态 |
| 布局描述 | `BaleenLayout.bin` | 不执行，构建期写入布局指定位置 | 卷标识、系统卷位置、内核路径、引导状态区域及格式版本 |

`BOOTX64.EFI` 的名字由 UEFI 可移动介质引导路径要求决定，不是本项目选的，见[后缀设计](后缀设计.md)第六节；镜像放在固有其他路径时可以改用启动项指向的名字，但可移动介质回退路径必须是它。布局描述按介质形态分别生成内容，字段与写入位置见后续的详细规格。

**验证范围**：构建期脚本要覆盖介质与入口的启动矩阵——BIOS 与 UEFI 各入口、内部硬盘、U 盘、移动硬盘、ISO 写入 U 盘与虚拟机挂载 ISO，以及各组合下的卷定位、镜像校验与失败报告；掉电回滚演练见[内核集更新与回滚](内核集更新与回滚.md)。
