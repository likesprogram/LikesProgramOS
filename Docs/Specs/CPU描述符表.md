# CPU 描述符表

本文定义 GDT 与 IDT 的装载机制、Baleen 与内核在这件事上的分工，以及两种运行模式的字节布局差异。段选择子布局、权限级、TSS 与处理器入口属于使用方策略，不在本文统一。

**一句话口径：本机制只做表项编码、表存储与 `lgdt`/`lidt`/段重载，不决定表里放什么；Baleen 与内核各持自己的表实例，差异落在填表内容上，机制共用。**

本文定义接口、边界与使用方式；Core 与内核尚未使用该机制。

## 一、分层与职责

| 层 | 职责 | 不承担 |
| --- | --- | --- |
| 机制（`Platform::Gdt` / `Platform::Idt`） | 按 SDM 布局编码表项、持有表存储、装载表寄存器、按当前模式重载段寄存器 | 不选描述符集与选择子编号、不设 DPL、不建 TSS 结构、不生成任何处理器入口、不切换运行模式 |
| 使用方策略 | 决定表里有哪些段与门、选择子如何编号、TSS 与 IST 如何填、处理器入口指向哪里、失败时如何处理 | 不自己拼表项字节、不自己写 `lgdt`/`lidt` 与段重载 |
| 处理器入口代码 | 异常与中断的入口、寄存器保存与返回 | 不在本机制内生成；内核的异常与 IRQ 框架、Baleen 的停机诊断各自在自己的汇编里定义 |

**为什么机制与策略要分开**：段编号、DPL、TSS 与入口地址随阶段而变——Baleen 只需要平坦段和少量诊断入口，内核需要内核/用户段、TSS 与 IST、以及覆盖全部向量的异常与中断入口。共用一份"策略"会强迫两边接受对方的表，共用"机制"则两边都少写一遍容易错的字节编码与段重载。

**为什么内核不能直接复用 `Platform::Cpu`**：`CPU 事实探测`的实现在 32 位形式下（EFLAGS、SGDT、固定地址测试）编译期拒绝 64 位目标，而描述符表机制必须按长模式编译一份。因此两张表放在 `Packages/Common` 的独立文件里，与 `Cpu` 同包不同文件。

## 二、机制范围

声明与实现分列：`Packages/Common/Include/Platform/Descriptor.hpp` 放声明与表存储，`Packages/Common/Src/Platform/Descriptor.cpp` 放表项编码，`Packages/Common/Src/Platform/Descriptor.asm` 放纯汇编原语；Cpu 一侧对应 `Cpu.hpp`、`Cpu.cpp` 与 `Cpu.asm`。

| 接口 | 语义 |
| --- | --- |
| `Gdt::Clear()` | 清空全部槽位，得到一个只有空描述符的表 |
| `Gdt::SetCode(index, dpl, width)` | 写平坦代码段：基址 0、可执行可读、向上扩展；宽度取 16 位、32 位或长模式 64 位 |
| `Gdt::SetData(index, dpl, width)` | 写平坦数据段：基址 0、可写、向上扩展；宽度取 16 位或 32 位 |
| `Gdt::SetTss(index, base, limit)` | 写可用 TSS 描述符；长模式下占两个相邻槽位 |
| `Gdt::Load(codeSelector, dataSelector)` | 装载 GDTR，重载数据段寄存器，并用远返回把 CS 换到目标选择子 |
| `Idt::Clear()` / `Idt::SetGate(vector, handler, selector, type, dpl, ist)` | 清空门、写一个中断门或陷阱门 |
| `Idt::Load()` | 装载 IDTR；不改段寄存器，也不改中断标志 |
| `Gdt::Base()/Limit()`、`Idt::Base()/Limit()` | 表存储起始地址与限长，用于诊断输出和装载后回读核对 |
| `LoadTaskRegister(selector)` | 把 TSS 选择子装入任务寄存器（LTR）；内核的 IST 与特权级栈切换依赖它 |

**当前机制不覆盖的内容**：基址非零的段、LDT、调用门、任务门、16 位 TSS；描述符表的页表映射与每 CPU 副本的组织方式；模式提升与回退（实模式 → 保护模式 → 长模式）里的远跳转——按[一级引导契约](Baleen/一级引导契约.md)与 [Stub 约定与结构](../../Packages/Baleen/Stub/README.md)的分工，这些留在各阶段汇编入口，因为它们必须在 C++ 还不能运行时完成。

**表存储由使用方拥有**：`Gdt` 与 `Idt` 是普通对象，槽位固定、无动态分配、静态实例常量初始化，因此可以直接放在阶段二进制的静态存储里，也可以每 CPU 一个实例。IDT 的限长始终覆盖全部 256 个向量，未设置的门按"不存在"处理：触发时会走处理器的异常规则（可能升级为双重故障），所以使用方至少要装好自己需要的向量与基本异常向量。

**段表必须放在可写存储**：CPU 在加载段选择子时会置位描述符的 Accessed 位并写回内存。需要校验自身镜像摘要的阶段不能把段表放在被摘要覆盖的只读区——那里只留只读模板，运行时把副本拷进未初始化区再加载，写回就落在镜像之外，见 [Stub 约定与结构](../../Packages/Baleen/Stub/README.md) 第 3.4 节。

## 三、两种模式的字节差异

同一份源码按目标模式编译，各自得到正确的字节布局。差异集中在下面几处，都是容易写错又不易察觉的地方。

| 项 | 32 位保护模式 | IA-32e 长模式 |
| --- | --- | --- |
| 门描述符宽度 | 8 字节 | 16 字节 |
| 表寄存器操作数 | 16 位限长加 32 位基址，6 字节 | 16 位限长加 64 位基址，10 字节 |
| 门里的 IST 字段 | 没有；该参数必须为 0 | IST 1 至 7，0 表示不切换栈 |
| TSS 描述符 | 8 字节，占一个槽位 | 16 字节，占两个槽位，上位放基址 63:32 |
| CS 重载方式 | 远返回，弹回 32 位返回偏移与 16 位 CS | 远返回取 64 位操作数宽度；默认宽度是 32 位，用默认形式会弹错返回偏移 |
| 数据段重载 | DS、ES、SS、FS、GS 都必须拿到有效选择子 | 只重载 DS、ES、SS；FS、GS 的基址由内核按每 CPU 数据单独设置，重载选择子对内核没有用处 |
| 门类型值 | 中断门 `0xE`、陷阱门 `0xF` | 与 32 位相同，布局不同、类型值相同 |

**目标代码段必须与当前模式同宽。** `Gdt::Load` 是与当前模式同宽的原地重载，不承担模式切换：从 32 位切到长模式的远跳转、以及将来的回实模式路径，都由各阶段汇编在被测机制之外完成。

**纯汇编原语写在汇编文件里**，与它们的 C++ 调用方同名成对：`Packages/Common/Src/Platform/Descriptor.asm` 承担表寄存器装载与段寄存器重载，`Cpu.asm` 承担端口与寄存器读写。`Descriptor.asm` 的位宽随汇编目标选择（`-f elf32` 是 32 位保护模式，`-f elf64` 是长模式），出入口约定也随之变化：32 位是 cdecl 栈传参，64 位是 System V 寄存器传参。`Cpu.asm` 与 32 位专用的 `Cpu.cpp` 一样只有 32 位形式。**这两个文件是包的一部分：构建必须汇编它们，否则 `Cpu.cpp` 与 `Descriptor.cpp` 会因为缺少这些符号而链接失败。**

## 四、Baleen 与内核的分工

| 使用方 | 表实例与内容 | 处理器入口 | 装配 |
| --- | --- | --- | --- |
| Baleen 各阶段汇编入口 | 只够进入保护模式的固定表：空描述符、32 位代码段与 32 位数据段 | 无，此时还没有 IDT | 只读模板在汇编里，运行时拷进未初始化区再加载 |
| Baleen Stub（C++ 侧） | 独立静态实例：平坦 32 位段加 16 位段（回实模式路径用），选择子与引导表同号 | `Stub.asm` 的 32 个异常桩，统一进 `[ FATAL ] Exception` 诊断行后停机 | 运行期表在 `_Stub_Main` 里建立并装载 |
| Baleen Core（C++ 侧） | 独立静态实例：平坦 32 位代码段与数据段，选择子与交权表同号 | `Core.asm` 的 32 个异常桩，统一进 `[ FATAL ] Exception` 诊断行后停机 | 运行期表在 `_Core_Main` 里建立并装载 |
| 内核平台初始化 | 每 CPU 实例：内核与用户段、TSS 与 IST | 内核异常与 IRQ 框架的入口 | 按内核规格装配 |

**内核侧与 Baleen 侧的差别清单**（同一机制、不同策略）：段选择子编号与 DPL（内核还含 DPL 3 的用户段与用户可调用的门）、是否有 TSS 与 IST、门描述符宽度（内核按长模式编译）、是否每 CPU 一份表、入口代码指向谁的框架。这些差异都不需要改机制，只需要使用方填不同的表。

**Stub 如何使用这套机制**：IPL 把 Stub 文件读到 `0000:7E00` 后直接跳过去，交权时机器仍是 16 位实模式；提升到 32 位保护模式由 Stub 自己的入口汇编完成——它自带三条描述符的引导表（空、32 位代码、32 位数据，只读模板，运行时先拷进未初始化区再加载），只够完成这一步切换。随后 `_Stub_Main` 依次做控制台、CPU 探测、模式核对、A20，再用 `Platform::Gdt` 建立五条描述符的运行期段表（选择子与引导表同号，多出的两个 16 位段留给回实模式的 BIOS 路径），用 `Platform::Idt` 给 0 至 31 号向量装上 `Stub.asm` 里的异常桩。中断在入口处关闭并保持关闭，所以这些门只为 CPU 异常服务。**这一步的价值是把三重故障换成一行诊断**：装载运行期表之前，Stub 里的任何异常都是没有输出的复位。

## 五、硬规则

1. **装载前关中断。** `Gdt::Load` 会在重载段寄存器期间短暂处于"新表已装载、CS 还是旧段"的中间状态，此时到达的中断会按新表解释旧的入口地址。
2. **新表的段基址必须与当前一致。** 重载后指令流与栈继续按原来的线性地址执行；若新代码段或数据段的基址不同，`Load` 之后的取指与栈访问会落到别处。
3. **装载后回读核对。** `SGDT`/`SIDT`/`STR` 可以读回实际生效的表基址、限长与任务寄存器选择子，这是本项目验证采用的手段，也是各阶段自检可用的廉价检查。
4. **处理器入口由使用方提供。** 门里的地址必须是使用方自己的入口桩；机制不提供默认处理器，也不接管返回地址修正。fault 类异常压入的返回偏移指向出错指令本身（例如 `UD2`），入口桩要按异常类型决定是否修正。
5. **错误用返回值表示。** 槽位越界、DPL 大于 3、选择子为 0、向量越界、限长超出编码范围等都在调用时返回 false，不静默截断。
6. **实模式弹跳必须经 16 位代码段中转。** 装自带段表切 16 位代码段、在保护模式里清 CR0 的 PG 与 PE、再远跳进实模式；在 32 位模式下直接清 PE 再远跳，实模式的 INT 调用不会返回。

## 六、覆盖范围

机制的覆盖范围：

- 两种模式：32 位保护模式与长模式的段描述符、TSS 描述符与门描述符（各自的布局与宽度），表限长，选择子与向量的取值校验；非法取值、越界与 DPL 大于 3 一律返回 false，不静默截断。
- `Platform::Gdt` 与 `Platform::Idt` 的编码、装载与段重载以及 `LoadTaskRegister`。C++ 与汇编分成三份：`Cpu.hpp` / `Cpu.cpp` / `Cpu.asm` 与 `Descriptor.hpp` / `Descriptor.cpp` / `Descriptor.asm`，纯汇编原语只出现在 `.asm` 里；`.asm` 的位宽随汇编目标选择——32 位侧 `LGDT`/`LIDT` 取 6 字节操作数、CS 重载用 `RETF`，长模式侧分别取 10 字节操作数与 `RETFQ`。
- 构建与链接的约束：两种目标都用 `-ffreestanding -fno-exceptions -fno-rtti -Wall -Wextra -Werror` 编译，`.asm` 在 `-f elf32` 与 `-f elf64` 下都可汇编；链接结果不含未定义符号、`.init_array` 与运行库依赖。
- 装配约定：内联汇编统一使用大写助记符与寄存器名，NASM 指令与 `%` 预处理指令同样大写；GCC 的约束字母与 clobber 名不在此列（它们由编译器解析）。

不在本文范围：TSS 结构本身的定义与初始化、每 CPU 表的组织、用户段与系统调用门的策略、异常与 IRQ 入口框架。

- Baleen 交权时的机器状态与 A20 约定见[一级引导契约](Baleen/一级引导契约.md)与 [Stub 约定与结构](../../Packages/Baleen/Stub/README.md)；本文不改变交权 ABI，也不规定 Core 以什么模式进入内核。
- 引导期与内核期的文本诊断通道见[输出通道与Print](输出通道与Print.md)；本文的检查使用 0xE9 调试口与串口标记，与那份规格的通道定义一致。

## 八、外部依据

- [Intel SDM](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)：段描述符、门描述符、GDTR/IDTR 与 TSS 的字节布局；长模式 TSS 的字段偏移。
- [LGDT/LIDT](https://www.felixcloutier.com/x86/lgdt:lidt)：长模式下操作数固定为 16 位限长加 64 位基址，32 位与兼容模式使用 16 位限长加 32 位基址。
- [LTR](https://www.felixcloutier.com/x86/ltr)：操作数固定为 16 位，长模式下按 16 字节描述符取得 64 位基址；选择子不得为空且须指向可用的 TSS 描述符。
- [RET](https://www.felixcloutier.com/x86/ret)：远返回在长模式下的默认操作数宽度是 32 位，64 位形式依次弹回 RIP 与 CS。

指令参考条目用于核对字节与操作数宽度，不构成本项目在任何硬件或虚拟机上的验证结果。
