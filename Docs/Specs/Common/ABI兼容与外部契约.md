# ABI 兼容与外部契约

本文定义内核集内部与对外边界的兼容规则。内核集内部不承诺跨 `BuildId` 兼容，契约由同一份定义生成；面向外部作者的引导、驱动、应用与服务接口需要独立维护兼容性。

## 一、三类外部边界

- **引导交接契约**：引导器与内核之间的 `BootInfo` 与交权状态使用显式尺寸和版本，是内核唯一承诺的入口契约。它与第三方引导协议无关——第三方工具要用自己的方式启动本内核，需要自行实现转换层，见[内核启动与固件边界](../内核启动与固件边界.md)。
- **DriveSDK**：提供稳定调用表，驱动不包含内核私有头，也不直接绑定具体 `.osm` 的符号。模块提供实现不改变该外部边界。
- **AppSDK**：定义 syscall 和服务生命周期接口，权限由运行期能力检查决定。

## 二、追加是有条件的扩展方式

**追加是有条件的扩展方式，不是自动兼容保证：**

1. 可扩展结构和接口表携带尺寸、版本或能力信息。接收方只读取或写入双方约定且调用方实际提供的范围，缺失可选字段使用定义好的默认值。
2. 保持已有字段的偏移、类型、对齐和语义；不复用已有操作号、接口 ID 或错误码。新增必需字段、删除、改序或改变调用约定必须使用新接口版本。
3. 数组携带元素数量、容量和步长；按值传递、内嵌结构及固定布局不得仅靠尾部追加扩容，需要保留旧布局或提供新接口。
4. 跨边界的整数宽度、指针和地址语义、所有权、生命周期及调用约定必须明确，不依赖编译器私有 C++ 对象布局。契约头从唯一定义生成，不能复制出第二份定义。
5. ABI 基线检查布局、偏移、尺寸、调用表、ID 和版本协商规则；同时验证旧调用方与新实现、新调用方与旧实现的边界访问，不能只比较“是否追加”。
6. 更新发布前检查目标内核与已安装驱动、程序的接口需求。不兼容组件需捆绑升级或拒绝发布；启动必需组件还必须满足保留集的恢复要求，不能等重启后再碰运气。
7. **未发布的接口按设计调整处理。** 接口在首次发布之前处于设计阶段，字段可以在同一版本号内增删改、重排，不构成兼容性变更，不需要新接口版本；第 2 条与第 5 条的约束从首次发布起适用。

## 三、与其他约定绑定的部分

SDK 的交付形态（`.dso` / `.arc` 与契约头）见[后缀设计](../后缀设计.md) 5.13；ABI 基线验证属于构建期配套工具的职责，见[用户空间与常驻服务](../用户空间与常驻服务.md)第五节；更新发布前的接口需求检查与[内核集更新与回滚](../内核集更新与回滚.md)的保留集规则配合执行。

**内核模块接口的版本与兼容窗口由[内核模块容器](../内核模块容器.md)定义**：导出/导入按接口 ID 与槽位版本协商，模块声明依赖版本范围与内核 ABI 范围，且 `ModuleVersionMajor` 必须与 `.os` 的 `ModuleMajor` 硬相等。同一 `.os` 发布线内模块按修订更新（新模块文件、新清单与 `Modules.list` 落进同一集目录，重启生效、整修订回退，见[模块修订与更新](../模块修订与更新.md)）；主版本升级仍按整集更新/回滚（见[内核集更新与回滚](../内核集更新与回滚.md)）。更新发布侧尚未实现的是 Updater 的模块修订事务（暂存、依赖求解、保留空间检查、发布 `Pending` 与清理），归后续用户空间阶段；模块按修订的选版与回退已由引导选择器实现（M2 起，算法见[引导状态记录](../Baleen/引导状态记录.md) 2.2，M6 起用同集两修订夹具验证）。
