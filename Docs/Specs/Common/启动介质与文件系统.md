# 启动介质与文件系统

本文定义系统需要支持哪些启动介质、每种介质经由哪条控制器与访问链，以及必备文件系统和相关取舍。

介质怎样被引导器找到并装载，见 [Baleen 引导器](../Baleen/README.md)；内核侧的控制器与文件系统实现见[内核模块与驱动清单](../内核模块与驱动清单.md)；引导器与内核共用的块设备与文件系统抽象接口见[文件系统抽象与 VFS](文件系统抽象与VFS.md)（草案）。

## 一、启动介质与访问链

系统需要在没有内置硬盘时从 U 盘、移动硬盘、外置 SSD 或光盘启动，USB 3.x 存储设备也属于必备支持范围。统一设备模型根据启动线索优先扫描相关磁盘、USB 控制器和设备；线索不足时在受支持设备中继续查找并验证卷身份。访问系统卷所需的驱动已在 `.os` 内，不等待外部 `.drv`。

| 启动介质 | 控制器与访问链 | 默认系统卷路径 |
| --- | --- | --- |
| 内置 SATA 盘 | 内置 AHCI | Ext4 |
| 内置 NVMe 盘 | 内置 NVMe | Ext4 |
| 老 IDE 盘 | 内置 ATA PIO | Ext4 |
| U 盘（USB 2.0/3.x） | 内置 xHCI、USB 核心、hub、设备声明的 BOT 或 UAS 与 SCSI 存储 | Ext4 |
| USB 移动硬盘 / 外置 SSD | 内置 xHCI、USB 2.0/3.x、BOT/UAS 与 SCSI 块设备；包含通过 USB-SATA、USB-NVMe 桥接的存储设备 | Ext4 |
| SATA 光驱 | 内置 AHCI ATAPI | ISO9660 → Ext4 镜像 |
| 老 IDE 光驱 | 内置 ATA PIO ATAPI | ISO9660 → Ext4 镜像 |
| USB 光驱 | 内置 xHCI、USB 核心、设备声明的 BOT 或 UAS 与 SCSI 光驱命令 | ISO9660 → Ext4 镜像 |

### 1.1 引导期的启动模式与访问链

上表是内核侧的介质访问目标。**引导期由 Baleen 承担介质定位与内核装载**，它按介质与装配方式覆盖的启动模式如下：BIOS 路径按固件提供的 INT 13h 访问设备（不自行实现 USB、AHCI 或 NVMe 驱动），UEFI 路径按固件应用与块设备协议访问。

| 启动模式 | 装配方式 | 载体与接口 |
| --- | --- | --- |
| 硬盘（512e / 4Kn） | 安装工具装配 | 固件映射为硬盘的 SATA / IDE / SCSI 扩展卡 / NVMe 等；BIOS 路径经固件 INT 13h，UEFI 路径经固件块设备协议 |
| U 盘、移动硬盘、外置 SSD（512e） | 从 ISO 刻录 / 安装工具装配 | 固件 USB 引导能力（USB 1.1 / 2.0 / 3.x 控制器） |
| U 盘、移动硬盘（4Kn 透传） | 从 ISO 刻录 / 安装工具装配 | 同上；部分固件的 USB 存储层只接受 512 字节块设备（如 SeaBIOS），此时设备不可见。介质布局与内置硬盘一致，固件能识别即可引导；UEFI 块设备协议按设备报告的逻辑块大小工作，不受该限制 |
| 光盘（El Torito 无仿真） | 从 ISO 刻录（含虚拟机挂载） | SATA / IDE ATAPI 光驱、虚拟机挂载 ISO；经引导目录与 EFI 项引导 |
| 软盘、USB-FDD、USB-ZIP | — | 传统软驱与仿真；不在支持范围 |
| 网络引导（PXE / HTTP Boot） | 从网络 | 网卡与固件网络栈：BIOS 侧为 PXE Option ROM，UEFI 侧为 PXE 与 HTTP Boot；列入后续扩展 |

**两种装配方式的差别在介质内容，不在引导二进制**——两者用的是同一份 IPL、Stub 与 Core：

| 装配方式 | 介质内容 | 系统卷形态 | 承担者 |
| --- | --- | --- | --- |
| 从 ISO 刻录 | 混合镜像：MBR 引导记录 + ISO9660 卷 | ISO9660 卷内的 Ext4 镜像文件 | `MakeIso` 产出混合镜像，由用户或写盘工具写入介质 |
| 安装工具装配 | 磁盘布局：MBR 分区表 + 引导载荷 + ESP + 系统卷分区 | 分区上的 Ext4 卷，与内置硬盘一致 | `MakeHdd` 产出整盘镜像直写；ISO 内的交互式安装器（可选内置硬盘、U 盘或移动硬盘为目标）由部署侧实现 |

**USB 存储的 4Kn 限制来自固件，与装配方式、介质布局无关**：安装器装配后的 U 盘、移动硬盘与内置硬盘内容一致，接入方式（USB 桥是否透传 4Kn）与固件的 USB 存储实现决定它能否被枚举。BIOS 侧部分固件只接受 512 字节块设备；UEFI 侧按块设备协议处理设备报告的逻辑块大小，不受此限制。

**引导二进制与逻辑扇区单位解耦**：BIOS 路径按介质起始的固定偏移读描述符与载荷、运行期向固件询问扇区大小，载荷按 4096 对齐，因此同一份二进制在 512e 与 4Kn 上都能引导。**分区表属于部署阶段**（写入方按目标设备生成），引导二进制不解析它，见 4.1 与 4.2。

## 二、ISO 镜像形态与三种投递方式

**ISO 是分发形态，不是一种物理设备。** 项目的引导介质是“系统引导文件”，它可以被投递到三种载体上，而内核对这三种载体的访问链完全一致：

| 投递方式 | 载体呈现 | 引导侧 | 内核侧看到的卷 |
| --- | --- | --- | --- |
| 写入 U 盘或移动硬盘 | 混合镜像（hybrid ISO）：介质同时带光盘布局与可引导分区记录 | 固件按 U 盘方式引导 | ISO9660 卷 |
| 虚拟机选择 ISO 文件 | 虚拟光驱（QEMU `-cdrom` 等） | 虚拟机固件按光驱引导 | ISO9660 卷 |
| 物理或外置光驱 | 光盘 | 固件按 El Torito 引导 | ISO9660 卷 |

因为写入 U 盘后的介质呈现的仍是 ISO9660 卷，**内核不需要区分“这来自光驱还是来自 U 盘”**：三种方式都归到同一条 `ISO9660 → 卷内 Ext4 镜像` 路径。刻录或写入时由镜像组装器保证同一份镜像同时满足光盘与 U 盘两种引导记录要求，写法与限制见 [Baleen 引导器](../Baleen/README.md)。

**光盘上的系统卷是卷内文件，不是整盘系统卷。** 将 Ext4 系统卷镜像作为 ISO9660 文件保存，与磁盘版本共用卷内布局；内核通过块设备偏移视图访问它。采用单区段实现时，镜像组装器必须保证文件连续，装载时验证，不支持的布局明确拒绝。

## 三、必备文件系统

**USB 存储、Ext4、ISO9660、FAT32 是本项目的必备能力，随 `.os` 提供。** USB 明确包含 xHCI、USB 2.0/3.x 设备与 hub 枚举，以及 BOT、UAS 两种存储传输路径，覆盖 U 盘、移动硬盘、外置 SSD 和 USB 光驱；三个文件系统通过统一 VFS 和块设备层访问设备。

FAT32 支持同样必须内置，可在模块装载前读取已识别的 FAT32 引导、安装和恢复介质，运行期用于读写交换卷。默认系统卷仍是 Ext4；FAT32 的必备支持不把所有文件系统都变成系统卷，也不要求每次启动挂载每一个卷。ISO9660 只要求主目录与 Rock Ridge，不要求 Joliet；镜像组装器保证所需路径能被这套实现识别。

## 四、取舍与边界

引导期的启动模式与访问链见 1.1；内核侧的介质访问目标见第一节。引导期按固件报告的逻辑扇区大小访问介质，物理扇区大小不替代它。

| 取舍 | 决定与约束 |
| --- | --- |
| 读写 | 同一驱动和文件系统实例早期只读；Ext4 日志回放等会修改介质的操作不得隐式发生。需要恢复的卷只在具备安全写入与恢复条件后处理，否则报告并停止该启动路径 |
| DMA 与中断 | 早期允许必要的 DMA，轮询完成并设置超时；中断、工作队列和异步请求在依赖就绪后启用，沿用同一请求模型和资源归属 |
| 设备范围 | 优先扫描启动所需设备，之后在同一设备树上继续发现其他设备；不得另建早期设备表并在运行期重复绑定 |
| USB 控制器与链路 | xHCI 是内置必备主控，支持 USB 3.x 链路及其管理的 USB 2.0 设备；根据主控、端口、hub、线缆和设备实际能力协商速率。纯 EHCI 是另一条主控路径，仍需独立驱动接入，不能将其与 xHCI 支持混淆 |
| USB 存储协议 | BOT 与 UAS 均内置，并可在挂载系统卷前使用。按接口描述符及主控能力选择协议；不能假定 USB 3.x 设备一定使用 UAS，也不能假定 UAS 设备总能退回 BOT。只有设备实际提供兼容的 BOT 接口时才允许安全回退 |
| USB hub | 当前支持根 hub 之外一层 hub；更深拓扑需扩展同一实现和验证范围，不另建运行期替代栈 |
| ISO9660 | 主目录与 Rock Ridge，不要求 Joliet；镜像组装器保证所需路径能被这套实现识别 |
| 光盘系统卷 | 将 Ext4 系统卷镜像作为 ISO9660 文件保存，与磁盘版本共用卷内布局 |

USB 3.x 表示链路能力，BOT/UAS 表示存储传输协议，二者分别识别；支持 USB 移动存储不等于自动支持其上的所有文件系统。USB-SATA、USB-NVMe 桥接设备在此通过它们暴露的 USB 存储接口访问，不要求把 USB 桥接路径当作直接 AHCI 或 PCIe NVMe 控制器。

早期 UAS 可以限制在途命令数量并轮询完成，但仍须实现所选模式需要的命令、数据、状态端点、streams 能力检查及超时恢复；不能把启动成功依赖的 UAS 能力留到外部模块装载之后。轮询和运行期异步处理共用同一协议状态与设备实例。

AHCI 的 CPU 侧传输使用 DMA，即使设备侧执行 PIO 命令也是如此。依据是 Intel AHCI 规范。

块设备契约必须携带设备报告的逻辑块大小，不得写死 512 字节。镜像位置用字节偏移和长度描述，并检查边界与对齐。光盘上的 Ext4 镜像使用块设备偏移视图；采用单区段实现时，镜像组装器必须保证文件连续，装载时验证，不支持的布局明确拒绝。

### 4.1 分区、部署与逻辑扇区单位

**分区表由部署阶段生成，不属于引导二进制。** MBR 分区项与 GPT 表项的长度字段不带单位，固件按目标设备的逻辑扇区解释，同一个整数在 512e 与 4Kn 上指向相差 8 倍的位置；分区表因此在写入时按目标设备确定单位，不存在一份字节同时适配两种逻辑扇区的写法。部署环节与职责：

| 部署环节 | 职责 |
| --- | --- |
| 镜像组装（`MakeHdd` / `MakeIso`） | 按目标设备生成 MBR 分区表与引导载荷，产出可写盘、写 U 盘的镜像 |
| 安装器（ISO 内运行） | 用户选定内置硬盘、U 盘或移动硬盘后，读取该设备报告的逻辑扇区大小，据此生成分区表并写入系统 |

引导二进制（IPL、Stub、Core 与 `BOOTX64.EFI`）不解析分区表：BIOS 路径按介质起始的固定偏移读取描述符与载荷，扇区大小在运行期向固件询问；载荷按 4096 对齐，在 512 / 2048 / 4096 三种单位下都能整扇区读取。同一份二进制可直接写进 512e 或 4Kn 介质，不需要按扇区单位重新编译。

部署侧的分区要求：

| 项 | 要求 |
| --- | --- |
| 分区表形态 | MBR 与 GPT 两种形态共用同一套引导区，读取方按 LBA 访问；介质前部布局见 4.2 |
| 0 号分区 | ESP：类型 `0xEF`、FAT32、起点优先取 1 MiB，内容含 `\EFI\BOOT\BOOTX64.EFI` |
| 1 号分区 | 系统卷：类型 `0x83`、Ext4 |
| 引导载荷保护区 | 介质起始区不得被分区覆盖：描述符在 `0x22000` 与 `0x22020`，载荷自 `0x23000` 起按 4096 对齐 |
| 系统卷定位 | 由 `BaleenLayout.bin` 布局描述给出，写入方保证分区表、布局描述与实际写入位置一致 |

**ISO 是分发与安装媒介**：运行于虚拟机挂载、U 盘启动或移动硬盘启动，用于试用与执行安装；硬盘上的正式系统由安装器按上面的要求写入。系统卷在 ISO 内是 ISO9660 卷内的 Ext4 镜像文件，与磁盘形态共用卷内布局。

### 4.2 引导区与分区表保留区

**MBR 与 GPT 共用同一套引导区。** 描述符固定在字节偏移 `0x22000`（`CoreDescriptor` 在 `0x22020`），引导载荷自 `0x23000` 起：两者都落在 GPT 保留区（主头 LBA 1、分区项区 LBA 2–33）之后，也落在 MBR 只用 LBA 0 的范围之后。分区表形态因此只影响介质最前部的分区描述，切换形态不需要调整引导区，也不需要重新编译任何二进制。

介质前部的两类内容分开看（LBA 以设备逻辑扇区为单位）：

| 内容 | MBR 分区表 | GPT |
| --- | --- | --- |
| LBA 0 的 0–445 字节 | IPL 引导代码（两种形态共用同一份） | 同左 |
| LBA 0 的 446–509 字节 | 槽位 0 = ESP（`0xEF`）、槽位 1 = Ext4（`0x83`） | 槽位 0 = `0xEE` 保护项，覆盖全盘 |
| LBA 1–33 | 空闲 | GPT 主头（LBA 1）与分区项区（LBA 2–33） |
| `0x22000` 与 `0x22020` | 引导区的两枚描述符（两种形态共用） | 同左 |
| `0x23000` 起 | 引导载荷：Stub 与 Core | 同左 |
| 第一个分区（起点优先 1 MiB） | 0 号分区 ESP（FAT32）、1 号分区 Ext4 系统卷 | 同左，分区改由 GPT 项描述 |
| 磁盘末尾 | — | GPT 备份表与备份头 |

**分区表的写入方**：MBR 分区表由镜像组装器（`MakeHdd` / `MakeIso`）生成；GPT 分区表的写入列入部署侧实现（安装器按目标盘生成），两者的 LBA 单位都按目标设备的逻辑扇区确定（见 4.1）。

**混合 ISO 固定使用 MBR 分区表。** 光盘形态没有分区表，混合镜像（写 U 盘或移动硬盘）的 MBR 只为固件找 ESP 服务；GPT 与 ISO 结构有三处硬冲突：GPT 主头与标准项区（LBA 1–33）覆盖 El Torito 引导镜像（位于字节 `0x800`）与 ISO9660 元数据（主卷描述符固定在 LBA 16）；备份表需要盘尾扇区，而那里是 ISO9660 的文件数据区；GPT 服务的需求（超过 2 TiB 的盘、与其他系统共存）也不适用于安装介质。**需要 GPT 的是安装器装配的磁盘布局**，不是 ISO 本身。

描述符与载荷的字节位置取 512 / 2048 / 4096 三种逻辑扇区的公倍数：`0x22000` 在三种单位下分别是 LBA 272、68、34，都是扇区边界且在 4Kn 的 GPT 保留区（到 `0x21FFF`）之后。**同一份镜像在三种单位下的引导区位置一致**，不随介质单位变化。

引导区的容量要求：Stub 不超过 `0x8200`；Core 上限为 `0x400000`，若核心载荷接近该上限，"1 MiB 之前"的范围（约 1 MiB 减保留区）容不下，写入侧需后移第一个分区起点或为核心载荷另划未分区区段。

读盘只走 EDD：引导区位于保留区之后，超出传统 C0H0 兼容范围，不保留 CHS 回退。

## 五、阶段切换与写入启用

同一实例从轮询转为中断或异步处理时，要暂停新请求、完成或收敛在途 I/O、切换完成通知方式，再恢复请求。写入的启用还须验证介质可写、缓存刷新、文件系统一致性及失败处理能力。阶段切换不构成驱动热替换，也不释放仍有效的实例和资源。

**没有可写介质时只读运行。** 日志保存在内存和可用输出通道，配置及内核集不能更新，也不启用需要持久试启动记录的自动回滚协议。U 盘、移动硬盘和外置 SSD 上的系统在写入条件满足后可以写入，日志和更新元数据应控制写入频率。
