# 系统卷布局

**系统卷是内核与用户空间的根。** 它是一张 Ext4 卷，卷标识由[布局描述](../Baleen/布局描述.md)与内核各自核对一次；卷内路径是系统各部分之间唯一的约定——引导器只知道内核镜像的那一条路径，内核与用户空间按本文的目录树找到其余内容。本文定义目录树的职责与边界、命名与放置规则，以及构建产物落到哪里。

引导器、描述符区、布局描述与引导状态区域都在**卷外**（引导区），不进系统卷；系统卷里只有系统与用户的内容，没有引导元数据。

## 一、设计原则

1. **按“谁管理、谁能改”划分目录，不按文件后缀划分。** 后缀表达容器类别，见[后缀设计](../后缀设计.md)；目录表达归属：随系统更新的一侧、可单独卸载的一侧、用户自己的一侧。
2. **三种归属，三条边界。** `/LikesProgram` 是系统目录：随内核集与系统更新切换，用户不单独增删；`/ProgramFiles` 是程序目录：镜像内置的可卸载程序与用户安装的程序都在这里；`/Users` 是用户目录：配置与数据随用户走。
3. **路径只定语义，不定格式。** 本文给的是路径与职责；某类文件叫什么名字、内容什么格式，由各自的规格定义。
4. **卷标识来自 superblock，不靠标记文件。** 不设“这是系统卷”的根标记：身份由 `s_uuid` 与布局描述核对，卷根不预置杂物。
5. **只读介质上不假定可写。** ISO 形态的系统卷在只读介质上；`Users` 与安装记录需要可写介质才能持久化，只读介质上的用户数据机制（内存层或覆盖层）随后续阶段定义，当前不承诺。
6. **同一个组件只有一份落点。** 不允许同一份 `.osm` 或 `.exe` 在两处并存，避免“改一处、读另一处”。

## 二、目录树

```text
/                                  系统卷根
├── LikesProgram/                  系统目录：随系统更新，用户不单独增删
│   ├── System/                    内核集：一次交权要载入的镜像与它的事实
│   │   ├── KernelSets/            内核集目录：每集一个 <BuildId> 子目录，含清单与全部产物
│   │   └── Drivers/               外部驱动 .drv
│   ├── Programs/                  系统程序：Init、Session、桌面、外壳与系统服务
│   ├── Config/                    系统配置：启动配置、发行策略、服务编排参数
│   └── Resources/                 系统资源：字形、主题、图标等
├── ProgramFiles/                  程序目录：可单独卸载的程序
│   └── <厂商>/<程序>/             每个程序一个子树
└── Users/                         用户目录：每个账户一份
    └── <账户>/                    用户配置与数据
```

`Packages/LikesProgramOS/Static/` 就是这份树的源，构建期按原样写进系统卷，见第五节。

卷根另有一个 `lost+found` 是 mkfs 自己建的文件系统恢复目录，不属于本文的布局设计，也不需要系统去用它。

## 三、各目录职责

### 3.1 `/LikesProgram` — 系统目录

**由系统自身管理，随内核集或系统更新整体切换，用户不能在系统里单独卸载。** 里面的内容属于发行的一部分：发行配置选中的能力必须齐全，缺失按[内核架构与自举闭包](../内核架构与自举闭包.md)的策略处理。

| 子目录 | 内容 | 说明 |
| --- | --- | --- |
| `System/` | 内核集 | 见 3.2 |
| `Programs/` | 系统程序与系统服务 | `Init.exe`、`Session.exe`、`Desktop.exe`、`Shell.exe`、`Terminal.exe` 及 `EquipmentManager`、`LogService`、`Compositor`、`Updater`、`Maintenance` 等；程序是 `.exe`，服务声明是 `.svc`，同处一目录，角色由声明表达。清单与职责见[用户空间与常驻服务](../用户空间与常驻服务.md) |
| `Config/` | 系统配置 | 启动配置、发行策略、服务编排参数；随内核集发布的配置与集绑定，见[内核集更新与回滚](../内核集更新与回滚.md) |
| `Resources/` | 系统资源 | 字形、主题、图标等随系统走的数据；用户自己的资源在 `Users` 下 |

内核 exec 的第一个用户态进程 `Init.exe` 的路径是内核侧约定，落在系统程序目录；具体路径随用户空间阶段固定。

### 3.2 `/LikesProgram/System` — 内核集

| 内容 | 说明 |
| --- | --- |
| `KernelSets/<BuildId>/` | 一个完整内核集：清单 `Manifest.mft`、内核本体 `LikesProgram.os` 与发行选择的 `.osm`；[内核镜像数据](../Baleen/内核镜像数据.md)在内核镜像文件起点，布局描述的内核路径指向缺省集的集目录 |
| `Revocation.rvk` | 签名的吊销记录：引导选择器在装载前读它、验签并按单调并集应用；文件不存在表示没有吊销记录，是正常形态。字节表与签名者规则见[内核集清单与签名](../内核集清单与签名.md) 5.1，生成工具是 `MakeRevocation` |
| `Drivers/` | 外部驱动 `.drv`；启动必需驱动以完整实现编入 `.os`，不在这里 |

**内核集按 `BuildId` 分目录并存。** 集目录名是 `BuildId` 32 字节的小写十六进制，候选集与已知良好集各占一个目录、互不覆盖；目录内的清单是集合的身份与内容列表，格式与签名见[内核集清单与签名](../内核集清单与签名.md)，选版状态见[引导状态记录](../Baleen/引导状态记录.md)。**选版启用前**，卷内可以是单集的扁平落点（`System/LikesProgram.os`，当前构建的形态）；启用选版与试启动时迁移到集目录形态。同一份文件的落点唯一，更新不得原地覆盖回滚仍需要的版本。

### 3.3 `/ProgramFiles` — 程序目录

**镜像内置但用户可卸载的程序，与用户自己安装的程序都在这里。** 与 `LikesProgram/Programs` 的区别是管理归属：这里的程序可以在系统里卸载；系统程序只能随系统更新切换，不能单独卸载。

- 一个程序一个子树：`ProgramFiles/<厂商>/<程序>/`，程序文件与它的资源、声明同处一棵子树。
- 卸载的粒度是子树：删除子树加安装记录；安装记录与版本并存规则由安装与更新阶段定义。
- 内置的可卸载程序在组装镜像时写入，卸载后不会再出现——重新安装需要原安装包或镜像恢复。

### 3.4 `/Users` — 用户目录

- 每个账户一份：`Users/<账户>/`，账户名由登录与服务编排阶段定义。
- 账户目录里区分用户可见目录（`Desktop`、`Documents`、`Downloads`、`Pictures` 等）与私有目录（每用户配置、缓存）；具体集合随用户空间阶段确定，新增按追加方式。
- 只读介质上不持久化：ISO 形态下 `Users` 的写入需要可写介质或内存层，机制未定（第一节第 5 条）。

## 四、谁读谁写

| 使用方 | 读 | 写 |
| --- | --- | --- |
| BaleenCore / UEFI | 布局描述与集目录：内核路径、卷标识核对、按集标识读清单与产物 | **不写系统卷**；引导状态区域在卷外的裸块区 |
| 内核 | `System/` 下的内核集文件、`Config/` 与 `Resources/` | 早期只读；写入条件见[启动介质与文件系统](启动介质与文件系统.md) |
| Init 与常驻服务 | 系统程序、配置、资源、`ProgramFiles` | `Users`、安装记录；范围受能力授权约束 |
| Installer / Updater | 全部 | `LikesProgram` 与 `ProgramFiles`；按 3.2 的并存要求保留回滚版本 |

## 五、生成与组装

**`Packages/LikesProgramOS/Static/` 是系统卷根的源。** 构建期把它写进卷，路径不改写：

1. 各模块的 Makefile 产出自己的产物到各自的 `Out/`；
2. `Packages/LikesProgramOS/Makefile` 把产物从 `Out/` 拷进 `Static/` 的对应落点，映射逐项列在 Makefile 里，就是“哪个产物落到哪个路径”的唯一清单；卷内路径直接映射到 `Static` 下的同一路径；
3. 组装时把 `Static` 拷成卷根副本，丢掉 Git 的存在标记 `.keep`（空目录不进 Git 的产物），其余字节按原样交给 `mke2fs -d` 就地生成系统卷镜像，不挂载、不需要 root。

| 产物 | 卷内落点 | 当前状态 |
| --- | --- | --- |
| 内核映像（内核侧 Core） | `/LikesProgram/System/KernelSets/<BuildId>/LikesProgram.os` | 已接通：构建期按 `.os` 的 `BuildId` 落进集目录，签名清单同目录并存；布局描述的 `KernelPath` 指向缺省集 |
| 内置 `.osm`、`.drv` | `/LikesProgram/System/KernelSets/<BuildId>/`（随集）、`/LikesProgram/System/Drivers`（外置） | 随对应模块阶段接入 |
| 系统程序与服务声明 | `/LikesProgram/Programs` | 随用户空间阶段接入 |
| 可卸载内置程序 | `/ProgramFiles/<厂商>/<程序>` | 随安装器阶段接入 |

拷贝进 `Static/` 的是构建产物，不进 Git；`Static/` 的目录骨架与手工维护的内容（配置、资源、模板）进 Git。**组装器不检查卷内有没有内核**：内核镜像缺失时 BaleenCore 报告“系统卷里没有内核”并停在阶段边界，这是可观测的正常状态，不是组装错误。

## 六、命名与放置规则

1. 目录与文件名用 ASCII 可打印字符，不用空格，避免仅大小写不同的重名（同一份布局将来可能被大小写不敏感的卷形态引用）。
2. 目录名是平实英文单词，与本文及各规格的口径一致；新增顶层目录必须写明归属（系统、程序还是用户）并同步本文与 `Static/` 骨架。
3. 系统目录的子目录按内容类别分（内核集、程序、配置、资源），不按文件后缀再分一层。
4. 程序一个子树；同一程序的不同版本不并存在同一子树里，版本并存由安装与更新阶段在子树外表达。
5. 集目录名是 `BuildId` 的 64 个字符小写十六进制，不由英文单词组成，属第 2 条的例外，见 3.2 与[内核集清单与签名](../内核集清单与签名.md)第一节。
