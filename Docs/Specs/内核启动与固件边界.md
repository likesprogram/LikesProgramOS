# 内核启动与固件边界

本文定义内核入口的最小契约、固件服务在本项目中的失效边界，以及第三方引导方式接入本内核的条件。

**一句话口径：内核只认自家引导器 [Baleen](Baleen引导器.md) 的交接契约；进入 `KernelMain` 的第一步就是让固件启动服务失效，此后固定运行模式，不降级回固件。**

## 一、内核入口契约

内核入口由引导器按其交接契约提供，包含两部分：

- **镜像入口**：Baleen 交接契约定义的镜像头与入口点；由打包器写入并验证，由 Baleen 在装载前校验。

**内核不为第三方引导协议提供适配层。** `.os` 里没有 Multiboot2、Linux boot protocol 之类的入口实现，也不承诺从这些入口启动。BIOS 与 UEFI 是本项目自家支持的引导模式，它们的入口形态由 Baleen 一侧负责准备——UEFI 固件加载的是 Baleen 的固件应用，BIOS 加载的是 Baleen 的一级引导，两者都不直接接触内核镜像，因此**内核镜像不需要附带任何固件能直接识别的标准头**。内核在入口处只做两件事：核对 `BootInfo` 的尺寸与版本，然后按其中声明的机器状态进入自己的初始化序列。`BootInfo` 的字段定义、生成方式和版本规则由 [Baleen 引导器](Baleen引导器.md) 定义。

这样安排的理由是职责单一：**识别介质、定位卷、读入镜像、准备机器状态全部属于引导器**，内核从“已经拿到的启动信息”开始工作。内核对引导器用什么方式找到系统卷不感兴趣，只要求 `BootInfo` 里的事实准确。

## 二、固件服务失效边界

**固件不是被假定已经卸载，而是在 `KernelMain` 的第一步失效。** 区别很重要：

- 引导阶段的介质访问、卷定位和镜像装载由引导器完成，此时代码运行在固件提供的环境中（BIOS 中断或 UEFI Boot Services）。
- 进入 `KernelMain` 后，内核立即让固件启动服务失效，此后不再调用任何固件服务。目的不是“清理”，而是**固定运行模式**：内核之后的每一条执行路径都只能依赖自己的实现，不存在“这次不行就退回固件”的分支。

| 环境 | 失效动作 | 之后 |
| --- | --- | --- |
| UEFI，Boot Services 仍有效 | 调用 `ExitBootServices`。按 UEFI 规范，它必须恰好调用一次，且需要与当前内存图匹配的 MapKey：若调用返回 `EFI_INVALID_PARAMETER`（MapKey 已过期），重新取内存图后再调用 | 不再使用 Boot Services；`BootInfo` 中标记为已退出 |
| UEFI，引导器已退出 Boot Services | 不重复调用，只核对 `BootInfo` 中的状态标记 | 同上 |
| Legacy BIOS | BIOS 服务只在实模式可用，长模式下本就不具备调用条件；内核不建立回退路径，也不保留实模式跳板 | 不再使用 BIOS 中断服务 |

**“不降级”的准确含义**：不因为固件还能提供某项能力就把该能力算作可用。UEFI Runtime Services 在 `ExitBootServices` 之后技术上仍然存在，本项目也不使用它们——需要平台能力（时间、变量、复位、电源）时，由内核对相应硬件或 ACPI 表自行实现，或由用户态服务接管。这条边界同时约束驱动和模块：**内核代码不得为“固件还能帮忙”设计任何分支**。

失效之后的启动全过程见下一节；设备与文件系统能力全部来自 `.os` 的内置实现，见[内核架构与自举闭包](内核架构与自举闭包.md)与[启动介质与文件系统](启动介质与文件系统.md)。

## 三、载入链

```text
阶段 0  固件 → 引导工具 / 引导选择器（Baleen）→ 所选 LikesProgram.os
        自动回滚模式先持久记录 Trying，再交权；BootInfo 交付统一启动状态
阶段 1  初始化内置平台、内存和统一对象/归属机制，按依赖准备调度、IRQ 与设备框架
        进入 KernelMain 后第一步：让固件启动服务失效，固定运行模式
        DevModel 优先发现启动路径
        DriverLoader 注册内置驱动，由同一实例同步读取介质；挂卷并验证构建清单
阶段 2  按硬依赖图装载所选 .osm，建立归属，完成同步 Init
        外置基础模块包括 Process、Ipc、Fault，实际顺序由依赖和阶段约束生成
阶段 3  按激活条件启用调度、IRQ、工作队列及驱动异步能力
        同一 DevModel 继续枚举；DriverLoader 装载额外 .drv，已有绑定不重复创建
        内置驱动继续使用同一实例，满足介质和文件系统条件后开放写入
阶段 4  内核 exec Init.exe → 必需服务与健康检查 → 会话或发行指定的就绪状态
        试启动满足全部确认条件后，持久提交 Confirmed
失败    可撤销的可选能力失败：传播依赖失败并按策略降级
        必需能力失败或状态不可恢复：报告并重启；选择器回退整个内核集
```

`Init` 只做可撤销的软件准备，不启动线程、不启用设备中断、不执行不可逆设备操作；`Activate` 才按依赖启用对应能力。启动设备的首次硬件激活发生在挂系统卷之前，可使用同步轮询。后期异步能力的启用是该实例的阶段转换，不是再次执行 `Init` 或创建替代实例；需要提前激活的内置依赖仍按同一图检查。阶段转换与写入启用条件见[启动介质与文件系统](启动介质与文件系统.md)。

**启动设备线索不足时，由 `.os` 校验卷标识和布局信息；无法唯一定位就报告失败，不能猜测磁盘。** 线索由 `BootInfo` 传入，校验规则见 [Baleen 引导器](Baleen引导器.md)。

进入用户态之后的启动编排见[用户空间与常驻服务](用户空间与常驻服务.md)。
