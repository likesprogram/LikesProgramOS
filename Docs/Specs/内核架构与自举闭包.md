# 内核架构与自举闭包

本文定义 LikesProgramOS 内核的组成方式：链接模式与源码边界、自举闭包与内置必备基线、外置能力归属，以及镜像体积口径。

**内核 = `LikesProgram.os` + 发行配置选择的 `.osm` 模块。** `.os` 提供本项目规定的内置必备基线，发行配置不能将其裁掉；外置模块可以按需选择，但被选中能力的硬依赖必须齐全。发行策略可进一步声明必需的扩展能力，缺失时进入可用的恢复路径或拒绝启动，不能把“模块可选”解释成任何模块缺失都能正常运行。

内核模块共用源码和接口契约，通过 `LINK_MODE` 决定编入 `.os`，还是生成启动时装载的 `.osm`。拆分的目的有两个：

- **引导期自足。** 退出固件启动服务后，`.os` 自带读取系统卷、装载模块和报告错误所需的全部能力。
- **更新可恢复。** 新旧内核集并存，按整套构建清单切换和回滚。模块可以分别存储和传输，但不能绕过构建一致性检查单独混装。

后缀语义见[后缀设计](后缀设计.md)；本节引用其约定，不另行定义容器类别。

## 一、构建模式与源码边界

| 取值 | 产物 | 初始化调用方 |
| --- | --- | --- |
| `LINK_MODE=builtin` | 编进 `LikesProgram.os` | 内置启动序列 |
| `LINK_MODE=module` | 编成 `xxxx.osm` | 模块装载器 |

`LINK_MODE` 决定链接目标，不表示运行期按需加载。发行配置选中的 `.osm` 在启动阶段按依赖序装载；两种目标共用模块逻辑、接口声明和初始化契约，不按链接目标维护两套实现。

构建与装载遵守以下规则：

1. **自举闭包和发行必备基线必须内置。** 退出固件启动服务后，到能够装载模块之前需要的能力，以及本项目规定随 `.os` 提供的能力，设为 `builtin`，其硬依赖递归纳入内置集合。功能内置不要求最早阶段全部激活。
2. **`builtin` 不得硬依赖 `module`。** 构建系统根据接口需求和依赖声明检查依赖图，违反即失败。模块装载器通过统一入口调用被装载模块；内置机制可以提供注册面供模块扩展，但不能直接导入具体 `.osm` 的符号。
3. **跨模块接口只有一份定义。** 契约层生成导出与导入声明；编入 `.os` 时由链接器解析，生成 `.osm` 时由装载器解析。调用方式的差异由构建和装载工具处理。
4. **一个内核集来自同一次构建。** `.os`、该构建的 `.osm` 和构建清单共享 `BuildId`。清单绑定各产物的摘要、依赖、布局和启动配置；装载时同时检查签名、摘要和 `BuildId`，不接受跨构建混装。

**内核模块和驱动均不维护“引导简版 / 运行期完整版”两套实现。** 启动必需驱动以完整实现编入 `.os`，从启动到运行期沿用同一设备身份、资源记录和驱动实例。早期同步轮询、后期中断与异步工作是同一实现的运行阶段，不再通过 `boot/full` 编译配置生成两个实例并交接。

驱动清单区分内置驱动和外部 `.drv`，两者共用驱动契约与生命周期。内置描述随 `.os` 校验和注册，外部驱动文件由同一个 DriverLoader 读取、验签和装载；不能把读取启动卷所需的唯一驱动只放在尚不能读取的卷里。

## 二、`LikesProgram.os` 的功能与自举闭包

`.os` 负责基础初始化、统一设备管理和驱动装载、访问启动介质、装载同一内核集的模块，以及执行早期诊断和恢复决策。整套镜像的选择和跨版本回滚由交权前的引导选择器完成，见[内核集更新与回滚](内核集更新与回滚.md)。

**USB 存储、Ext4、ISO9660、FAT32 是本项目的必备能力，随 `.os` 提供。** USB 明确包含 xHCI、USB 2.0/3.x 设备与 hub 枚举，以及 BOT、UAS 两种存储传输路径，覆盖 U 盘、移动硬盘、外置 SSD 和 USB 光驱；三个文件系统通过统一 VFS 和块设备层访问设备。必备能力必须保留完整实现，但只在对应设备、卷和运行条件就绪时启用。介质与控制器对应关系见[启动介质与文件系统](启动介质与文件系统.md)。

以下模块及其硬依赖设为 `LINK_MODE=builtin`：

| 模块 | 内容与边界 |
| --- | --- |
| 平台初始化 | GDT/TSS/IDT、长模式、页表与 physmap、CPU 特性与拓扑探测、异常处理和早期计时；自举所需 ACPI 等平台事实在此取得 |
| 物理内存与虚拟内存 | 页帧分配器、地址空间、映射、内核堆及 DMA 缓冲区管理 |
| Objects | 统一对象、句柄、代际、命名空间和归属记录；设备资源从首次登记起使用同一套机制，用户句柄在进程环境就绪后启用 |
| Sched | 调度器、线程、等待队列和同步机制；早期不需要线程的路径同步执行，就绪后启用工作队列和抢占 |
| Irq | 统一 IRQ 登记、分发和排空；早期设备 I/O 可轮询，满足激活条件后启用设备中断 |
| DevModel | 完整设备模型：设备身份、PCI/USB 与平台枚举、资源分配、拓扑和绑定关系；早期优先发现启动路径，运行期在同一设备树上继续枚举和处理热插拔 |
| DriverLoader | 统一管理内置驱动描述和外部 `.drv`，负责匹配、校验、初始化、绑定、停用及符合条件的热替换 |
| 启动设备驱动 | ATA PIO、AHCI/ATAPI、NVMe，以及 xHCI、USB 2.0/3.x 核心与 hub、BOT/UAS 和 SCSI 存储；覆盖 U 盘、移动硬盘、外置 SSD 与 USB 光驱，同一实例分阶段启用读写、中断和异步处理 |
| Ext4 | 默认系统卷文件系统，包含读写实现；早期只读，文件系统恢复和写入在相应条件满足后启用 |
| ISO9660 | 只读光盘文件系统，支持主目录与 Rock Ridge，用于定位系统卷镜像和读取光盘文件 |
| FAT32 | 必备文件系统，提供引导文件、安装恢复介质和交换卷的访问能力；读写共用同一实现，早期只读 |
| VFS 与块设备层 | 统一挂载、路径解析、文件引用、块大小和偏移视图；早期与运行期沿用同一卷和设备实例 |
| 配置与清单 | 解析配置、验证构建清单、选择能力和发行策略；不能通过配置改写产物的硬依赖 |
| 输出与诊断 | 内存日志 ring、可用串口、VGA 文本、BootInfo 帧缓冲绘字、栈回溯和诊断；持久输出等待写路径可用；文本输出的前端与阶段装配见[输出通道与Print](输出通道与Print.md) |
| 容器与模块装载 | 有界解析、验签、段映射、重定位、符号解析、依赖校验及初始化编排 |
| 启动状态、信任锚与契约层 | 所选内核集与试启动身份、失败报告和重启请求、信任及撤销规则、公共基础库和接口声明 |

**完整实现内置，不等于全部功能同时启动。** Objects、Sched 和 Irq 随设备框架内置，避免它直接依赖尚未装载的外部模块，或为早期启动再维护替代实现。初始化与运行阶段都参与依赖检查：不能因为某次调用发生得晚，就允许 `builtin` 直接导入 `module` 的符号。

早期 I/O 默认采用有超时的同步轮询和必要的 DMA。切换到中断或异步处理前，使用同一实例完成请求排空、通知方式和同步状态切换；设备身份、资源所有权和上层引用保持有效，不重新绑定第二个“完整驱动”。阶段转换规则见[启动介质与文件系统](启动介质与文件系统.md)。

## 三、外置能力归属

| 外置能力 | 归属 |
| --- | --- |
| 进程与用户地址空间管理、IPC、运行期故障策略 | 内核基础模块 `.osm`；早期故障报告和停止路径不依赖这些模块 |
| Ext4、ISO9660、FAT32 之外的文件系统、网络协议栈、审计 | 内核可选模块 `.osm` |
| 非启动必需设备及扩展驱动 | 外部 `.drv`，由内置 DriverLoader 管理 |
| 设备管理策略、日志归档、显示合成、会话与登录、升级编排、诊断工具 | 用户态 `.exe` 与服务声明 |
| 分发和安装 | 安装包 `.app` 与 Installer |

具体模块与输出名称见[内核模块与驱动清单](内核模块与驱动清单.md)和[用户空间与常驻服务](用户空间与常驻服务.md)。

## 四、镜像体积与参考口径

**`LikesProgram.os` 的体积参考目标为约 100MB。** 这是希望接近的规划量级，可以根据功能和实际构建结果调整，不是硬上限，也不作为构建失败条件。自举能力、必备功能和依赖完整性优先。

这个目标统计发布版 `.os` 文件，包含内置设备框架、启动驱动和必备文件系统，调试符号单独统计。构建报告分别记录发布文件大小、采用压缩时的压缩前后大小、启动峰值内存和运行期常驻内存，不能用一个数字代替全部口径。

主流系统也会提前准备启动依赖，但打包方式不同：Linux 可以由引导器提供 initramfs，也可以将其嵌入内核镜像；Windows 的 OS loader 提前装入 boot-start 驱动；macOS 使用预链接启动镜像或 Kernel Collection。LikesProgramOS 选择把本项目的启动必需实现内置，不要求每次启动先从系统卷读取这些驱动。
