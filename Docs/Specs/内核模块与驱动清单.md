# 内核模块与驱动清单

本文列出内核侧各组件的名称、交付形态和职责；产物后缀按[后缀设计](后缀设计.md)使用，不在这里重新定义类别。**引导链自身的产物（IPL、Stub、BootCore、BOOTX64、布局描述）见 [Baleen 引导器](Baleen/README.md)**；用户态程序、常驻服务与安装相关见[用户空间与常驻服务](用户空间与常驻服务.md)。

## 一、内核本体，`ring 0`

| 模块 | 输出名称 | 被谁载入 | 用途 | 手册 |
| --- | --- | --- | --- | --- |
| LikesProgram.os | `LikesProgram.os` | 自家或第三方引导工具 | 标准入口、自举闭包、统一设备和驱动框架、必备文件系统、同集模块装载及恢复请求 |  |

内置模块保持独立源码和接口，链接到同一个 `.os`，不再分别产出这些基础模块的 `.osm`：

| 模块 | 交付形态 | 用途 | 手册 |
| --- | --- | --- | --- |
| Objects | 内置 `.os` | 统一对象、用户句柄、代际、命名空间和归属管理；从早期设备登记延续到运行期 |  |
| Sched | 内置 `.os` | 调度、线程、等待、同步与工作队列；按阶段启用 |  |
| Irq | 内置 `.os` | IRQ 登记、分发、屏蔽和同步排空，支撑驱动中断与停用 |  |
| DevModel | 内置 `.os` | 完整设备模型、身份、拓扑、资源与绑定；同一设备树分阶段枚举 |  |
| DriverLoader | 内置 `.os` | 统一注册内置驱动和装载外部驱动，管理绑定、停用与外部驱动热替换 |  |
| Ext4 | 内置 `.os` | 默认系统卷读写与一致性处理，早期只读 |  |
| ISO9660 | 内置 `.os` | 光盘主目录与 Rock Ridge 读取 |  |
| FAT32File | 内置 `.os` | FAT32 读写，提供早期引导文件和运行期介质访问 |  |

平台、内存、VFS 等其他内置机制见[内核架构与自举闭包](内核架构与自举闭包.md)，启动驱动见本文第五节。

## 二、SDK 与契约层

内核内部契约随整集构建；面向外部作者发布的 SDK 遵守独立的兼容规则，见 [ABI 兼容与外部契约](ABI兼容与外部契约.md)。

| 名称 | 交付形态 | 给谁用 | 内容 | 手册 |
| --- | --- | --- | --- | --- |
| 契约层 | 源码树内 | 内核模块作者 | 生成的结构体、操作号、错误码、基础公共库、接口 ID、导入导出声明、初始化与归属契约 |  |
| DriveSDK | 独立发布 | 驱动作者 | 驱动契约表、稳定内核调用面、设备类请求、MMIO/DMA、IRQ、设备事实、停用与热替换接口；不得包含内核私有头 |  |
| AppSDK | 独立发布 | 应用和服务作者 | syscall 包装、文件、事件、终端、CRT 与启动；服务状态、控制和退出语义；需要能力授权的系统接口 |  |
| HostSDK | 独立发布 | 构建工具与安装器 | 容器、契约表、服务声明、构建清单、布局、签名和引导选择记录的格式定义及共用生成工具 |  |

## 三、外置内核基础模块，`LINK_MODE=module`，`ring 0`

这些模块提供常规用户态系统所需能力，发行通常将其列为必需。它们依赖内置框架，不能成为内置框架的直接符号依赖；缺失时只能使用实际仍可运行的恢复路径。以下表格不规定装载顺序。

| 模块 | 输出名称 | 用途 | 手册 |
| --- | --- | --- | --- |
| Process | `Process.osm` | 进程对象、用户地址空间、线程账和退出回收，使用内置 Objects、Sched 和内存机制 |  |
| Ipc | `Ipc.osm` | 端点、请求应答、事件和管道；不作为启动设备访问的前提 |  |
| Fault | `Fault.osm` | 运行期故障分类、恢复范围判定与维护策略；内置机制保留独立的早期报错和停止路径 |  |

## 四、内核可选模块，`LINK_MODE=module`

按发行需要选择；任何选中模块的硬依赖仍必须满足。Ext4、ISO9660 和 FAT32 已内置，不能作为可选文件系统删去。exFAT 是独立扩展，不与 FAT32 的必备地位混淆。

| 模块 | 输出名称 | 用途 | 手册 |
| --- | --- | --- | --- |
| ExFAT32File | `ExFAT32File.osm` | exFAT 文件系统探测、挂载和访问，使用统一 VFS 契约 |  |
| 网络协议栈 | 后续版本 | 网络核心与协议 |  |
| 审计 | 后续版本 | 安全审计与事件订阅 |  |

## 五、系统驱动，当前运行于 `ring 0`

内置与外部驱动使用同一驱动契约，由统一设备事实匹配。交付形态沿用[后缀设计](后缀设计.md)的驱动约定；是否支持热替换由设备、驱动能力和系统策略共同决定。

| 模块 | 交付形态 | 用途 | 手册 |
| --- | --- | --- | --- |
| AtaPio | 内置 `.os` | ATA 与 ATAPI 实现，包含读写和缓存刷新，同一实例按阶段启用 |  |
| Ahci | 内置 `.os` | AHCI/SATA 端口、ATAPI、DMA、中断、热插拔和恢复，早期可轮询 |  |
| Nvme | 内置 `.os` | NVMe 队列、DMA、中断与完成处理，同一队列和实例管理机制 |  |
| UsbCore / Xhci / UsbHub | 内置 `.os` | xHCI、USB 2.0/3.x 设备与 hub 枚举、链路能力识别、传输和完成处理，纳入统一设备树 |  |
| UsbStorage | 内置 `.os` | BOT/UAS 与 SCSI 存储，支持 U 盘、移动硬盘、USB-SATA/USB-NVMe 外置 SSD 和 USB 光驱；同一实例提供早期访问、运行期读写、多设备与热插拔 |  |
| Ps2Kbd | `Ps2Kbd.drv` | i8042 键盘探测、中断处理和键码上报 |  |
| Ps2Mouse | `Ps2Mouse.drv` | i8042 鼠标探测、位移与按键事件 |  |
| DispiFb / VbeFb | `DispiFb.drv` / `VbeFb.drv` | 显示模式与线性帧缓冲上报 |  |
| Acpi | `Acpi.drv` | ACPI 运行期服务和电源策略扩展；使用内置平台层发布的表信息，自举必需逻辑不得依赖它 |  |
| UsbHid / 网络类 | 后续版本 | 通过同一设备框架接入 USB 输入与网络设备 |  |

驱动执行上下文、装载流程与热替换协议见[模块与驱动装载](模块与驱动装载.md)。
