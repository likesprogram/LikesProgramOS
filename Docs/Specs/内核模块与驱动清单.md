# 内核模块与驱动清单

本文列出内核侧各组件的名称、交付形态和职责；产物后缀按[后缀设计](后缀设计.md)使用，不在这里重新定义类别。内核侧的交付形态分四类：**内核核心**（编进 `.os`）、**引导闭包**（交权前由引导器预装的 `.osm`）、**运行期模块**（内核挂载系统卷后装载的 `.osm`）与**外部驱动**（`.drv`）。划分规则见[内核架构与自举闭包](内核架构与自举闭包.md)，`.osm` 容器格式见[内核模块容器](内核模块容器.md)，模块修订与版本保留模型见[模块修订与更新](模块修订与更新.md)。**引导链自身的产物（IPL、Stub、BaleenCore、BOOTX64、布局描述）见 [Baleen 引导器](Baleen/README.md)**；用户态程序、常驻服务与安装相关见[用户空间与常驻服务](用户空间与常驻服务.md)；这些产物在系统卷内的落点见[系统卷布局](Common/系统卷布局.md)。

**输出名称是文件主名，集内落点文件名带版本。** 下表的输出名称（如 `DevModel.osm`）是构建产物名；落进 `KernelSets/<BuildId>/Modules/` 时文件名带模块版本（`<主名>.<major>.<minor>.<patch>.osm`，平铺、不建版本目录），具体路径以清单条目为准。版本判定以 `.osm` 文件头与清单/`Modules.list` 登记为准，文件名只用于保留与识别。引导闭包与运行期模块的主版本都跟随 `.os` 发布线（`.os` 镜像数据里的 `ModuleMajor`），跨主版本一律拒绝；同一发布线内模块按修订更新、重启生效、整修订回退，不热替换、不卸载（[模块修订与更新](模块修订与更新.md)）。

## 一、内核本体，`ring 0`

| 模块 | 输出名称 | 被谁载入 | 用途 | 手册 |
| --- | --- | --- | --- | --- |
| LikesProgram.os | `LikesProgram.os` | 自家 Baleen 引导器（第三方需自写中间层） | 标准入口、内核核心：平台初始化、内存、Objects、Sched、Irq、输出与诊断、容器与模块装载、配置与清单、启动状态与契约层；不含设备与文件系统实现 |  |

内核核心模块保持独立源码和接口，链接到同一个 `.os`，不再分别产出这些基础模块的 `.osm`：

| 模块 | 交付形态 | 用途 | 手册 |
| --- | --- | --- | --- |
| 平台初始化 | 内核核心 `.os` | 入口、GDT/TSS/IDT、页表与 physmap、CPU 特性与拓扑探测、异常处理与早期计时 |  |
| 物理内存与虚拟内存 | 内核核心 `.os` | 页帧分配、地址空间、映射、内核堆与 DMA 缓冲区管理 |  |
| Objects | 内核核心 `.os` | 统一对象、用户句柄、代际、命名空间和归属管理；从早期设备登记延续到运行期 |  |
| Sched | 内核核心 `.os` | 调度、线程、等待、同步与工作队列；按阶段启用 |  |
| Irq | 内核核心 `.os` | IRQ 登记、分发、屏蔽和同步排空，支撑驱动中断与停用 |  |
| 输出与诊断 | 内核核心 `.os` | 内存日志 ring、串口、BootInfo 帧缓冲绘字、栈回溯与失败报告；屏幕事实与等待配置已定稿，屏幕目标、等待与复位已在 M3 落地 |  |
| 容器与模块装载 | 内核核心 `.os` | `.osm` 有界解析、段映射、重定位、接口版本选择、依赖校验与初始化编排 |  |
| 配置与清单 | 内核核心 `.os` | 解析配置与引导器交来的已验证清单副本，选择能力与发行策略 |  |
| 启动状态、信任锚与契约层 | 内核核心 `.os` | 所选内核集与试启动身份、失败报告和重启请求、信任与撤销规则、公共基础库与接口声明 |  |

内核核心各机制的内容与边界见[内核架构与自举闭包](内核架构与自举闭包.md) 2.1；内核核心不含设备与文件系统实现，后者全部在引导闭包中。

## 二、引导闭包，`ring 0`，预装 `.osm`

引导闭包是退出固件启动服务后、挂载系统卷之前必需的模块。它们由 Baleen 在交权前按 `Modules.list` 预装，内核入口校验交接后按依赖序初始化；装载流程见[模块与驱动装载](模块与驱动装载.md)。**成员固定，发行配置不能裁剪**，引导器也不解析容器内部、不执行模块：

| 模块 | 输出名称 | 用途 | 手册 |
| --- | --- | --- | --- |
| DevModel | `DevModel.osm` | 完整设备模型、身份、拓扑、资源与绑定；同一设备树分阶段枚举 |  |
| DriverLoader | `DriverLoader.osm` | 统一管理驱动描述与外部 `.drv`，负责匹配、校验、初始化、绑定、停用与热替换 |  |
| VFS 与块设备层 | `Vfs.osm` | 统一挂载、路径解析、文件引用、块大小和偏移视图；早期与运行期同一卷和设备实例 |  |
| 启动设备驱动 | `AtaPio.osm`、`Ahci.osm`、`Nvme.osm`、`UsbCore.osm`、`Xhci.osm`、`UsbHub.osm`、`UsbStorage.osm` | 启动介质访问链的完整实现；逐个名称与职责见第六节 |  |
| Ext4 | `Ext4.osm` | 默认系统卷读写与一致性处理，早期只读 |  |
| ISO9660 | `ISO9660.osm` | 光盘主目录与 Rock Ridge 读取 |  |
| FAT32File | `FAT32File.osm` | FAT32 读写，提供引导文件、安装恢复介质与交换卷访问 |  |

缺引导闭包或其中任何一条校验不通过，按所选集失败处理，走屏幕可见的 `[ FATAL ] E-KRN-5x` 报错、等待与重启，不做降级启动，见[模块与驱动装载](模块与驱动装载.md) 2.1。引导闭包预装（M2）、`Modules.list` 读取（M3/M4 交接包校验）与内核侧装载（M4；运行期 `.osm` 在 M6）均已落地；内核当前停在调度与进程模型之前的阶段边界。

**M6 实现状态**：上表 13 个闭包模块均已落地为真实实现（USB 链为 xHCI 根端口 + BOT/SCSI，hub 下游枚举与 UAS 属阶段 3 以后；ISO9660 与 FAT32File 只读）；DevModel 的 USB 设备经 UsbCore `Register` 接入。平台设备与热插拔、外部 `.drv` 装载、Ext4 写与日志回放、FAT32 / ISO9660 的内核挂载消费者属后续阶段，见[启动介质与文件系统](Common/启动介质与文件系统.md)与[文件系统抽象与 VFS](Common/文件系统抽象与VFS.md)。

## 三、SDK 与契约层

内核内部契约随整集构建；面向外部作者发布的 SDK 遵守独立的兼容规则，见 [ABI 兼容与外部契约](Common/ABI兼容与外部契约.md)。

| 名称 | 交付形态 | 给谁用 | 内容 | 手册 |
| --- | --- | --- | --- | --- |
| 契约层 | 源码树内 | 内核模块作者 | 生成的结构体、操作号、错误码、基础公共库、接口 ID、导入导出声明、初始化与归属契约 |  |
| DriveSDK | 独立发布 | 驱动作者 | 驱动契约表、稳定内核调用面、设备类请求、MMIO/DMA、IRQ、设备事实、停用与热替换接口；不得包含内核私有头 |  |
| AppSDK | 独立发布 | 应用和服务作者 | syscall 包装、文件、事件、终端、CRT 与启动；服务状态、控制和退出语义；需要能力授权的系统接口 |  |
| HostSDK | 独立发布 | 构建工具与安装器 | 容器、契约表、服务声明、构建清单、布局、签名和引导选择记录的格式定义及共用生成工具 |  |

## 四、运行期内核基础模块，`LINK_MODE=module`，`ring 0`

这些模块提供常规用户态系统所需能力，在内核挂载系统卷后按本次所选模块修订的清单条目从系统卷装载；发行通常将其列为必需。它们依赖内核核心与引导闭包已发布的接口，不能成为内核核心的直接符号依赖；缺必需模块按所选集失败处理，走 `[ FATAL ] E-KRN-5x` 屏幕报错、等待与重启，见[模块与驱动装载](模块与驱动装载.md)。以下表格不规定装载顺序。

| 模块 | 输出名称 | 用途 | 手册 |
| --- | --- | --- | --- |
| Process | `Process.osm` | 进程对象、用户地址空间、线程账和退出回收，使用内核核心的 Objects、Sched 和内存机制 |  |
| Ipc | `Ipc.osm` | 端点、请求应答、事件和管道；不作为启动设备访问的前提 |  |
| Fault | `Fault.osm` | 运行期故障分类、恢复范围判定与维护策略；内核核心保留独立的早期报错和停止路径 |  |

## 五、内核可选模块，`LINK_MODE=module`

按发行需要选择；任何选中模块的硬依赖仍必须满足。Ext4、ISO9660 与 FAT32File 是引导闭包成员，不在本表，也不能作为可选文件系统删去。exFAT 是独立扩展，不与 FAT32 的必备地位混淆；可选模块缺失或失败按发行策略降级并 `WARN`，不重启。

| 模块 | 输出名称 | 用途 | 手册 |
| --- | --- | --- | --- |
| ExFAT32File | `ExFAT32File.osm` | exFAT 文件系统探测、挂载和访问，使用统一 VFS 契约 |  |
| 网络协议栈 | 后续版本 | 网络核心与协议 |  |
| 审计 | 后续版本 | 安全审计与事件订阅 |  |

## 六、系统驱动，当前运行于 `ring 0`

启动驱动属于引导闭包，其余驱动以外部 `.drv` 分发；两者使用同一驱动契约，由引导闭包中的 DriverLoader 按统一设备事实匹配。交付形态沿用[后缀设计](后缀设计.md)的驱动约定；是否支持热替换由设备、驱动能力和系统策略共同决定。

| 模块 | 输出名称 | 交付形态 | 用途 | 手册 |
| --- | --- | --- | --- | --- |
| AtaPio | `AtaPio.osm` | 引导闭包 | ATA 与 ATAPI 实现，包含读写和缓存刷新，同一实例按阶段启用 |  |
| Ahci | `Ahci.osm` | 引导闭包 | AHCI/SATA 端口、ATAPI、DMA、中断、热插拔和恢复，早期可轮询 |  |
| Nvme | `Nvme.osm` | 引导闭包 | NVMe 队列、DMA、中断与完成处理，同一队列和实例管理机制 |  |
| UsbCore / Xhci / UsbHub | `UsbCore.osm` / `Xhci.osm` / `UsbHub.osm` | 引导闭包 | xHCI、USB 2.0/3.x 设备与 hub 枚举、链路能力识别、传输和完成处理，纳入统一设备树 |  |
| UsbStorage | `UsbStorage.osm` | 引导闭包 | BOT/UAS 与 SCSI 存储，支持 U 盘、移动硬盘、USB-SATA/USB-NVMe 外置 SSD 和 USB 光驱；同一实例提供早期访问、运行期读写、多设备与热插拔 |  |
| Ps2Kbd | `Ps2Kbd.drv` | 外部 `.drv` | i8042 键盘探测、中断处理和键码上报 |  |
| Ps2Mouse | `Ps2Mouse.drv` | 外部 `.drv` | i8042 鼠标探测、位移与按键事件 |  |
| DispiFb / VbeFb | `DispiFb.drv` / `VbeFb.drv` | 外部 `.drv` | 显示模式与线性帧缓冲上报 |  |
| Acpi | `Acpi.drv` | 外部 `.drv` | ACPI 运行期服务和电源策略扩展；使用内核核心平台层发布的表信息，自举必需逻辑不得依赖它 |  |
| UsbHid / 网络类 | 后续版本 | 后续版本 | 通过同一设备框架接入 USB 输入与网络设备 |  |

驱动执行上下文、装载流程与热替换协议见[模块与驱动装载](模块与驱动装载.md)。
