# 模块与驱动装载

本文定义内核模块与驱动的装载流程、执行上下文、归属登记与热替换边界。模块与驱动共用容器解析、映射、重定位和验签原语，但装载流程分开。

模块与驱动的交付形态见[后缀设计](后缀设计.md)，具体模块与输出名称见[内核模块与驱动清单](内核模块与驱动清单.md)；这些机制打包成哪个产物由 [`LINK_MODE`](内核架构与自举闭包.md) 决定。

## 一、驱动执行上下文

**代码的交付位置、功能启用时机和执行特权级分别定义。** `.os` 中的驱动可以在工作线程中处理请求；外部 `.drv` 也可以运行在内核态，后缀和线程名称都不提供隔离。

| 阶段或方式 | 执行方式 | 边界 |
| --- | --- | --- |
| 早期启动 | 当前启动上下文中同步执行，必要时轮询 DMA 完成 | 不依赖尚未启用的工作线程；保留超时、资源归属和错误处理 |
| 运行期异步驱动 | 在内核工作队列或专用内核线程处理适合延后的任务 | 仍在内核地址空间；不要求每个驱动独占线程，中断入口只做所属上下文允许的工作 |
| 用户态设备策略 | EquipmentManager 等 `.exe` 通过受控接口请求设备管理操作 | 策略在用户态，设备框架和启动必需驱动继续在内核态 |
| 后续用户态驱动 | 独立进程与地址空间，通过驱动宿主协议访问设备 | 必须另行定义 IPC、资源授权、MMIO/DMA、IRQ 转发、故障回收与设备复位；不能仅迁移线程或复用普通内核指针 |

当前内置启动驱动和 `.drv` 使用内核态契约；用户态驱动是后续扩展边界，不自动适用于现有驱动。涉及 DMA 时还要考虑 IOMMU 等访问约束。启动关键链路不在运行期自动迁往用户进程，避免让读取驱动进程本身又依赖尚未运行的驱动。

## 二、依赖、初始化与归属

构建清单记录由导入表和显式接口需求生成的硬依赖，装载时交叉校验；发行配置只决定选择哪些能力、哪些必需、阶段与失败策略，不能隐藏实际依赖。构建检查 `builtin` 闭包，装载检查完整选中集合、环和阶段约束。提供者被标为“可选”，也不会使消费者的硬依赖自动变成可选。

装载流程如下，每一步都返回明确失败码：

1. 验证构建清单及 `.os` 身份；对候选容器做有界解析，核对签名、摘要、`BuildId`、接口和显式硬依赖。
2. 求出选中能力的硬依赖闭包，交叉校验导入表；拒绝环和“前阶段依赖后阶段”等矛盾。拓扑同层按显式顺序及稳定的模块标识排序。
3. 映射段、完成重定位与导入解析，**在执行任何模块入口前建立归属上下文**。
4. 同步调用 `Init` 进行可撤销准备。资源、内存、注册和对共享状态的修改必须可追踪；回调在所属阶段允许前保持未激活。
5. `Init` 成功后提交准备结果，发布供后续初始化使用的接口；只有前置条件全部满足的模块才能进入 `Activate`，再启用线程、IRQ 等运行期行为。
6. 准备失败时执行 `Abort`，撤销已登记资源和修改，并验证没有残留引用；传播硬依赖失败，再按发行策略决定降级或回滚。
7. `Abort` 不完整、发生不可逆副作用或激活后状态损坏时，不在当前内存状态下改装旧模块；报告并重启，由选择器回退整个内核集。

内置模块遵守同一初始化契约，自举所需的激活在读取 `.osm` 之前完成。已经激活的内置模块失败同样不能假定可以原地撤销。模块装载默认同步执行；驱动加载器的运行期停用和排空可以使用已启用的内置调度与 IRQ 机制。内置框架若需要进程、IPC 或故障策略扩展，通过明确可缺失的注册面接入，在提供者就绪前禁用相应功能，不直接绑定外置模块符号。

用户句柄命名空间的创建、设备策略订阅等晚期功能延后启用，不另建早期对象表或设备资源表。需要在晚期新增的硬依赖也必须满足 `builtin` 闭包检查。

**归属登记覆盖所有可回调和可访问实例的资源。** 包括接口表、事件订阅、定时器、IRQ、DMA 缓冲区和设备绑定；引用计数不能代替这些记录。

- 模块或驱动执行入口前先取得所有者身份，注册时立即登记。初始化失败可撤销准备记录；正常运行期也允许注销已经排空的注册，不能规定登记表只增不减。
- 撤销先禁止新调用，再排空执行中的回调和 I/O，停止设备访问，最后注销和释放。不能仅凭“登记已删除”就释放仍被 CPU 或设备引用的内存。
- 内核模块成功激活后不卸载；归属用于回收可撤销资源、故障定位和恢复判断。驱动只有满足停用协议才允许卸载。
- 归属记录提供管理边界，不构成内存保护边界；它不能保证损坏的 `ring 0` 代码只影响自身。

## 三、驱动装载与热替换

| | 内核模块装载器 | 驱动加载器 |
| --- | --- | --- |
| 实现位置 | `.os` 的模块装载器 | `.os` 内置 DriverLoader |
| 输入 | 所选构建清单与 `.osm`；内置模块信息由 `.os` 提供 | 内置驱动描述，或外部 `.drv` 与驱动声明 |
| 触发 | 启动配置与模块硬依赖图 | 同一 DevModel 提供的设备事实与绑定需求 |
| 接口 | 内核模块契约与导入、导出表 | 内外驱动共用的 DriveSDK 驱动契约表 |
| 依赖 | 构建集内的模块依赖 | 稳定内核调用面及设备拓扑，不直接导入其他驱动或具体 `.osm` 的符号 |
| 生命周期 | 激活后与内核同寿命 | 内置代码随内核集更新，实例遵守设备生命周期；外部驱动满足停用契约时可以卸载或替换 |
| 失败 | 依赖传播、受控降级或整集重启回滚 | 按设备重要性和可恢复程度降级、恢复、维护或停机 |

内核驱动调用表由稳定契约定义，内置机制和可选模块通过注册提供实现；可选接口未就绪时，依赖它的设备功能不得激活。驱动不互相导入符号，并不消除控制器、总线、存储层和子设备之间的运行期依赖；替换时必须按设备拓扑协调受影响对象。

**内置驱动随 `.os` 重启升级，不参与运行期代码热替换。** 正常的轮询到异步转换、设备停用和重新绑定只改变实例状态，不替换内置代码。以下热替换协议适用于外部 `.drv`，与内置驱动后期启用功能是两回事。

**热替换是有前置条件的能力。** 设备与驱动必须支持停止请求、排空、状态交接或可恢复重置，以及失败恢复。不满足时通过重启升级。协议由内置 DriverLoader 执行，Updater 决定何时发起：

1. 在旧实例正常服务时完整读入候选及恢复所需资料，验签并检查 ABI、设备匹配和热替换能力；校验通过前不执行候选入口。
2. 建立候选归属并映射，执行不接管硬件、不发布设备绑定的准备；旧实例代码、状态和恢复资源仍保留。
3. 在统一请求入口暂停新的上层请求，协调受影响设备和消费者，通过旧实例完成必要的文件系统屏障、写入和缓存刷新，再排空在途操作。
4. 使旧实例静默，停止 DMA，屏蔽并同步 IRQ，排空回调和执行引用。未能证明设备与 CPU 已停止引用时，不释放资源，也不强行进入下一步。
5. 在设备绑定尚未对外切换时，交接或重建硬件状态、IRQ 和注册归属，激活候选并检查就绪。此时不允许新旧实例同时驱动设备。
6. 原子发布新绑定并增加代际，恢复请求。这是**提交点**；提交前失败且硬件状态可恢复时，可以撤销候选、恢复旧实例并重新开放请求。
7. 提交后确认旧实例无执行、回调和 DMA 引用，再撤销剩余归属并释放。提交后的故障按当前实例故障处理，不承诺直接跳回已释放的旧实例；需要时执行新的受控替换或重启恢复。

**默认系统卷链路使用内置驱动，随内核集重启升级。** 若后续允许外部驱动参与关键存储链路，它也默认重启升级；例外热替换必须证明所需代码和资料已驻留、在途写入及文件系统状态可收敛、设备可恢复，并通过专门故障演练。仅预读候选包不足以满足这些条件。停流期间可能暂停设备服务，“内核不重启”不等于“设备没有停顿”。

当前内置驱动与 `.drv` 都在 `ring 0`，接口契约本身不能隔离错误指针或失控 DMA。设备局部降级只适用于状态受控的故障；系统卷、关键控制器或内核状态损坏时，可以进入维护模式或停止运行。同一设备必须保持唯一有效控制者，不能在失败时唤起另一个早期驱动实例抢占设备。
