# 用户空间与常驻服务

本文列出用户态程序的职责、常驻服务的编排方式、安装包与安装事务的边界，以及构建期配套工具。内核侧模块见[内核模块与驱动清单](内核模块与驱动清单.md)。

## 一、常驻服务与 Init

服务的交付形态沿用[后缀设计](后缀设计.md)中的用户程序与服务声明约定：**服务本身是 `.exe`，声明是 `.svc`**。这里说明运行职责：服务生命周期 API 放在 AppSDK，声明格式由 HostSDK 提供，Init 负责读取声明和编排进程。应用与服务共用进程、文件、事件、日志和能力机制。

服务可以提供前台调试入口，但需要明确实现该运行模式和生命周期处理，不能把它说成所有操作系统对服务的统一要求。独立服务开发库也是可能的组织方式；本项目选择并入 AppSDK，以减少重复接口和分发依赖。

| 服务声明字段 | 说明 |
| --- | --- |
| 程序 | `.exe` 路径及所选版本 |
| 运行身份 | 系统服务或用户会话服务 |
| 启动时机 | 用户态引导阶段、登录前、登录后或按需唤醒 |
| 依赖与顺序 | 所需服务、设备事实和就绪条件 |
| 失败策略 | 重启次数、退避、连续失败后的动作 |
| 能力 | 设备访问、端口、文件系统范围等授权需求 |
| 日志目标 | 日志导出去向 |
| 控制接口 | 启动、停止、重载、状态查询 |
| 健康确认 | 是否属于发行必需服务、就绪探针及超时条件 |

内核只负责启动第一个用户态进程 `Init.exe`。Init 按依赖启动服务，再启动会话与登录，并在满足发行健康条件后提交本次试启动确认。能力需求由声明提出，运行期根据授予的能力检查，不能只因文件被声明为服务就自动放行特权接口。试启动确认的提交条件见[内核集更新与回滚](内核集更新与回滚.md)。

## 二、用户程序，`ring 3`

用户程序在独立进程和地址空间中运行；交付形态与兼容性边界遵循[后缀设计](后缀设计.md)。本节列出由 Init 或 Session 启动的程序及其职责。

| 程序 | 输出名称 | 谁拉起 | 用途 | 手册 |
| --- | --- | --- | --- | --- |
| Init | `Init.exe` | 内核 exec | 首个用户态进程，启动服务和会话，执行健康确认 |  |
| Session | `Session.exe` | Init | 会话、登录、环境、应用启动和前台进程组 |  |
| Desktop | `Desktop.exe` | Session | 桌面外壳：背景、图标、任务栏和窗口管理策略 |  |
| Shell | `Shell.exe` | Session | 命令行、程序启动、管道与重定向 |  |
| Terminal | `Terminal.exe` | Session | 终端模拟器，渲染 tty 字符流 |  |
| FileManager / Settings | 后续版本 | Session | 文件浏览与系统设置 |  |
| Installer | `Installer.exe` | Session | 解包、校验、暂存和发布安装事务；内核集重启生效 |  |
| SelfTest | `SelfTest.exe` | Init | 用户态自检、组件和 ABI 基线验证 |  |

由 Init 按服务声明编排：

| 服务 | 输出名称 | 启动时机 | 用途 | 手册 |

## 四、安装包与安装事务

安装包及包内载荷类别遵循[后缀设计](后缀设计.md)。Installer 负责解包、校验、暂存和发布；本节说明它与内核集及组件更新的关系。

- 修改 `.os` 或 `.osm` 的包必须提供可验证的完整目标内核集；可以复用已存在且摘要一致的文件，不能让不完整集合进入试启动。
- 驱动、程序和服务声明按版本并存发布，当前正在使用或回滚所需的版本不原地覆盖。启动必需组件遵守内核集的启动配置保留规则；已发布的清单及其绑定配置不可原地改写，改变启动必需组件时须发布绑定新配置的新签名清单，保留旧版，并重新执行试启动确认。
- 暂存文件不等于生效。发布选择记录前完成完整性与依赖检查；是否重启、重启进程或热替换由载荷和运行状态决定。

## 五、配套工具，构建期

构建期工具跑在宿主上、用宿主的格式，不是本系统的容器，见[后缀设计](后缀设计.md) 5.11。

| 工具 | 用途 |
| --- | --- |
| 契约定义与生成器 | 从唯一定义生成契约头、Python 与汇编常量、布局和 ABI 断言 |
| 构建系统 | 求解 `LINK_MODE` 与硬依赖闭包，检查内置必备基线、驱动来源和阶段约束，生成同一 `BuildId` 的产物与构建清单；报告镜像和内存尺寸，不以约 100MB 目标设硬门禁 |
| 容器打包器 | 按[后缀设计](后缀设计.md)的类别与命名约定生成产物，按对应格式规格校验内部信息、摘要及 `.os` 的标准引导入口 |
| 签名与信任工具 | 密钥、信任锚、签名和撤销规则 |
| 内核集与启动状态工具 | 清单校验、镜像槽位、选择记录、尝试身份和良好集管理 |
| 布局计算与镜像组装 | 引导区、元数据区、内核槽位、Ext4 系统卷、ISO9660 光盘布局及连续镜像约束；同时产出可写入 U 盘的混合镜像，见 [Baleen 引导器](Baleen引导器.md) |
| 验证脚本 | 依赖和 ABI 检查、USB/Ext4/ISO9660/FAT32 必备能力检查、介质与入口启动矩阵（含 xHCI 下 USB 2.0/3.x、BOT/UAS、U 盘、移动硬盘、外置 SSD 与 USB 光驱）、驱动单实例及轮询/异步阶段切换验证、掉电回滚与外部驱动热替换演练 |
