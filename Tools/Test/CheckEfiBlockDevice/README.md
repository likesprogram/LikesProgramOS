# CheckEfiBlockDevice

宿主侧 C++20 检查工具：核对 Baleen UEFI 的块设备适配——把 `EFI_BLOCK_IO_PROTOCOL` 包成 `Storage::BlockDevice` 的那一层（`Packages/Baleen/Uefi/Src/EfiBlockDevice.cpp`）。编译后输出 `Tools/Bin/CheckEfiBlockDevice`。**手工执行，不构成默认构建依赖**；用例、模拟介质与假协议都内嵌在源码里。

```sh
make -C Tools/Test/CheckEfiBlockDevice
Tools/Bin/CheckEfiBlockDevice
```

工具按宿主选项编译**目标侧的同一份源码**（不做第二份参考解析），底层是就地构造的假块设备协议：三个动作由本工具的静态函数实现，按与固件同一套调用约定（`BALEEN_EFIAPI`，即 ms_abi）声明，背后是一块 64 KiB 的内存介质。协议替身按固件语义核对介质标识、介质在位、块数整倍数、缓冲对齐与范围——**这样「未对齐缓冲经内部对齐缓冲中转」那条路径才真的被走到**，而不是只看返回值。

## 检查内容（20 项用例）

**Bind（6 项）**：

- 空协议、协议没有介质：`InvalidArgument`，且失败绑定不留下任何事实（含把上一次成功的绑定清掉）
- 介质不在位（`mediaPresent = 0`）：`NotFound`；插回后可绑定
- 块大小为 0、3、500、768、1000：`NotSupported`；1、512、4096 这类 2 的幂接受
- 对齐要求（`ioAlign`）4097、8192、65536 超过实现上限 4096：`NotSupported`；0、1、512、4096 接受
- 成功绑定的事实：块大小、容量 `(lastBlock + 1) × 块大小`、可写性、介质在位、对齐要求、介质标识、可移动性；重新绑定后事实全部随新介质更新
- `lastBlock` 取最大时容量按 64 位回绕为零，随后的读与写按越界拒绝，且不下发

**Read（4 项）**：

- 未绑定：读、写、刷新一律 `NotSupported`，参数校验不参与
- 参数与容量边界：空缓冲、零长度、偏移未按块对齐、长度不是块的整数倍、起点等于容量、区间越过容量、整段加一块、近顶偏移都不回绕地报 `InvalidArgument`，全部拒绝都不触及协议；首块与最后一块可读
- 内容与块号换算：读到的字节与介质模式一致，偏移除以块大小得到下发的块号，下发长度与介质标识符合预期
- 介质标识被换掉（固件换了介质）：读、写、刷新都报 `NotFound` 且不再下发；`MediaId()` 报告的是绑定时的标识

**Write（2 项）**：

- 只读介质报 `ReadOnly` 且不触及协议（只读判定在参数校验之后：空缓冲仍先报 `InvalidArgument`）；可写介质上各类非法参数报 `InvalidArgument` 且不下发
- 写落到模拟介质的对应偏移、不碰相邻字节、能原样读回，最后一块可写

**Flush（1 项）**：

- 状态映射：成功 → `Ok`、`EFI_UNSUPPORTED` → `NotSupported`、`EFI_DEVICE_ERROR` → `Io`、`EFI_NO_MEDIA` → `NotFound`、`EFI_WRITE_PROTECTED` → `ReadOnly`、`EFI_NOT_READY` → `Io`；每次刷新都下发一次，介质指针消失时报 `NotFound` 且不下发

**对齐中转（3 项）**：

- 对齐要求 4096 时，未对齐调用方缓冲的读经内部中转缓冲下发（替身核对下发缓冲确实按 4096 对齐），内容与对齐读逐字节一致
- 一次 10240 字节的未对齐读按 4096 上限切成三次下发，块号随偏移推进、最后一次长度是余下的 2048 字节，整段内容一致
- 未对齐缓冲的写经中转落到介质，区间之外不被改动，写后读回一致

**介质与实现边界（2 项）**：

- 介质在两次调用之间被拔掉：读、写与刷新都报 `NotFound` 且不下发，插回后不必重新绑定即可恢复
- 块大小 8192（超过中转上限 4096）且要求对齐时：绑定直接拒绝（`NotSupported`），未绑定时的读写报 `NotSupported` 且不触及协议

## 曾经的偏差点与现在的取值

这五处是工具建起来时如实钉住的实现行为，**都已按 `Storage::BlockDevice` 的契约修正**，用例随之改成钉住现在的取值：

- `Bind` 的注释与实现不一致：现在注释写明了四种失败各自的返回（协议为空或没有介质事实 `InvalidArgument`、介质不在位 `NotFound`、块大小或容量无法表示或超中转上限 `NotSupported`）
- 块大小大于中转上限 4096：现在 `Bind` 直接拒绝（`NotSupported`），不留到某次未对齐调用才失败
- 只读介质的 `Write` 先判只读再判参数：现在先校验参数（`InvalidArgument`），参数合法才报 `ReadOnly`
- `Flush` 不核对介质在位：现在与 `Read` / `Write` 同一条核对，介质拔出后报 `NotFound` 且不下发
- 容量按 `(lastBlock + 1) × 块大小` 回绕：现在绑定时就检测并表示不了的容量，拒绝而不是回绕成零容量

## 不覆盖的路径

- 真实 OVMF 固件的协议实现与 `Baleen` 引导链的接线：由实机启动路径覆盖，本工具只检查这一层怎么调用协议、怎么解释返回值
- `BALEEN_EFIAPI` 在真机上的参数传递：本工具用同一属性声明替身，宿主上验证的是参数与返回值的语义，不是寄存器约定本身
- 并发与中断上下文：这一层没有同步设施，也没有可重入要求
