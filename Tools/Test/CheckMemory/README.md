# CheckMemory

宿主侧 C++20 检查工具：核对引导期的内存图可用性判定与低地址弹跳窗口搜索（`Packages/Baleen/Common/Src/BootMemory.cpp`）。编译后输出 `Tools/Bin/CheckMemory`。**手工执行，不构成默认构建依赖**。

```sh
make -C Tools/Test/CheckMemory
Tools/Bin/CheckMemory
```

## 为什么单独立一份

判定只有一份实现：Stub 用它挑装载 BaleenCore 的低地址弹跳窗口，BaleenCore 用它核对装载区与内核镜像跨度。两阶段曾各写一份，语义分歧会让同一台机器上一个阶段找得到窗口、另一个阶段找不到——这份检查把这套判定的边界与合并规则在宿主侧钉死，不需要启动虚拟机。

内存图条目的属性位过滤不在这里重复：Stub 的 INT 15h E820 例程已经丢弃属性位 bit0 为 0 的条目、给旧式条目补上「应保留」，本工具按判定实际拿到的形态构造条目，只判 `type`。

## 检查内容（14 项用例）

**区间可用性判定（`SpanUsable`）**：

- 单条可用条目整段覆盖；起点或末端差一个字节即不可用
- 相邻的可用条目合并覆盖同一区间；中间差一个字节的空洞、夹一条保留条目都不得被跳过
- 条目顺序不作假定：倒序排列必须给出同一结论
- 只有 `type` 为 1 的条目算可用，其余类型不参与合并
- 退化输入：空图、空指针、零长度区间一律不可用
- 回绕：区间末端溢出、条目长度溢出都不得被当成覆盖

**弹跳窗口搜索（`FindBounceWindow`）**：

- 实机形态的内存图（低 64KiB 可用、0x9FC00 起保留、1MiB 起可用）取到搜索起点那一段
- 整段可用的窗口按 64KiB 步进取第一段，部分覆盖的窗口被跳过；一个窗口可以跨两条相邻可用条目
- 搜索范围内整段保留时返回 `0`（Stub 的 `E-STUB-36` 就是这条路径）
- 搜索上端不含：只从 `kBounceEnd` 起可用的窗口不得被选中
- 参数退化：范围倒置、范围容不下一个窗口、窗口大小为零都不搜索
- 结果不变量：非零结果必须按步进对齐、落在搜索范围内、整段可用，且与逐段判定同源

固件里"找不到窗口"的真实失败路径由 [CheckStub](../CheckStub/README.md) 的 `--window-probe` 模式覆盖（注入一张没有可用窗口的内存图，核对 `E-STUB-36` 与停机）。
