# CheckMemory

宿主侧 C++20 检查工具：核对引导期的内存图可用性判定、低地址弹跳窗口搜索与内核页帧分配器的交接区间预留（`Packages/Baleen/Common/Src/BootMemory.cpp`、`Packages/LikesProgramOS/Core/Src/Memory.cpp`）。编译后输出 `Tools/Bin/CheckMemory`。**手工执行，不构成默认构建依赖**。

```sh
make -C Tools/Test/CheckMemory
Tools/Bin/CheckMemory
```

## 为什么单独立一份

判定只有一份实现：Stub 用它挑装载 BaleenCore 的低地址弹跳窗口，BaleenCore 用它核对装载区与内核镜像跨度。两阶段曾各写一份，语义分歧会让同一台机器上一个阶段找得到窗口、另一个阶段找不到——这份检查把这套判定的边界与合并规则在宿主侧钉死，不需要启动虚拟机。

页帧预留同理：装载器要在首次 `Allocate` 之前把预装模块字节、清单副本、列表副本与预装记录数组保留住，`Reserve` 的边角（对齐、64 位溢出、与内核/引导器跨度重叠、重复释放）在引导期没有第二次机会，只能在宿主侧先钉死。本工具**直接编译内核交付的 `Memory.cpp`**，不复制实现。

内存图条目的属性位过滤不在这里重复：Stub 的 INT 15h E820 例程已经丢弃属性位 bit0 为 0 的条目、给旧式条目补上「应保留」，本工具按判定实际拿到的形态构造条目，只判 `type`。

## 宿主侧编译的内核源码

| 文件 | 处理 |
| --- | --- |
| `Core/Src/Memory.cpp` | 直接编译交付实现；`Core/Src/Libc.cpp` 一并编入提供 `memset` |
| `Core/Include/Memory.hpp`、`Libc.hpp` | 直接包含交付头 |
| `Include/Paging.hpp` | **宿主替身头**：内核的 `PhysToVirt` 加直映射窗口基址 `0xFFFF800000000000`，宿主没有页表，替身按恒等换算，夹具把「物理地址」当宿主指针传内存图 |
| 编译选项 | 目标对象额外加 `-ffreestanding`，与交付构建一致；宿主模式下 `-ftree-loop-distribute-patterns` 会把 `Libc` 的循环变成对同名函数的调用（自递归的 `memset`），`-ffreestanding` 下不会 |

取整方向是这里钉的第一条规则：`MarkRange` 标占用时把区间碰到的每一页都标占（起址下取整、终址上取整），放行时只放整页（起址上取整、终址下取整）。引导期内核 `.bss` 尾、内存图数组尾与引导器跨度尾都可能不按 4 KiB 对齐，used 方向用下取整会把尾页漏成空闲页——M3 实机启动就踩到这一次（`0x103C000` 被 `Allocate` 交出去，清单副本 `memcpy` 覆盖内核 `.bss` 尾）。

夹具的内存图是 `0..32MiB` 一条可用条目；`Initialize` 另外标占内核起点以下全部地址（`0..16MiB`）、内核跨度（`16MiB..17MiB`）与引导器跨度（`18MiB..19MiB`），因此空闲页固定为 3584 页。内核与 `BootInfo` 结构自身地址在宿主上高于低 4GiB 管理范围，那两处 `MarkUsed` 是空操作，不影响断言。

## 检查内容（27 项用例）

**区间可用性判定（`SpanUsable`，6 项）**：

- 单条可用条目整段覆盖；起点或末端差一个字节即不可用
- 相邻的可用条目合并覆盖同一区间；中间差一个字节的空洞、夹一条保留条目都不得被跳过
- 条目顺序不作假定：倒序排列必须给出同一结论
- 只有 `type` 为 1 的条目算可用，其余类型不参与合并
- 退化输入：空图、空指针、零长度区间一律不可用
- 回绕：区间末端溢出、条目长度溢出都不得被当成覆盖

**弹跳窗口搜索（`FindBounceWindow`，8 项）**：

- 实机形态的内存图（低 64KiB 可用、0x9FC00 起保留、1MiB 起可用）取到搜索起点那一段
- 整段可用的窗口按 64KiB 步进取第一段，部分覆盖的窗口被跳过；一个窗口可以跨两条相邻可用条目
- 搜索范围内整段保留时返回 `0`（Stub 的 `E-STUB-36` 就是这条路径）
- 搜索上端不含：只从 `kBounceEnd` 起可用的窗口不得被选中
- 参数退化：范围倒置、范围容不下一个窗口、窗口大小为零都不搜索
- 结果不变量：非零结果必须按步进对齐、落在搜索范围内、整段可用，且与逐段判定同源

固件里"找不到窗口"的真实失败路径由 [CheckStub](../CheckStub/README.md) 的 `--window-probe` 模式覆盖（注入一张没有可用窗口的内存图，核对 `E-STUB-36` 与停机）。

**页帧分配与交接区间预留（`PageAllocator`，13 项）**：

- 初始化按内存图放行可用页，扣掉内核起点以下、内核跨度与引导器跨度；首次分配落在自由区起点，`Free` 后复原
- 首次 `Allocate` 之前 `Reserve` 生效：分配跳过保留页、空闲页数同步扣减，同一区间重复预留被拒绝
- `ReleaseReserved` 后页面重新可分配、空闲页数复原，重复释放返回 `NotFound`
- 退化参数：零长度 `ZeroLength`、起址或长度未按 4 KiB 对齐 `Unaligned`，且不改变状态
- 管理范围与 64 位加法：越出低 4GiB `OutOfRange`、跨上限 `OutOfRange`、`起址 + 长度`溢出 `Overflow`；上限内但不可用的页按 `Occupied` 拒绝
- 重叠拒绝：内核跨度、内核以下保留区、引导器跨度、内存图外、已分配页，以及整段/部分/跨起终点落在已有预留内都是 `Occupied`
- 释放只认完全相同的登记项：长度不符、起址不符、从未预留、内核与引导器跨度都返回 `NotFound`（后两者不是预留项，不会被释放）
- 预留表容量：`kMaxReservations` 项都成功，下一项 `NoRoom`；释放一项后可以再预留
- 重新 `Initialize` 清空预留表：旧预留失效，空闲页数按新的交接事实复位
- **MarkRange 取整方向（标占用必须盖住区间碰到的每一页）**：内核 BSS 终址未对齐（`0x103C018`）时所在页 `0x103C000` 不得被 `Allocate` 返回；引导器跨度首尾都未对齐（跨页）时两页都标占、中间页不被误标；内存图数组自身地址未对齐且跨页时同样两页都标占（宿主夹具用 `g_hostPhysBias` 把数组摆到低物理地址）
- 放行方向不受影响：未对齐的可用条目只放整页（`0x100100..0x102100` 只放 `0x101000` 一页），首尾半页留在占用侧
