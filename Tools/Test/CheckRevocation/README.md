# CheckRevocation

宿主侧 C++20 检查工具：签名吊销记录与引导状态区单调纪元。编译后输出 `Tools/Bin/CheckRevocation`。手工执行，不进入默认构建。

```sh
make -C Tools/Test/CheckRevocation
Tools/Bin/CheckRevocation
```

## 覆盖内容

检查的是将要交付的那些实现：`Revocation.cpp` 与 `BootState.cpp` 取自 `Packages/Common`，`ManifestVerify.cpp`、`TrustAnchor.cpp` 与 `LoadKernel.cpp` 取自 BaleenCore，`BootMemory.cpp` 取自 Baleen 共用实现；锚表、内存介质与内存文件系统由本工具自带（两条锚的公钥由固定种子派生，用例里核对派生结果与内嵌表逐字节一致）。规格依据：[内核集清单与签名](../../../Docs/Specs/内核集清单与签名.md) 5.1、5.2 与[引导状态记录](../../../Docs/Specs/Baleen/引导状态记录.md)第二、六节。

- **记录结构**：正例通过；长度多一字节/少一字节、格式标记、版本、头部长度、长度字段、标志字段、纪元为零、签名算法、签名密钥编号、签名区保留字节十类破坏一律拒绝
- **签名与自吊销**：正例验签通过并解出纪元、下限与位图；换另一把受信公钥、改动一个字节都失败；签名者出现在本记录吊销位图里时记录不成立
- **位图与并集**：`KeyId 0` 不构成吊销；`KeyId` 1、8、9、32、64、255 各标一位且恰好一位；并集的纪元与下限取较大者、位图按位或，并入更小的事实不改变结果
- **系统卷读取（`Missing` / `Unusable` / `Applied`）**：缺文件返回 `Missing` 且不改动事实；长度不符、篡改，以及 `Open` 返回的不是 `NotFound`（存储层读不了，如 `Io`）都返回 `Unusable` 并给出原因——打不开不能当成“文件不存在”；合法记录返回 `Applied`
- **真实清单验证**（走 `ManifestVerify.cpp`）：被吊销的签名密钥按 `E-CORE-74` 拒绝；吊销别的密钥不影响本清单；记录抬高的下限高于清单安全版本时按 `E-CORE-66` 拒绝，等于时不拒绝
- **清单验签编号与顺序**：签名区结构错（算法不是 Ed25519、密钥编号为 0、保留字节非零）返回 `E-CORE-62`，只有签名值验证失败才返回 `E-CORE-64`；`.os` 的内核镜像数据头检查失败返回 `E-CORE-54` 并带出内核数据检查的原因；签名错且 `BuildId` 也不符时报 `64`（验签先于 `BuildId` 比较）；被吊销且不在锚表里的签名密钥报 `74`（吊销判定先于信任锚查表）
- **单调性**：记录文件缺失时持久事实仍生效；记录被回滚成旧纪元、且不吊销任何密钥时，并集后仍不解除吊销、下限不被拉低；写回再读出的撤销事实一致
- **记录版本**：格式尚未发布，只有一个版本 `1`、长度 `0xF0`；往返一致（含已试次数），版本不是 `1` 的记录按损坏处理（不猜字段表）
- **内核装载重叠**：镜像数据声明装载地址 `0x200000`、跨度 `0x200` 时，引导器区间覆盖装载地址（`E-CORE-91`）必须在装载前拒绝；区间紧邻其后不重叠、或调用方没有引导器区间事实（`loaderBytes=0`）时正常通过

## 退出码与结论

退出码：`0` 全部通过、`1` 有断言失败。结论行只有“全部通过”与“N 项断言失败”两种，不写“基本通过”。

## 不做的事

- 不启动 QEMU、不碰真实镜像：介质与文件系统都是内存替身；真实引导链上的读取由[CheckSelect](../CheckSelect/README.md) 与实机路径覆盖
- 不覆盖 `MakeRevocation` 的命令行解析：生成侧的确定性与自检由该工具自己的结论行覆盖
