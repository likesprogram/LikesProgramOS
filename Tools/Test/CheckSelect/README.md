# CheckSelect

宿主侧 C++20 检查工具：核对 BaleenCore 的选版（`Packages/Baleen/Core/Src/SelectSet.cpp`）与引导状态记录（`Packages/Common/Src/BootState.cpp`，引导期与运行期共用）。编译后输出 `Tools/Bin/CheckSelect`。**手工执行，不构成默认构建依赖**；用例内嵌在源码里，介质是内存块设备（默认 512 字节逻辑块，块大小相关用例按 4096 / 2048 构造，并强制与真实适配器相同的块对齐契约）。

```sh
make -C Tools/Test/CheckSelect
Tools/Bin/CheckSelect
```

工具按宿主选项编译**目标侧的同一份源码**（不做第二份参考解析），把它接到内存介质与两个替身上运行：

- **清单验证替身**（`VerifyKernelSet`）：按集目录返回夹具登记的结果（含清单登记的 `.os` 相对路径），并核对选版传进来的期望集标识与**设备已见最高安全版本**（低于已见最高按 `E-CORE-66` 拒绝，规格第三节第 6 条）。清单结构、签名、`BuildId` 一致、防回滚与逐产物摘要的真实验证不在本工具里重复，由 [CheckCrypto](../CheckCrypto/README.md) 与实机启动路径覆盖——本工具只核对“选版怎么调用它、结果怎么影响状态转换”
- **诊断输出替身**（`WriteDiagnostic`）：不装控制台，把诊断行收进夹具，按编号断言

**记录字节表是两侧互验的**：夹具自带一份独立的 CRC-32 与按规格第二节字节表拼副本的构造器，用来造出“校验和正确但字段违规”的副本，并反向确认生产读取方接受合法副本。生产代码不会产生这类副本，只有夹具能造。

## 检查内容（60 项用例）

**引导状态记录**：

- 空区域、没有状态区域（`StateOffset` 为 0）：按“无记录”处理，按缺省集启动；`StateOffset` 为 0 时不做任何写入
- 读状态区域失败与区域参数非法（长度不足、起点未按块对齐）不按“无记录”处理：分别以 `E-CORE-89` / `E-CORE-90` 致命停机——不定下目标集、不写盘、不进入清单验证
- 缺省集事实写回：没有记录时（空区域或记录损坏的降级策略路径），若缺省集清单的安全版本或有效吊销事实非零，用一条 `Confirmed` 记录（代次从 1 起）把验证过的缺省集、`SeenSecurityVersion` 与吊销并集持久化；没有事实、只读介质或 `StateOffset` 为 0 时不写
- 回退缺省集写回事实：回退前有有效记录时保持原记录状态，只抬升 `SeenSecurityVersion`、并入吊销并集，有变化才写新代次；写失败只报 `E-CORE-70`（`E-CORE-59` 表示没有已知良好集、本次启动的是布局描述的缺省集）
- 槽位环形与代次：未写过的槽位按 A..H 顺序填（代次 1..8），填满之后第九次写覆盖代次最低的槽位 A；**写入永不覆盖当前最新的有效槽位**
- 读取：八个槽位取**校验通过且代次最高**的那个；一个写坏回落到其它完好的；只剩一个完好仍可读；全部坏 → 损坏；最高代次出现两次 → 损坏
- 字段校验：逐项拒绝校验和不符、状态越界、`Flags` 非零、两处保留字段非零、代次为零、尝试次数超上限、`Confirmed` 带候选字段、`Confirmed` 缺集标识、`Pending` 带尝试身份的副本；合法副本必须被接受
- **掉电演练（逐字节截断）**：把一次写入按字节逐个截断（511 个截断点），读取方在任一截断点上都必须拿到一份完整有效记录、不得判损坏；截断到记录有效长度 `0xF0`（含校验和）时新槽位自身已完整，读取取它
- **写中途断电（撕裂现场）**：撕裂槽位在 11 个边界上穷举（`0/1/2/4/8/16/32/64/128/192/235` 字节），每一档都不得被选中、不得报有效——**哪怕它声称的代次最高**；反面边界 `0xF0` 必须按完整记录接受；八个槽位里七个只落了头 32 字节时仍要读出唯一完好那一份
- **维护动作**：槽位级检查逐个报告结论与代次；受控清零把区域还原成出厂形态（只读介质上拒绝）；按有效记录修复每一个坏槽位、记录内容不变、修完代次互不相同，没有可用记录时拒绝；人工接受只允许下调已见最高安全版本，抬高、相等或没有记录都拒绝
- 写入顺序与门槛：写 → 刷介质缓存 → 读回（规格第四节第 3..5 步，按介质操作序列断言）；**提交按设备逻辑块落盘**——512 字节块上一次提交是单槽位写，4Kn（4096 字节块）与 2048 字节块上读—改—写包含目标槽位的整块、其余槽位字节不变；代次全 FF 拒绝写入且不落盘；只读介质不发起写调用；写失败不改动当前有效的槽位；写“成功”但读回不符、以及刷盘失败，都按写失败处理
- 确认提交：只有记录仍是 `Trying` 且 `AttemptId` 相符才写 `Confirmed`；转正保留已试次数（只增的审计账），尝试身份与剩余次数清零；发布新候选才把已试次数从零重记
- **块大小与对齐边界**：4Kn 与 2048 字节块介质上的提交长度分别是 4096 / 2048 且按块对齐，八槽环形推进后逐个槽位仍有效；状态区域起点未按块对齐、或长度不足一个区域时，在读写介质之前即拒绝（选版以 `E-CORE-90` 停机；4Kn 上旧实现的 512 字节写会被真实适配器以 `InvalidArgument` 拒绝）
- 版本口径：只有版本 1，往返一致（含已试次数）；版本不是 1 的记录按损坏处理
- 介质策略位：记录全部不可用时默认停机不猜目标集（`E-CORE-69`）；介质置了降级位时退到缺省集并报 `E-CORE-56`

**选版**：

- `Confirmed`：选已知良好集、不写记录；清单安全版本更高时同状态抬升 `SeenSecurityVersion`（代次加一、保留良好集指针）
- `Pending` / `Trying` 的候选路径：`Pending` 由本工具按同一记录格式构造（见下），校验通过后写 `Trying`、次数递减、尝试身份取写入代次、已见版本在同一份记录里抬升；`Trying` 未确认按剩余次数重试；次数用尽写 `Failed` 并回退良好集
- 候选失败：清单验证失败写 `Failed` 并回退，原因随 `E-CORE-72` 带出；没有已知良好集时写 `Failed` 后启动缺省集
- 写入门槛：写不成立（含刷盘失败）就不进入候选（`E-CORE-70`），按降级路径选已知良好集；只读介质同样如此
- 代次耗尽停机：有效记录到代次上限（`kGenerationMax`）后，任何需要提交的选版路径（`Confirmed` 抬升、候选写 `Trying`、回退写 `Failed`、缺省集写回）都以 `E-CORE-92` 致命停机，不按普通写失败报 `E-CORE-70` 继续；只读介质上的全一代记录同样停机（耗尽判定先于写能力）
- 损坏记录不猜测目标集（`E-CORE-69`，不定下目标集、不写盘）
- 吊销记录打不开（`Open` 返回的不是 `NotFound`）不按“没有记录”处理：报 `E-CORE-75` WARN 后继续，选版仍按记录与缺省集决策
- 缺省集与防回滚：`Failed` 记录直接选良好集；回退到缺省集时带设备已见最高版本做比较（低于已见最高以 `E-CORE-66` 拒绝）；没有记录时按 `0` 比较、只做内嵌下限检查；缺省集同样先验证清单与防回滚，没有已验证的直启路径
- 扁平落点被拒绝（`E-CORE-84`）：布局路径不是 `KernelSets/<BuildId>/<相对产物路径>` 形态（含旧扁平落点与过长的缺省路径）时拒绝，不碰状态区域、不进入清单验证
- 子目录 `.os` 按清单路径装载：装载路径由集目录与验签通过的清单 `.os` 条目拼成，不固定拼 `LikesProgram.os`——缺省集、已知良好集与候选集都按同一规则
- 布局路径与清单产物不符拒绝（`E-CORE-85`）：布局路径里的相对产物路径不等于清单登记的 `.os` 条目时拒绝；判定发生在清单验证之后（不是验签失败），装载路径只取验签清单

## Pending 的可复现入口

`Pending` 的发布方是运行期的 Updater，`Confirmed` 的提交方是 Init，两者都未实现（[引导状态记录](../../../Docs/Specs/Baleen/引导状态记录.md)第四节、[BaleenCore 说明](../../../Packages/Baleen/Core/README.md)第三节）。本工具用**同一份记录格式与同一个写入函数**在内存介质上构造 `Pending` 记录，因此“候选路径”在开发期有可复现入口：`Pending` → 校验候选 → 写 `Trying` → 试启动身份 → 回退或重试。真实产品里的候选路径仍等待 Updater 落地。

## 未由夹具覆盖

- 清单验签与逐产物摘要的真实实现（`ManifestVerify.cpp`）：由 CheckCrypto 与实机启动路径覆盖
- 介质上的真实写盘、只读介质失败与刷盘原语：由 [CheckStub](../CheckStub/README.md) 的 `writeSectors` 探针在 QEMU 里覆盖（内存介质只核对写入顺序与返回值；BIOS 路径没有刷新原语，边界见[引导状态记录](../../../Docs/Specs/Baleen/引导状态记录.md)第五节）
- 维护动作的命令形态与审计行：由 [FixBootState](../../Maintain/FixBootState/README.md) 承担，本工具只覆盖它调用的那几个操作
- 加载候选后进入内核、Init 到达确认点提交 `Confirmed` 的运行期路径：内核与用户空间尚未实现
