# CheckStorage

宿主侧 C++20 检查工具：核对 S1 存储抽象的接口与共用实现——统一路径、共用名字比较、偏移视图与错误文本，并验证同一份源码在 32 位与 64 位下的编译、链接与运行。编译后输出 `Tools/Bin/CheckStorage`。**手工执行，不构成默认构建依赖**，用例与检查逻辑内嵌在源码里。

```sh
make -C Tools/Test/CheckStorage
Tools/Bin/CheckStorage                 # 全部检查
Tools/Bin/CheckStorage --cases-only    # 只跑用例，跳过双编译检查
```

## 检查内容

**用例检查（24 项）** 用编译进来的 `Packages/Common/Src/Storage/` 实现运行：

- 路径语法与切分：根路径、多层合法路径、空指针与非绝对路径、空分量与结尾分隔符、`.` 与 `..`、整条路径与单分量的长度上限、非 ASCII 与空格按原字节使用
- 共用名字比较：逐字节比较、ASCII 折叠比较、非 ASCII 字节按原值、单字节折叠
- 偏移视图：未绑定行为；绑定时对起点未对齐、零长度、越界与 64 位回绕的拒绝，且拒绝后不留下绑定；绑定成功的事实与读写转发；区间读的非法参数与边界；只读底层的写拒绝
- 错误码诊断文本：已定义取值的文本非空、互异、稳定，未知取值给兜底文本
- 文件系统基类接线：默认实现与能力位、`ResolvePath` 的逐段解析与错误码映射、按路径查询事实

**双编译检查** 用 `CXX`（默认 `g++`）完成，输入是本工具的源码与 `Packages/Common/` 下的 Storage 源码：

1. **32 位编译、链接与运行**：把 Storage 的四个源与同一份用例源码用 `-m32` 重新编译、链接并运行，核对 24 项用例在 32 位下的结果
2. **目标侧链接**：按 Baleen 各阶段的选项（`-m32 -ffreestanding -fno-exceptions -fno-rtti -fno-pic -fno-pie -fno-stack-protector`）编译并做 `-nostdlib` 静态链接，核对无未定义符号；产物符号表里不牵入 `__udivdi3` / `__umoddi3` / `__divdi3` / `__moddi3` 这类 64 位除法辅助函数

## 选项

| 选项 | 说明 |
| --- | --- |
| `--root <目录>` | 项目根，输入路径都从这里展开；默认从可执行文件位置推断（`Tools/Bin/CheckStorage` 向上三级） |
| `--work <目录>` | 工作目录，32 位与目标侧编译的中间产物与日志写在这里；默认建在系统临时目录下（`checkstorage.<pid>`） |
| `--keep` | 无论成败都保留工作目录 |
| `--strict` | 缺少 32 位工具链时返回失败（默认返回 2） |
| `--cases-only` | 只跑用例，跳过 32 位双编译检查 |
| `-h`, `--help` | 显示用法 |

环境变量 `CXX` 指定 C++ 编译器（默认 `g++`），`NM` 指定符号查看器（默认 `nm`）。

## 退出码

| 码 | 含义 |
| --- | --- |
| 0 | 全部检查通过 |
| 1 | 有用例或检查失败；工作目录保留，便于查错 |
| 2 | 缺少 32 位工具链（`-m32`），32 位检查未执行；加 `--strict` 时按失败处理 |

失败时工具打印相关日志的末尾若干行，完整日志留在工作目录里。
